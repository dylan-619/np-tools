# KZ3 板载点位经典 PLC 仿真案例：两设备顺序启停

设计日期：2026-10-19  
案例 ID：`two-device-output-sequence`，拟定版本 `1.0.0`  
用途：会展固定模板，在 NP-Tools 内贯通点表、对话、代码、本地仿真部署和 HMI  
状态：案例设计已确定；模板源码、实例化程序和交互主机运行器待实施。本文不是已通过验证的案例包。本次无实板烧录，所有操作在 NP-Tools 内完成，只有 OpenCode 通过地址连接。

## 1. 案例就做这一个

采用经典的两台输送设备顺序控制：**启动时先后级、再前级；停止时先前级、再后级。** 采用 KZ3 板载逻辑地址：两路 DO 表示两个设备的控制输出，三路 DI 用于启动、正常停止和运行许可。DI 由工具内虚拟控件注入，DO 来自实际执行的主机版 C 逻辑。

只演示启停顺序、延时、自保持、停止优先和许可撤销，不需要电机、变频器、模拟量传感器或扩展模块。无需实体工装，页面展示运行器输出的 DO 指示；HMI 使用“输出接通/输出断开”，不声称检测到电机运行。

不增加独立手自动模式、故障复位、轮换、运行计时或反馈超时。HMI 和虚拟 DI 按钮都是同一顺序控制的操作入口，没有两套控制模式。

用户输入示例：

> 两台输送设备，先启动后级，隔 2 秒启动前级；停止时先停前级，后级延时 5 秒再停。许可撤销时两台立即停止。

AI 可以补充说明“启动按钮松开后保持输出”“停止优先于启动”“恢复许可后需重新启动”。这些已在模板中实现，现场只需理解、解释和配置。

## 2. 固定板载点位

依据 [KZ3 标准板型](../../../KZ3_F427_SLE_V1/application/io_definitions/board_kz3_f427_standard.yaml)：板型声明 12 DI、8 DO；本例仅使用以下 5 点，其余不使用。

| source | 模板逻辑名 | 作用 | 逻辑 true 的含义 |
|---|---|---|---|
| `board.di01` | `start_button` | 虚拟启动按钮 | 按下；仅采上升沿 |
| `board.di02` | `stop_button` | 虚拟正常停止按钮 | 停止请求有效；按电平处理 |
| `board.di03` | `run_permit` | 运行许可开关 | 允许启动和保持输出 |
| `board.do01` | `downstream_output` | 后级设备输出 | 接通后级控制输出 |
| `board.do02` | `upstream_output` | 前级设备输出 | 接通前级控制输出 |

标准板型声明 DI `active: low`、DO `active: high`、DO `safe_value: false`。业务逻辑读取驱动转换后的布尔值，不在控制代码再次取反。这些是源码定义，本次虚拟采样直接产生逻辑布尔值，无需实物接线确认，也不验证端子电气能力。

NP-Tools 提供 DI1“按下启动”、DI2“按下停止”、DI3“运行许可”三个虚拟控件。DI1/DI2 由内部运行 actor 产生约100ms脉冲，保证至少一个已完成扫描读取到 true，自动释放；DI3 保持直到用户改变。新运行全部为 false，用户先开启许可。

虚拟采样器通过真实 DataManager 输入发布接口注入，只允许这三个 DI。每次扫描重新采样当前虚拟值及质量，不通过 HMI 普通北向接口写物理点。脉冲与许可由工具后端管理，不依赖浏览器按钮松开事件，不直接执行 DO 动画。

运行器、10ms扫描目标、100ms显示快照、超时与进程退出行为按 [总设计第8节](设计文档.md#8-真实-c-逻辑的交互运行器) 实施；运行器是工具管理的私有子进程，无地址和端口供用户配置。

## 3. 固定控制行为

### 3.1 启动与正常停止

- 许可有效、三个 DI 质量有效、停止输入未按下且处于待命时，接受 DI1 的新上升沿或 HMI 的单次启动命令。
- 接受启动后 DO1 接通，进入启动等待；按钮松开不停止。
- 等待 `startDelayMs` 后 DO2 接通，DO1 保持。
- 联动输出时收到正常停止，DO2 立即断开，DO1 保持 `clearDelayMs`，到时断开并回到待命。
- 启动等待期间收到正常停止，两路立即断开，不再启动 DO2，不执行清料延时。
- 清料期间新的启动无效、不排队；重复正常停止不重新计时。
- 待命时停止不改变输出；停止输入保持有效期间不能启动。

### 3.2 立即停止及恢复

- DI3 许可撤销、三个 DI 任意一个质量无效：同一控制扫描撤销两路输出、清除顺序计时、丢弃在途启动，进入“禁止启动”。质量状态的有效值以当前 KZ3 API 定义为准。
- HMI“立即停止”命令：同一扫描撤销两路输出并清除计时。条件允许则回待命，否则处于禁止启动；无需故障复位。
- 许可/质量恢复后回待命，必须收到之后的新启动事件才能启动；恢复同一扫描的启动也丢弃。
- 上电两路输出断开。启动按钮上电时已经按住，必须先释放再按下才能启动。
- 启动上升沿检测与命令消费在所有状态持续执行：等待、停止、禁止期间的命令当场消费，不存成之后自动执行的请求。
- 同一扫描优先级：输入无效/许可撤销 → 立即停止 → 正常停止 → 定时转换 → 新启动。发生停止或恢复回待命的本扫描不再处理启动。

“立即”指控制器扫描内的响应；HMI 采样刷新不会同步到毫秒。软件立即停止不等同于安全认证急停。

### 3.3 状态与输出表

| phase | 显示 | DO1 后级 | DO2 前级 | 转移条件 |
|---|---|---|---|---|
| 0 `READY` | 待命 | 0 | 0 | 新启动且条件满足 → 1 |
| 1 `START_DELAY` | 后级接通，等待前级 | 1 | 0 | 启动计时到 → 2；正常停止 → 0 |
| 2 `BOTH_ON` | 两路输出接通 | 1 | 1 | 正常停止 → 3 |
| 3 `CLEAR_DELAY` | 前级断开，后级延时停止 | 1 | 0 | 清料计时到 → 0 |
| 4 `BLOCKED` | 禁止启动 | 0 | 0 | 许可及输入质量恢复 → 0，本扫描不启动 |

所有状态均先处理高优先级条件。无效状态值撤销两路输出、回到待命或禁止启动，并记录诊断；不能沿用上次输出。最终输出由单一 owner 在扫描末统一写出。关键不变量：**DO2=true 时 DO1 必须=true。**

```text
启动命令       ↑                                  正常停止 ↑
DO1 后级       ┌─────────────────────────────────────────────┐
               │                                             │
DO2 前级       │     ┌──────────────────────────────────┐     │
               │ 2秒 │                                  │ 5秒 │
               └启动等待                                └清料等待
```

具体边沿以扫描时刻为准；断开后保持断开，直到下一次有效启动。

## 4. 现场只允许改两个控制参数

| 参数 | 默认 | 范围 | 生效规则 |
|---|---|---|---|
| `startDelayMs` / `START_DELAY_MS` | 2000ms | 1000–10000ms，整数 | 每次接受启动时锁定本轮值 |
| `clearDelayMs` / `CLEAR_DELAY_MS` | 5000ms | 1000–10000ms，整数 | 每次接受启动时锁定本轮值 |

参数使用 `u32`，非持久化；掉电回到本次固件生成的默认值。HMI 仅在待命时开放编辑，控制器仍须校验范围并在启动时复制两参数快照，活动周期不受后台写入干扰。没有快照或范围校验的模板不得标为已完成。

AI 允许更改项目显示名称和两个设备名称；物理 source 在本展台锁定为上表五点。用户导入不匹配点表时先解释差异，不自动换成不存在的模拟源。当前案例的工程配置和 HMI 均使用同一角色映射。

最适合现场展示的需求变化：**“把启动间隔改为 3 秒，停止延时改为 4 秒。”** AI 提取两个数值，经检查后程序从模板生成新工程默认值，在工具内实际编译并部署新的 host 运行器；无需重新编写状态机。

HMI 调试阶段也可通过真实参数 API/CAS 临时修改这两个参数并观察下一轮效果。这是运行参数调整，不能冒充新源码编译部署。

## 5. 北向字段：固定 13 个

正式 reference 由既有生成器检查和分配；下表规定字段语义，不手写未核验的寄存器地址。点位 bind 指向上述固定模板逻辑名；parameter/command/state 的具体定义同步写入正式 `project_io.yaml`。

| field.name | 类别 / 类型 | 权限 | 作用 |
|---|---|---|---|
| `START_BTN` | DI / bool | 只读 | 虚拟启动按钮状态 |
| `STOP_BTN` | DI / bool | 只读 | 虚拟停止按钮状态 |
| `RUN_PERMIT` | DI / bool | 只读 | 运行许可 |
| `DOWN_OUT` | DO 命令映像 / bool | 只读 | 后级输出目标；不代表实测电机反馈 |
| `UP_OUT` | DO 命令映像 / bool | 只读 | 前级输出目标 |
| `LINE_START` | command / bool | 单次写 true | 启动顺序 |
| `LINE_STOP` | command / bool | 单次写 true | 正常顺序停止 |
| `LINE_PROTECT_STOP` | command / bool | 单次写 true | 立即停止，按固件 protective 语义声明 |
| `START_DELAY_MS` | parameter / u32 | 读写 | 启动等待 |
| `CLEAR_DELAY_MS` | parameter / u32 | 读写 | 后级停止延时 |
| `LINE_PHASE` | state / u32 | 只读 | 0–4，按状态表显示 |
| `LINE_BLOCK_REASON` | state / u32 | 只读 | 0 无，1 许可未给出，2 DI 质量异常；质量异常优先 |
| `LINE_REMAIN_MS` | state / u32 | 只读 | 当前等待剩余毫秒，非等待状态为 0 |

界面从 `LINE_BLOCK_REASON != 0` 派生禁止提示，不新增虚构故障点；剩余时间由控制器输出，界面不据本地计时判定顺序已完成。不增加 `LINE_RESET/LINE_AUTO/LINE_FAULT/UP_RUN/DOWN_RUN`。

## 6. 固定 HMI

一个精修画面即可：左侧后级输送设备，右侧前级输送设备，连线表达先后关系。两设备显示输出指示；下方显示三个 DI 的已采样状态和当前顺序阶段、剩余时间；右侧固定显示虚拟 DI 控件。

操作只有三个：**启动、正常停止、立即停止**。侧栏只有两个时间参数。没有独立设备点动、手自动、故障复位按钮。停止输入保持有效时显示原因，许可未给出时禁用启动；主机版 PLC 逻辑仍承担最终判断。画面持续显示“本地仿真”，运行器失败后显示数据失效。

使用现有 `.scene.json` 外形，`commands.start/stop` 绑定对应北向字段；立即停止保留在既定 sidecar action 中；`phaseLabels` 用本文件的五态定义，`blockReasonPoint` 与 `remainingPoint` 为需要在 sidecar schema 中声明的只读绑定。没有实际 RUN 反馈，不将输出绑定到 `points.running`。

## 7. 固定案例生成和现场流程

展前实现并验证一份 `logic.c`、一份测试和配套点表/HMI 模板。程序只填入两个参数、名称及工程身份；本机五个物理 source 固定。核心逻辑和测试断言不交给模型重写。生成耗时按总设计第 6、8、13 节分段记录。

现场讲解顺序：

1. 在 NP-Tools 展示 KZ3 点位示意，导入5点表，不连接主板。
2. 输入两设备先后启停需求；AI解释固定案例并补全停止优先、许可恢复不自启等规则。
3. 确认2秒/5秒或选定参数，工具实例化模板，显示代码、13个北向字段及当前主机检查。
4. 点击“部署到本地仿真”，工具编译并启动本次 C 运行器，核对修订/run身份；两输出初始断开。
5. 在同一对话要求生成 HMI，工具填充固定 scene 并打开内部画面。
6. 开启虚拟 DI3，点虚拟 DI1：DO1先接通，2秒后DO2接通。
7. 点虚拟 DI2：DO2先断开，5秒后DO1断开。
8. 再次启动，关闭DI3：两输出断开；恢复DI3后保持断开，新启动才动作。
9. 用 HMI command 操作同一逻辑；调整参数检查下一轮变化。
10. 修改需求产生新版本并重新部署，或者点击“重置演示”清空虚拟输入/参数/计时进入新一轮。操作始终在 NP-Tools 中完成。

## 8. 模板验收

| 检查 | 预期 |
|---|---|
| 上电，启动按钮已按住 | 两输出断开；释放后新按下才启动 |
| 合法启动、启动按钮松开 | DO1 保持；计时到后 DO2 接通 |
| 启动/正常停止同时出现 | 停止优先，无意外启动 |
| 启动等待中停止 | 两输出断开，之后不延后接通 DO2 |
| 正常停止及重复停止 | DO2 先断开，DO1 延时断开；重复请求不延长计时 |
| 清料期间按启动 | 无效且丢弃，到待命后不自动启动 |
| 任意状态撤销许可/DI 坏质量 | 本扫描两输出断开，计时清除 |
| 恢复许可同时启动/此前一直按住启动 | 不启动，等待之后的新事件 |
| 立即停止与定时完成同一扫描 | 两输出断开，不被定时转移重新接通 |
| 运行中后台修改参数 | 本周期快照不变，下一次启动采用有效新值 |
| 参数越界、时间到边界、时基回绕 | 拒绝无效值；无提前动作；回绕算法按 KZ3 计时约定正确 |
| 任意正常扫描 | DO2=true 必须伴随 DO1=true |
| HMI 命令消费/重连 | 不因重连重复启动；命令读回 false 不误判设备已停止 |

OpenCode断开不影响当前仿真。前端页面暂时断开时，Rust可继续驱动当前运行器，恢复页面需拉最新完整快照；运行器退出、扫描严重延迟或无法响应时，当前会话失效，HMI不得继续更新假数据或自动重放启动。应用退出需结束进程，重启演示后DI全部false、两DO安全，许可由用户重新开启。

本次验证包括固定案例host测试、交互runner输入输出测试和NP-Tools端到端演示。无需硬件接线/烧录验收，也不声称证明了STM32调度、电压极性或继电器动作。完整案例源码及运行器尚待实现，不能把本设计当作执行结果。
