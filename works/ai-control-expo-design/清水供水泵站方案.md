# 清水箱补水与双泵供水

本次将主案例升级为完整泵站工艺，继续在NP-Tools内完成点表、需求、固定模板生成、部署和HMI联调。保留原顺序启停案例及历史工程。所有设备反馈由主机过程模型产生，不要求实板或模拟量仪表。

## 工艺与点位

水源 → 双向电动进水阀XV101 → 清水箱 → 并联供水泵P101/P102 → 用水端。

| 点位 | 工艺含义 |
|---|---|
| DI1/DI2 | 水箱低位以上/高位液位开关 |
| DI3/DI4 | 水源可用/供水需求 |
| DI5/DI6 | P101运行反馈/故障触点 |
| DI7/DI8 | P102运行反馈/故障触点 |
| DI9/DI10 | XV101开到位/关到位 |
| DI11 | 设备运行许可 |
| DO1/DO2 | P101/P102启停 |
| DO3/DO4 | XV101开阀/关阀 |

11DI/4DO来自KZ3标准板型定义（12DI/8DO），不新增模拟量、PID或扩展模块。水箱百分比由过程模型提供给工艺图，控制代码仅依赖离散液位开关。

## 控制方案

- 点击“投入自动运行”才建立自动请求；冷启动保持待命。软件工况预置水源、供水需求和许可有效，降低第一次操作门槛。
- 低位开关失去后建立补水请求，持续开阀至高位开关成立。水源无水时关闭进水阀；这属于工艺条件不足，不当成阀门故障。
- 有供水需求且低位开关成立时启动工作泵。低水位立即撤销供水输出，补水恢复到低位以上后，已投入的自动控制可重新供水。
- P101默认为工作泵。硬接故障、启动失败、运行反馈丢失会撤销该泵输出并保持本机故障。只有旧泵反馈已经停止、两路泵输出全断且切换间隔满足，才允许备用泵投入。
- 泵输出互斥。停机反馈未消失时不启动另一台，即使已超过切换间隔。停机超时为本泵报警，后续仍需反馈确认停止才能接替。
- XV101行程期间保持对应方向输出，到位撤销。开/关输出互斥；反向前从最终两路全断起满2秒，并重新核对自动目标。等待时间不算行程时间。两限位同时成立、开关行程超时形成阀门故障。
- 每台设备独立故障复位：根因仍存在、运行反馈未停止时不能解除；健康设备复位不产生启停，不影响另一台设备。
- 正常停机撤泵输出，并在许可和质量正常时受控关闭进水阀。立即停止/撤销许可/输入坏质量撤销全部DO，不声称失电阀门已经关到位。恢复许可或质量后须重新投入，不自动续跑。
- 停止优先于启动；停止或复位与启动同拍不投入。时间参数在投入时快照，仅退出自动且设备已停止后允许修改。
- 运行时间使用SDK声明式累计，绑定各泵独立反馈；主机EEPROM夹具只验证软件保存路径，重置进程不冒充现场持久工时。

## 时间与过程模型

建议初值：泵启动反馈5秒、停止反馈5秒、阀行程8秒、泵切换2秒（范围不得低于2秒）。这是为软件联调选定的工艺参数，后续实际设备应按行程和电气条件校核。

过程模型按真实C输出推进水箱液位、阀门行程与泵运行触点，再将触点发布给真实DataManager/LogicManager。前端不实现第二套控制算法。初始水位15%、阀关闭、泵停止；示意低/高位约20%/80%。工况调试允许改变液位、水源、用水需求及故障条件。
