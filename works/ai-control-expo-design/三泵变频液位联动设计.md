# 三泵集水井液位控制设计

版本：v0.1设计基线，2026-10-19。更新：2026-10-20已实现为独立LAB_ONLY案例并完成主机验证，见 [三泵案例实施说明](三泵案例实施说明.md)。下文保留原设计中的候选项；实际PI单位/整定、趋势窗口、初始模型与74字段契约以实施说明和当前源码为准，不再将“尚未实现”段落作为当前状态。

本文件响应新增的“一台变频泵、两台工频泵、一台工频备用、三个主要液位等级”要求，作为下一版固定案例的实施依据。此前“不使用模拟量与 PID”适用于旧供水案例；本案例明确增加软件连续液位、实际频率反馈与 PI 调节。展会基础仍为 NP-Tools 内的软件闭环，无需接实板。

## 1. 工艺选择与展示重点

采用集水井提升排水：上游来水进入集水井，经三条并联泵支路排往下游。每条支路画止回阀与手动隔离阀，不增加电动阀控制，不沿用旧案例的电动进水阀。静态阀门符号不显示虚构的到位反馈。

| 设备 | 能力 | 正常角色 |
|---|---|---|
| P101 | 固定连接一台变频器，连续调速 | 优先启动、液位主调 |
| P102 | 工频，仅启动/停止 | 大来水时增援 |
| P103 | 工频，仅启动/停止 | P102 故障或不可用时接替；正常备用 |

正常最多运行两台：P101 + P102，或 P101 + P103。P103 不因为“液位更高”就自动成为第三台运行泵。两台已满负荷而液位继续升高时，发出排水能力不足报警。若以后需要三台同时应急排水，应另改最大容量及备用策略，不在本版暗中加入。

推荐采用“变频主调 + 工频分级投切”。辅泵投入/退出时需要协调变频输出，这一控制原则可参考 [ABB ACQ580 固件手册的 PFC 章节，印刷页112](https://library.e.abb.com/public/3486b1d5620647d0b2a26ff7bbacc397/EN_ACQ580_pump_control_program_FW_E_A5.pdf?x-sign=LPN5ZpmbnaUrnlAStFOQyjpu4q%2Bdbqx7mX4sXiCRtFzaQ%2B1GGNzekQ87p7CYmrYe#page=112)。本设计由 KZ3 执行调度与 PI，不要求使用 ABB 变频器，不复制该手册的现场参数。

对观众展示四件事：来水变化时自动调速；单泵能力不足时有依据地加泵；恢复后有序减泵；故障时备用接替，并能解释为什么等待或拒绝动作。

## 2. 三个主要液位等级

三个等级由一个连续液位测量值比较得到，不需要各增加一路模拟量，也不等于必须装三只浮球。只有三个开关量可以做分级启停，但不足以连续跟踪目标液位。

以下数值是软件案例的建议值，尚未经过设备模型整定或现场确认。

| 参数 | 软件建议值 | 作用 |
|---|---:|---|
| 停泵液位 `L_STOP_M` | 0.40m | 达到或低于此值，撤销全部自动泵命令；不等待最小运行时间 |
| 启变频液位 `L_VFD_M` | 1.00m | 自动已投入时，达到或高于此值，开始 P101 启动确认 |
| 启工频液位 `L_AUX_M` | 1.80m | 达到或高于此值，允许进入工频加泵条件检查；不单凭液位立即加泵 |
| 调节目标 `L_SP_M` | 0.80m | P101 正常运行后跟踪的目标，不是第四个启泵等级 |

液位量程暂按 0–3.00m 的软件工况设置。整组必须满足：`0 < L_STOP_M < L_SP_M < L_VFD_M < L_AUX_M < 液位量程上限`。液位回落到启变频液位以下时，正在运行的 P101 继续调节；不能在 1.00m 上下反复启停。来水过小时，最低有效频率仍抽得过快，允许降到停泵液位后停泵，待升至启变频液位重新运行；不承诺任何来水量下都能恒液位。

可另保留一只独立高高位开关作为报警、以及一只低水位许可开关作防干转联锁。它们是独立保护，不增加常规调度等级。本版高高位只报警，不跳过加泵条件，也不启动第三台；液位测量失效后不能凭高高位猜测连续液位。

| DI2 | P1_FLT | P101 / 变频器故障接点 |
| DI3 | P1_AUTO | P101 控制权在远程自动 |
| DI4 | P2_RUN | P102 独立运行反馈 |
| DI5 | P2_FLT | P102 故障接点 |
| DI6 | P2_AUTO | P102 控制权在远程自动 |
| DI7 | P3_RUN | P103 独立运行反馈 |

| DI9 | P3_AUTO | P103 控制权在远程自动 |
| DI10 | WATER_OK | 独立低水位许可，true 为允许抽水 |
| DI11 | LEVEL_HH | 独立高高位报警，true 为报警成立 |

点表保留 `board.di01` 等实际 source、用户描述和原始文件散列。别名不决定物理接线，导入后逐个核对角色；同一 source 不重复绑定。DI 的 active-low 是板级驱动定义，接点常开/常闭及逻辑真值仍需接线核验。

**电气边界：**板型文件中模拟量均标注 `electrical_verified: false`，AI 软件范围0–20.32mA、AO范围0–20mA，AO既有安全值为0mA。数量可用不等于电气联调通过。软件停机时 DO1=false、AO1=0mA；真实变频器必须确认0mA/信号丢失的停机策略、4–20mA标定、最小有效频率与故障接点语义，不能擅自把板级安全值改成4mA。也不能将 VFD 电源输出接到 DO 端子；这里的 DO 是柜内控制信号设计。

若现场改用 RS485 获取频率/写给定，必须提供具体变频器寄存器、倍率、时效和写入规则后再做适配，本版不猜地址。软件展示统一由设备模型产生 AI/DI，不要求购买变送器、变频器或泵。

## 4. 控制归属与调节

唯一闭环控制者为 **KZ3**：`液位 AI1 → 工程单位与质量检查 → PI → AO1频率给定 → P101`。变频器内部过程 PID 关闭，配置为远程频率跟随模式。PID 的 D 项为0；P102/P103没有调速能力，不能被选作变频调节泵，也没有变频器跨泵切换接触器。

液位越高，排水频率越大；不能直接照搬补水回路方向。P101软件调试频率范围暂拟25–50Hz，50Hz来自本次要求，25Hz仅为模型待验证值，不作为真实泵最低频率。启动前检查配置合法、全部关键质量正常、运行许可和低水位许可有效、无设备故障、控制权可用、容量允许。

使用 SDK 实际支持的 `tracking_mode`、`tracking_output`、`use_runtime_gains`。开始启动到运行反馈成立前，跟踪允许的启动给定，避免积分预先饱和；运行后按固定100ms PI周期调节，10ms控制扫描负责联锁和调度。限制输出和变化率，启用抗积分饱和。停止、许可丢失、增益变化和退出闭环时按冻结规则复位积分。

辅泵投入时，以已确认的辅泵运行反馈作为能力改变依据，跟踪协调后的 P101 给定，再交回 PI；退出时以辅泵停止反馈确认后提高 P101 给定、再交回 PI。协调量需经模型曲线/试验确定，不能使用“开一台工频就减50Hz”的公式。未取得协调值前，采用输出限速与抗饱和的保守过渡，并实测液位曲线，不声称已经无扰。

`LV_KP`、`LV_KI` 必须为独立 float 参数，北向 `read_write`，运行时实际进入 PID 输入；单位分别为 Hz/m、Hz/(m·s)。没有整定证据时使用0占位、回路禁用，阻止正常自动投入。软件固定案例上线前需对其固定模型完成离线整定，将合格增益与模型/源码散列绑定；不能让展会现场每次等待 AI 整定。真实设备仍需重新整定，不沿用软件增益作为现场参数。

改任一增益应退出本回路自动、复位积分、进入停止并要求重新投入。两项先后写入期间不得使用中间组合自动运行；校验有限数、非负、范围及完整配对。参数持久化仅在实际变化时进行，主机 fake EEPROM 不构成板上保存证明。

## 5. 正常调度：上升、下降与边界

建议状态：`STOPPED / AUTO_IDLE / VFD_STARTING / VFD_CONTROL / ADD_CONFIRM / AUX_STARTING / TWO_PUMP_CONTROL / REMOVE_CONFIRM / AUX_STOPPING / TRANSFER_WAIT / DEGRADED / BLOCKED`。状态只由控制 C 发布，HMI 不再写一份调度算法。

| 当前状态/触发 | 条件与确认 | 执行动作/去向 |
|---|---|---|
| 冷启动、重新部署、停止后 | 未有本轮新投入请求 | 全部自动命令断开，不自启 |
| 投入自动 | 许可、配置、质量、设备与容量均合格 | 进入 AUTO_IDLE；低于启泵级就等待 |
| AUTO_IDLE → 起 P101 | `H >= L_VFD_M` 连续确认；P101可用且最小停机时间满足 | 仅发 P101 启动，等运行反馈；不能同拍连起工频 |
| P101运行 | 反馈确认、连续液位有效 | PI跟踪目标；低于 `L_VFD_M` 不撤销运行 |
| 单泵 → 工频加级确认 | `H >= L_AUX_M`，P101运行反馈有效，**实际频率**有效且>=49.5Hz，并满足下述未下降判据 | 连续确认后选择P102；不可用则选择P103；无可用设备则报警 |
| 工频启动待确认 | 前一设备启动间隔满足、容量允许 | 只起所选工频泵，等待它自己的运行反馈；失败锁存并进入接替判断 |
| 两泵运行 | 健康反馈、许可有效 | P101继续PI，工频持续运行；P103若未被选用则保持备用 |
| 两泵 → 减级确认 | `H <= L_VFD_M`、P101实际频率<=最低调试频率+1Hz，工频最小运行时间满足，连续确认 | 停止当前工频泵；确认停止后 P101 单独调节 |
| 任意自动运行 → 低位停泵 | `H <= L_STOP_M` 或 `WATER_OK=false` | 当拍撤销三泵自动命令与频率给定，优先于普通计时；完成停止监视 |
| 正常低位停止后再升高 | 普通液位循环、自动请求仍有效 | 必须重新升至 `L_VFD_M` 且重新确认，不能停泵液位刚恢复就起泵 |
| 人工停止、许可撤销、关键质量异常 | 不等最小运行/减级确认 | 撤销自动请求并停机，恢复条件后仍需新投入 |
| 高高位 | 报警输入有效 | 报警；不额外启动第三台，不伪称容量足够 |

加泵中的“无法降低液位”按原意定义，**不偷偷改为只是持续高液位**：使用连续有效的滤波液位，滚动观察窗口内 `H(当前)-H(窗口起点) >= -0.02m`，即没有至少下降2cm。还必须在整个确认段满足高位、满频与运行条件；窗口数据不足时不放行。滤波时间暂拟1秒，趋势窗口10秒；它们是软件待验证值。若质量中断、退出满频、低于工频级、参数变化或发生投切，清空旧确认和趋势窗口，不能沿用历史高位时间立即加泵。满频命令50Hz而实际仅40Hz不成立。

时间顺序采用“高位且实际满频连续10秒形成有效趋势窗口 → 未下降判据成立后再连续确认5秒 → 只发出一次工频启动请求”。因此软件案例最早在该段开始15秒后申请加泵，普通工程30秒确认的候选配置则最早40秒；设备可用性、最小停机、启动间隔和容量可能使实际等待更长。两段计时不能重复抵扣。减级不使用加级的趋势窗口，独立重新计时。

减泵是一次受监督的减级，不保证单凭低频即可证明单泵足够。减级后若来水仍过大，允许重新满足完整高位/满频/趋势确认后加泵；受最小停机时间限制，禁止立即反复投切。需要通过模型与实际泵曲线验证工频泵能力、最低变频频率和目标附近是否存在可调区间。低于两泵最小排量时允许减级或液位循环，不编造平滑恒液位曲线。

停止与复位、停止与投入同拍，停止优先；一次扫描只发出一次新的启泵动作。上升、下降均使用包含等号的阈值，确认条件任一不满足即清零。参数变更不继承旧计时。计时使用防回绕策略。

### 各类时间分别定义

| 项目 | 软件案例建议 | 非软件工程基线 | 说明 |
|---|---:|---:|---|
| 启变频液位连续确认 | 2s | 待现场确认 | 不包含启动反馈超时 |
| 普通加/减级确认 | 5s | 30s候选，需工艺确认 | 软件另有独立10s趋势窗口；两种profile不可混用 |
| 泵启动反馈超时 | 5s | 待设备确认 | 从发启动命令起算 |
| 泵停止反馈超时 | 5s | 待设备确认 | 从撤销命令起算 |
| 相邻启动间隔 | 3s | 待电气确认 | 从上一台启动动作起算，反馈和容量仍需另满足 |
| 故障接替停稳间隔 | 2s | 待电气确认 | 从被替代泵GOOD停止反馈起算 |
| 工频最小运行/停机 | 各15s | 待设备确认 | 低位、停止与联锁可越过最小运行；故障不绕过停稳确认 |

软件参数需经离线模型验证后冻结为独立版本。数值变短必须明示为软件联调配置，不能通过偷偷加速墙钟伪装现场动作速度，也不将“普通30秒”强套到安全停机、PI计算或反馈超时。

## 6. 备用、故障与控制权

### 工频泵故障接替

P102故障或启动失败：撤销P102请求并独立锁存；P101继续健康调节，不无故全组停机。只有 P102运行反馈为GOOD且false、停稳间隔满足、P103可用、启动间隔满足、总占用容量允许时，P103才接替本次工频角色。P102停止反馈粘连或质量未知时继续占容量，显示等待/故障，不能以DO2已断代替“泵已停”。若备用P103启动失败，不在两台故障泵间循环重试。

P102修复复位后，本次已运行的P103继续承担增援，直到正常减级/停止。下一个完整周期才恢复P102优先，避免修好即切换。首版采用固定工频主备，不添加运行中轮换；将来若加均衡，只允许在P102/P103同能力池且全停的周期边界选择，不能把P101轮作工频备用。

### 唯一变频泵故障

工频泵不能等价替代液位连续调节。默认退出正常自动并停机报警，画面明确“变频调节不可用”。本设计建议另提供由操作者明确投入的 **工频降级排水**：故障P101已确认停止，P103按 `L_VFD_M` 启/`L_STOP_M` 停，P102按 `L_AUX_M` 加入、回落至 `L_VFD_M` 后持续确认退出，仍最多两台。进入前必须确认这是分级排水，不能继续标“恒液位调节”。此模式不再要求P101满频，因为它已经失效。

“投入工频降级”是独立命令，不能由一般故障复位隐式触发。P101恢复后先停止降级、确认两台工频停稳，再重新投入正常自动；不带运行状态自动切回变频。物理工程是否允许降级、排水能力是否足够，仍需按现场工艺确认。

### 质量、容量与复位

- 每泵容量只计一次，但运行反馈成立、启动待确认、停止未确认、就地运行、关键反馈未知均占用容量。容量未知时不批准额外起泵；不接管就地泵。若实际三台已在就地运行，显示真实超容量报警，不能伪造“最多两台”。
- 液位坏质量、非有限数、越量程或断线：退出正常自动并停机，撤销旧趋势/积分。独立高高位仍可报警，但不自动构造备用连续测量。
- 实际频率无效/超时：禁止满频加级，按频率监督故障退出正常自动；若需要继续排水，由操作者按上述明确流程投入已批准的工频降级。不得拿给定或旧缓存补出实际频率。
- 泵运行反馈/故障/控制权质量分别影响该设备可用性；未停确认仍占容量。组许可/低水位许可质量异常按全组阻断处理。高高位质量异常单独报警，不当作正常无报警。
- P1/P2/P3独立复位。故障接点仍在、反馈未停、质量无效或控制权不允许时拒绝复位；复位不建立新自动请求，也不清其他泵故障、共享调度或PI状态。健康泵复位无启停副作用。
- 许可、测量和通信恢复后，不自动解除锁存或恢复人工停止前的自动。正常液位循环可在已投入自动中重新启动，与异常恢复路径分开。

## 7. HMI：真实泵站画面

主画面为集水井 + 三条并联泵支路 + 出水总管。中央液位柱显示实际液位及三个主要液位线；目标线使用不同样式并标“调节目标”，不混作第四级。P101标“变频主调”，P102标“工频增援”，P103标“备用/接替中”。工频泵显示运行/停止，不伪装为可调频率。

核心可见信息：当前控制模式、真实反馈运行台数/占用容量、可用备用数、当前液位/目标、P101给定与实际频率、趋势曲线、当前阶段、等待原因与剩余确认时间、独立报警。运行灯来自运行反馈；启动命令另显示“启动中”。质量失效显示不可用与时间，不保留绿色缓存运行态。

常用操作只保留：投入自动、正常停止、立即停止、独立设备复位。折叠区提供三个液位与目标、PI参数/状态、许可、传感器质量和故障注入；详细整定不能挤占停止按钮。默认1100×760仍需看见主要控制和三台设备状态，展台大屏另做排练。

工况入口采用过程语言：“日常来水、来水增加、来水恢复、工频泵故障、变频泵故障、液位信号异常、低水位保护”。来水改变推动模型水量平衡，不能直接把运行状态改成“两泵运行”。故障解除只是恢复模型条件，仍需控制程序独立复位。初始水位预置仅允许停机时设置；运行中拖动液位须明确记为测试注入，不冒充水量平衡。

不显示没有来源的压力、流量实测、能耗节省百分比、AI评分或泵健康预测。可显示软件模型来水量，但明确其来源，不能标为现场仪表反馈。全局保持一个“软件联调”标识即可，不在每台设备和每个按钮重复“演示”。

## 9. 软件模型与实施改动

设备模型与控制逻辑分开：模型按上拍 DO/AO 推进电机启停、变频器斜坡与水位，再发布AI/DI；真实DataManager/LogicManager扫描生成新命令。水量关系采用 `井截面积 × 液位变化率 = 来水量 - 各运行泵排水量`；频率-排量曲线、启停延迟、液位噪声/滤波与信号失效均为明确的模型参数。模型反馈不得直接复制同拍命令，启动失败与停机粘连必须可复现。

模型上线前应满足：小来水单泵在调速范围内可稳定跟踪目标；大来水超过单变频满频排量、但在一变频加一工频能力范围内；低来水允许减级/停泵；超大来水触发能力不足。泵曲线、井面积和时间常数未经验证前不承诺稳定曲线或现场容量。

当前应用使用离散点位的两个案例，不能只加第三个泵图标就宣称支持本方案。需要以下实现：

1. 新案例YAML/C/真实测试、scene、模型、整定profile、资源散列与catalog注册；既有工程不迁移。
2. 工程驱动/前后端契约增加新案例身份、模拟量角色、float参数、分组约束与能力范围。当前严格输入集合不能直接接受本点表，应显式适配而非放开任意功能。
3. 固定C接入SDK已有PID能力；实际使用runtime KP/KI；三泵独立状态/计时/运行累计、容量及降级owner均有实际扫描证据。
4. C私有协议、Rust参数/工况白名单、实时快照支持有界有限float与三泵模型数据；保留runId/workspaceId隔离、来源散列、超时/进程退出边界。
5. 工艺HMI增加三泵/液位级别/实际与给定频率/趋势/等待理由；阈值和状态从C回读，前端不拥有调度。
6. 固定配置对话模板与工程技能同步到本项目资源；AI只能选择模板合法变体，不将旧42字段scene绑定到新案例。

展会主流程仍在NP-Tools：点表→需求对话→固定模板生成→仿真运行→HMI工艺调试→烧录物理设备。只有OpenCode Server在外部通过连接访问。已启动的软件控制不因AI断开而消失。

建议展台脚本：

1. 载入三泵点表，用一句话提出“三级液位、一变频两工频、一台备用”。AI核对点位，补全目标值、满频判断、减泵和故障策略，形成可审阅方案卡。
2. 确认后实例化固定案例，展示控制代码、北向点表与实际检查结果，部署软件运行器，在同一对话生成泵站HMI。
3. 日常来水：升至启泵级，观察P101启动、频率随液位变化、接近目标后稳定。
4. 来水增加：P101升至实际满频、液位达到工频级、趋势/持续条件合格，显示加泵原因，P102加入，P101回落调节。
5. 来水恢复：观察低频/低位减泵确认，P102停止后回到单泵；继续减少可观察低位停泵与重新积水启动。
6. 在双泵阶段注入P102故障：P101继续，P102停稳后P103接替。恢复故障接点并独立复位，不立即抢回。
7. 按需展示P101故障，明确选择工频降级；或展示测量失效后停机、恢复不自启。不要在一次短演示中把全部故障连续叠加。
8. 进入烧录物理设备步骤，展示真实固件/连接准备状态；具备合格设备与固件时才执行真实写入。

在固定模板、固定模型和完整自动检查完成前，本方案只作设计，不将旧双泵运行截图或旧测试数量记为新案例通过。
