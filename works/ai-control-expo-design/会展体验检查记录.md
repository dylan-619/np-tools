# AI 辅助工作台会展体验检查

日期：2026-10-20。范围：np-tools 工作台六步流程、展示文案、工艺需求引导、操作衔接和录屏准备。本次未改变三个案例的 C 控制逻辑、SDK、设备模型或硬件能力。

## 产品表达

入口采用“工业控制工程 / 智能设计与联调”，副文说明平台适用对象和交付范围。三个能力名称统一为“工艺需求分析、控制工程生成、运行仿真验证”。删除口号式、随意的标题；工程生成、仿真部署、工艺画面生成、控制器部署准备使用明确的功能名称。

## 检查与处理

| 环节 | 发现 | 本次处理 |
| --- | --- | --- |
| 入口 | 标语随意，第一屏长点位列表掩盖了工艺场景 | 产品定位、能力说明和场景概览；点表折叠；案例启动作为主入口，自有点表导入保留 |
| 工程恢复 | 初始化期间可点击入口，恢复完成后可能覆盖操作意图 | 初始化期间隔离新操作，完成恢复后开放流程；新增回归用例 |
| 场景选择 | 局部样式把自定义下拉箭头挤到下一行 | 恢复选择器的横向弹性布局 |
| 点表 | “点位已核对”可能被误读为工艺角色已完整确认 | 明确“点表结构已核对”，继续结合需求确认设备角色与控制条件 |
| 需求 | 示例过短，缺少异常、恢复和交付要求 | 三类场景均提供六部分需求提纲；建议值取自同一参数目录；仅填入草稿，不自动发送或确认；已有输入追加保留 |
| AI 方案 | 需要完整、可核对的方案结构 | 要求按控制目标、设备点位、运行策略、保护、参数及联调要点回复；区分用户要求、固定规则、建议和缺口 |
| 确认表 | 参数表与控制边界容易分离 | 表内可展开启停、接替和保护规则，修改后仍需重新确认 |
| 流程栏 | 之前按当前页序号把前序步骤打勾 | 改按点表、产物、主机验证及当前仿真实例的真实状态显示；HMI 打开与烧录准备不自动算验收通过 |
| 工程产物 | 界面偏编译技术细节，缺少产物用途说明 | 明确代码、工程点表、北向点位及验证记录的用途；通过标识来自实际主机报告 |
| 部署 | 顺控、双泵、三泵使用了不一致的设备描述和旧 DI 初始化日志 | 按当前案例显示模型与初始化引导；版本标识折叠保留 |
| HMI 生成 | 点击生成后仍停在部署页，不易观察 AI 过程 | 返回同一对话显示实际请求，场景校验成功后进入 HMI |
| 联调 | 缺少操作顺序和观察点 | 可展开的“联调操作指引”，覆盖主调、增援、接替、停机；不自动操作或伪造验收勾选 |
| 实板 | 容易把进入烧录页理解为已部署 | 明确“准备阶段 · 尚未写入设备”，保留匹配 ARM 固件与现有 ST-Link 烧录路径 |
| 模型等待 | 实测出现服务连通但模型正文迟迟未返回 | 增加超过 30 秒的实际等待时间与停止重试提示；不伪造生成进度，停止后保留已发送需求 |
