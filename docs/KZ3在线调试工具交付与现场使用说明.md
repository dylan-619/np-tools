# KZ3 在线调试工具交付与现场使用说明

> 交付状态：在线诊断与受控北向写入测试可交付；HIL、端子电气和现场负载结论待工程师执行并记录。
>
> 软件版本：NP-Tools 2.0.0；HTTP API：KZ3 v1；文档日期：2026-08-28。

## 1. 交付范围

本次交付面向现场工程师的设备接入、状态判断、业务点监视、通信排障和会话留档。工具提供：

- 独立的 KZ3 在线调试模式，与工程组态编辑隔离；
- 对 `/api/v1/device`、`hardware`、`network`、`sle`、`io`、`config`、`services`、`health` 的固定诊断；
- 基于当前工程北向字段的最多 12 点监视组；
- 点位设备质量、本机陈旧状态、采样时效和请求耗时；
- 暂停、继续、立即采样、单点读取、监视组本机记忆；
- 设备身份、健康、网络、服务和板级 I/O 诊断侧栏；
- BOOL/FLOAT parameter 修改和 BOOL command 单次触发；
- 写前读取、单次写入、写后读回、逻辑/物理效果人工标注；
- 会话日志、历史写入证据查看以及 JSON 会话报告导出。

当前版本开放的是受控测试写入，不是生产在线控制或在线强制。工具和 Rust/Tauri 后端只允许当前工程中
标记为 `read_write` 的 BOOL/FLOAT parameter 或 BOOL command，禁止直接写 point/state、整数
parameter、任意 URL 和任意路径。设备端权限、类型、范围和 owner 拒绝仍然有效。

## 2. 使用前条件

1. 工程师应取得目标控制器的 IP 和 HTTP 端口，确认调试电脑与设备位于授权的隔离网络；
2. 在“工程组态”中打开与目标设备预期一致的 `project_io.yaml`；
3. 当前固件必须实现 KZ3 HTTP v1 诊断接口；
4. 防火墙和网卡路由允许调试电脑访问目标设备；
5. 准备明确的工程师姓名/工号、测试编号和预期逻辑/物理效果；
6. 写入测试前确认设备处于安全测试条件，相关负载可被观察且具备人工停止手段；
7. 现场使用发布安装包，不使用浏览器开发服务器替代桌面程序。

工具当前无法从设备读取项目 ID、工程版本或点位 manifest，因此只能把兼容性标记为 `PARTIAL`。工程师
必须人工核对设备 SN、App 版本和当前打开工程。没有这些证据时，不得把点位数据用于投产结论。

## 3. 标准操作流程

### 3.1 进入在线模式

在左侧 KZ3 产品区选择“在线调试工作台”，或从工程组态右下角点击“进入在线调试”。在线模式会自动：

- 折叠全局导航；
- 隐藏无关串口连接状态；
- 隐藏 YAML 编辑、导入导出和配置 Tab；
- 在顶部固定显示当前工程身份与“写入需解锁”。

### 3.2 连接与预检

填写设备 HTTP 根地址，例如 `http://192.168.11.59:8080`。可选填写工程师和位置，这些信息会进入会话
报告。点击“连接并预检”后，先读取设备身份，再依次读取其余固定诊断。

状态含义：

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| 未连接 | 尚未建立有效会话 | 检查 IP 后连接 |
| 正在预检 | 正在读取身份和诊断资源 | 等待，不重复点击 |
| 在线监视 | 至少有近期成功响应 | 可以监视；写入仍锁定 |
| 监视已暂停 | 会话保留但停止周期轮询 | 可单点读取或继续 |
| 通信降级 | 存在请求失败 | 查看底部日志和诊断侧栏 |
| MISMATCH | 点位缺失、类型不符或打开工程变化 | 结束会话，核对工程和固件 |

### 3.3 建立监视表

在线调试默认展示当前工程的全部北向字段，标题同时显示工程字段总数和“监视 n/12”。只有加入监视组的
点参与周期轮询；可用“全部点/仅监视组”切换显示范围，并按点名、bind 或地址搜索。点表的“Modbus 地址”
列只显示北向 `reference`（例如 `00001`、`40001`），不重复显示第一列已经能够表达的绑定信息；悬停地址
仍可查看 `bind` 和值语义。每个工程最多保存 12 个监视点，列表保存在本机，不写入工程 YAML。

点位表按 PLC 调试语义固定分为“控制命令、可调参数、状态反馈、过程 I/O、其他上报”。控制命令和
可调参数分别承载一次性控制与运行期调参；其余分组是只读观察维度。每个分组显示点数、可写/只读属性和
已加入监视组的数量，可单独或一键展开、收起；搜索、类别筛选和“仅监视组”会继续作用于各分组。

- `GOOD/INIT/STALE/OFFLINE/BAD` 是设备返回质量；
- `LOCAL STALE` 表示工具超过 3 秒未收到该点新样本；
- “无采样”和 `UNKNOWN` 表示没有证据，不等于数值 0 或布尔 OFF；
- `DO/AO 目标` 是软件目标，不等于端子、接触器或真实电流反馈；
- Southbound 寄存器影子不等于物理反馈。

使用“暂停”冻结周期监视，使用刷新图标立即执行一轮采样；每行右侧刷新按钮只读取该点。操作列始终固定
在表格右侧，最小窗口下无需横向滚动才能找到单点操作。

### 3.4 解锁和执行北向写入测试

1. 在顶部填写工程师姓名/工号；连接设备并完成预检；
2. 确认工程身份未变化、健康四项均正常且没有 active fault；
3. 点击底部“解锁写入”，核对设备 SN 和工程版本，一次填写本组测试编号/依据，勾选安全确认并输入“启用写入”；
4. 许可按最后一次成功写入续期 10 分钟。离开页面、断开连接、工程变化、连续健康失败或 active fault 会立即上锁；
5. 切换“全部点”，对带 RW 且有写入图标的 parameter/command 点击写入；
6. parameter 选择 BOOL 值或输入范围内 FLOAT；command 固定单次触发 TRUE，但不会解除当前 10 分钟许可；
7. 单点弹窗自动带入解锁时填写的测试依据，只需确认点名和目标值；弹窗显示的是打开瞬间的读值快照，
   用户草稿与后台实时样本完全分离，轮询不会改写正在输入的目标值。弹窗单独显示“本次请求值”，修改
   目标值后会自动取消原安全确认，必须针对最终值重新勾选。正式提交前工具仍会重新读取写前值；若设备
   值已不同于弹窗打开时快照，则取消写入并要求重新核对。必要时可按点补充测试依据；
   “确认写入”按钮不跟随周期采样切换可用状态；点击后停止下一轮采样、等待当前采样排空，再执行写入，
   结束后自动恢复轮询；
   写入和解锁弹窗不会因点击遮罩或拖选文字到弹窗外而关闭，只能使用右上角关闭或“取消”明确退出；
8. 打开“写入证据”，核对传输、Owner 和读回，并人工标注逻辑效果、物理效果及观察备注；
9. 每完成一组测试立即导出会话报告，结束时点击“立即上锁”。

HTTP 成功响应只证明请求通过设备变量服务并被当前 RAM owner 接受。parameter 写后读回通过也不证明
已经持久化；command 不保证逻辑扫描、联锁、输出和现场负载已动作。parameter 读回失败/未知、超时或
设备拒绝会自动上锁，工具不会自动重试；成功的 command 保持当前许可，但仍应先确认关联状态再继续操作。
写入证据中的 `requestedValue` 和结果提示必须使用提交瞬间输入框中的可见值，不能从实时样本或打开时快照
反向覆盖。

### 3.5 诊断和留档

点击固定目标栏右侧“诊断”打开侧栏。健康、设备、网络、服务和板级 I/O 均按证据显示，未取得的数据
保持 `—`。侧栏默认宽 400 px，可拖动左边缘在 340～620 px 内调整；左/右方向键也可调整，宽度保存在
本机。窄窗口采用覆盖式侧栏并受视口宽度约束，避免挤压监视表或产生页面级横向滚动。底部 Dock 记录
会话、诊断和错误；点击“导出会话”保存 `kz3-debug-session/v1` JSON 报告。

报告包含项目身份、会话元数据、验证边界、诊断快照、监视点样本、日志和历史写入证据。产生写入记录后
`hardwareHil` 标记为 `in_progress`；这只表示测试已经开始，不表示通过。`fieldCommissioning`
保持 `not_verified`，直到另有受控现场验收记录。

### 3.6 结束会话

完成调试后点击“结束会话”，确认状态回到“未连接”，再离开在线调试页。直接离页也会停止轮询；旧会话
迟到响应会被丢弃，不能恢复已结束会话或污染下一台设备。

## 4. 故障排查

| 现象 | 优先检查 |
| --- | --- |
| 无法连接 | IP/端口、网卡路由、防火墙、设备 HTTP 服务 |
| 设备身份有数据但其他卡片为空 | 底部日志中的具体资源、HTTP status 和设备原始错误 |
| 点位 404 | 打开的工程与设备固件点表不一致；立即按 MISMATCH 处理 |
| 点位一直 UNKNOWN | 是否加入监视组、监视是否暂停、该点是否存在于设备 |
| LOCAL STALE | 链路延迟、轮询点过多、设备 HTTP client 忙或会话降级 |
| 诊断值为“—” | 当前没有证据，不得按 0、OFF 或正常处理 |
| “解锁写入”不可用 | 补充工程师；检查四项健康、active fault、工程变化和连接状态 |
| 没有写入图标 | 字段不是受支持的 RW BOOL/FLOAT parameter 或 BOOL command |
| HTTP 403 `point_write_failed` | 可能是只读、类型/范围、owner、写忙或工程不匹配；固件当前不能细分 |
| Owner 接受但读回失败 | 立即停止连续操作，读取点位与诊断，保留原始响应并核对工程/固件 |

工具不提供任意 HTTP 路径、任意 Modbus 地址、批量写入、在线强制或自动动作序列。不得使用第三方通用
请求工具绕过本工具边界。

## 5. 已执行的软件验收与未验证边界

成品发布前最低软件门禁：

```sh
pnpm build
pnpm exec eslint src/types/controllerDebug.ts src/stores/controllerDebugStore.ts \
  src/router/index.ts src/App.vue src/components/layout/AppSidebar.vue \
  src/views/devices/controller/ControllerView.vue \
  src/views/devices/controller/OnlineDebugTab.vue
cargo test --workspace
cargo clippy -p desktop --lib --no-deps -- -D warnings
rustfmt --edition 2021 --check src-tauri/src/kz3_http.rs
pnpm tauri:build
```

macOS 开发机没有 Developer ID 证书时，可使用 `pnpm tauri:build:macos-local` 生成完整 ad-hoc 签名的本机
验收包。该包可验证 bundle 完整性，但没有 Apple 公证，不能代替正式外部分发包。正式发布仍使用
`pnpm tauri:build` 并由发布环境提供 Apple 签名与公证凭据。

交互验收至少覆盖桌面默认 `1100×760` 和最小 `850×600`：页面不得产生全局横向滚动，目标身份、监视表、
操作列和底部证据 Dock 必须可见；诊断侧栏可以覆盖打开，但不能改变监视表宽度。还应覆盖宽屏并排模式，
验证侧栏默认 400 px、340～620 px 拖拽边界、键盘调整和本机宽度记忆。

以下结论明确不在本次软件交付证明范围内：

- 真实控制器 HTTP 长时间负载和断网恢复；
- DI/DO 端子极性、AO/AI 电气量程和负载动作；
- 702/703/705 输出的实际物理效果；
- 北向写入 owner、读回、逻辑联锁与物理反馈闭环；
- Windows/macOS 安装包在全部目标现场电脑上的兼容性。

这些项目在实际执行前必须保持“待 HIL/待现场”，不能用前端构建、Rust 单测或浏览器渲染结果代替。
