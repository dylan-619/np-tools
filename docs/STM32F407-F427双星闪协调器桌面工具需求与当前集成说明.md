# STM32F407/F427 双星闪协调器桌面工具需求与当前集成说明

> 文档状态：NP-Tools 集成基线
>
> 整理日期：2026-09-01
>
> 上游需求：`STM32_XTQ/docs/STM32F407-F427双星闪协调器桌面调试配置工具需求规格说明书.md`

## 1. 集成目标

在 NP-Tools 中增加独立的“双星闪协调器调试工作台”，服务研发联调、生产配置、现场开通和故障诊断。工具以一个串口设备会话为事务边界，固定使用协调器 USART1 `115200/8N1/None`，不复用 SJZDV3 的单模组、Modbus 或模拟量业务模型。

首版产品目标分为四层：

1. 稳定识别 F407/F427 协调器并展示真实 `@STATUS`；
2. 读取、审查和配置 EEPROM owner，所有写入基于完整当前对象；
3. 将双 Radio、路由、点缓存、同步和 Ethernet 故障分域展示；
4. 待固件补齐接口后，实现同步规则和 Radio 深度观测的完整闭环。

## 2. 产品差异与安全原则

- 设备有两颗独立星闪模块，Radio 1 为 USART6/ZIG1，Radio 2 为 USART2/ZIG2；角色可以交换，界面不得固定南北向。
- 有效模式为 `PROVISIONING(0)`、`ETHERNET_EDGE(1)` 和 `SLE_CASCADE(2)`。Radio 芯片工作模式由角色派生，不能作为独立配置制造不一致。
- `@CFG SET` 是完整对象替换，不是局部更新。写入前必须先读取当前 owner，候选 JSON 必须包含全部且仅包含固件 schema 字段。
- `CoordinatorConfig`、Radio、Ethernet 和 factory 身份写入成功后返回 `OK_REBOOTING` 并立即复位。设备回包只证明命令被接受，重启后仍需重新识别和读回。
- 不提供 EEPROM/Flash 裸地址写入、Mass Erase、跨芯片镜像烧录或绕过固件 owner 校验的入口。
- 工具中的“通过”结论必须区分本地校验、设备回包、读回一致、运行状态恢复和 HIL/现场验证。

## 3. 页面与功能范围

### 3.1 当前已集成

导航入口：`双星闪协调器 / 协调器调试工作台`。

运行总览：

- 通过 `@STATUS` 识别 `F407VGT6/F427VGT6`，显示固件、Router SN、有效模式、uptime、boot ID、reset cause 和配置错误掩码；
- 分别显示 Radio 1/2 的角色、状态机、READY、STA、观测地址、恢复、有效帧、UART、RX 重启、无效帧和丢弃字节；
- 展示路由/邻居/冲突/丢弃、点缓存、同步摘要、Ethernet/TCP 摘要和 capability 数量；
- 未知枚举保留原始值并显示 `UNKNOWN(raw)`；默认 2 秒周期轮询，配置事务期间停止发送轮询命令。

配置快照：

- 读取 `DeviceIdentity`、`CoordinatorConfig`、`Radio1Config`、`Radio2Config`、`EthernetConfig`；
- 基于设备当前值生成可审查 JSON 草稿；
- 校验必需/未知字段、整数范围、ASCII 字节范围、模式角色组合、Radio 地址与固定字段、IPv4/MAC 和完整命令长度；
- 普通固件身份保持只读；其他 owner 写入前显示重启与非原子风险确认；
- 收到 `OK_REBOOTING` 后进入等待复核状态，由用户在设备恢复后触发重新识别及五类 owner 读回。

会话与诊断：

- 保存事务 ID、操作类型、命令、回包、起止时间、串口和最终状态；
- 导出状态、前次采样、owner 快照、事务和未验证边界为 JSON 诊断记录；
- 不将串口联调描述为实板、射频或现场验证通过。

### 3.2 尚未集成

- 32 个 `DeviceCapability0..31` 的批量表格、CSV/JSON 导入导出和逐槽差异写入；
- 同步规则表单/表格编辑、规范化、CRC32、上传和读回一致闭环；
- 自动串口热插拔重连与 30 秒重启窗口；
- 状态时间序列 CSV、结构化 diff、跨设备网络名/地址台账；
- `tools/xtq.py` 的构建、目标探测、安全烧录、复位和 GDB Server 专家界面；
- Windows/macOS 安装包、24 小时长稳、F407/F427 双目标 HIL 和三级级联现场验收。

## 4. 已落地协议

```text
@STATUS\r\n
@CFG GET DeviceIdentity\r\n
@CFG GET CoordinatorConfig\r\n
@CFG GET Radio1Config\r\n
@CFG GET Radio2Config\r\n
@CFG GET EthernetConfig\r\n
@CFG SET <owner> <single-line-complete-json>\r\n
```

主要响应处理：

| 回包                                                  | 当前行为                                   |
| ----------------------------------------------------- | ------------------------------------------ |
| `OK <json>`                                           | 解析并保留原始回包，更新状态或 owner 快照  |
| `OK`                                                  | 标记事务成功；在线 owner 后续读取确认      |
| `OK_REBOOTING`                                        | 进入等待重启复核，不宣称运行恢复           |
| `READ_ONLY`                                           | 停止写入，提示普通固件身份只读             |
| `BAD_*`、`EEPROM_*`、`FLASH_ERROR`、`BUSY`、`TIMEOUT` | 记录设备错误并停止事务，不自动无限重试     |
| 本地超时                                              | 标记 timeout，不自动重复可能产生写入的命令 |

## 5. 固件接口缺口

以下能力不能由桌面端从摘要计数推断，必须由固件和桌面端共同冻结协议：

1. `@SYNC GET`：返回 canonical UTF-8 JSON 的准确长度、CRC32、sequence 和定长 payload；
2. Radio 完整观测：工作模式、网络名、功率、字段有效位、当前差异、重试和恢复退避剩余时间；
3. 路由、邻居和点缓存明细；
4. 每条同步规则统计、源点诊断、目标路由和受控单次执行；
5. 指定 Radio 的安全原始 AT 会话。

在这些接口完成前，NP-Tools 只展示固件真实提供的摘要，不显示虚构的同步内容、Flash 擦除次数、栈高水位或模组功率档位。

## 6. 分阶段出口

| 阶段        | 出口                                                              |
| ----------- | ----------------------------------------------------------------- |
| 1. 只读诊断 | 设备可识别，状态和五类 owner 可稳定读取，诊断记录可导出           |
| 2. 配置闭环 | 模式、双 Radio、Ethernet、capability 可差异审查、写入、重连、读回 |
| 3. 同步闭环 | 完整规则可读取、编辑、校验、上传、重读一致                        |
| 4. 专家工具 | 安全封装 `tools/xtq.py`，目标和镜像校验不可绕过                   |
| 5. 发布验收 | Windows/macOS、长稳、异常断电、双目标 HIL 和现场结论分层记录      |

## 7. 当前验证边界

当前集成可通过前端类型检查和生产构建验证页面、协议模型与编译契约；这不等于串口实板验证。以下仍需设备与环境证据：F407/F427 启动、双 Radio RST/STA 与射频、EEPROM 掉电写入、LAN8742/TCP、同步 Flash 维护及掉电恢复、三级级联和现场长稳。
