# STM32F407/F427 双星闪协调器桌面工具当前集成说明

> 状态：NP-Tools 软件集成说明；未执行 F407/F427 实板、无线或级联 HIL。
> 日期：2026-09-05

## 当前可用范围

NP-Tools 为协调器提供独立串口工作台，使用 USART1 `115200 8N1`。当前可依赖的行为包括：

- 通过 `@STATUS` 读取并保存会话内状态时间线，展示已知的 Radio、路由、点缓存、同步和网络摘要；未知字段不推断为已解释状态。
- 读取 `DeviceIdentity`、`CoordinatorConfig`、`Radio1Config`、`Radio2Config`、`EthernetConfig`，以及 `DeviceCapability0..31`；Capability 写入后重新读取同一槽位核对。
- 对现有 owner 写入保留设备回包、重启恢复和读回边界；收到 `OK_REBOOTING` 时只重开本次已知串口，不扫描或抢占其他端口。
- 对同步规则执行本地 schema 预检、规范化、CRC32 与精确 `@SYNC BEGIN ... @SYNC COMMIT` 上传。
- 上传同步规则后发送 `@STATUS`，仅比较 `json_length` 与 `rules` 摘要；匹配时也明确标记为“内容未验证”。

## 当前不会使用的接口

当前固件源码未提供 `@SYNC GET` 或等效的完整规则读回。NP-Tools 不发送该命令，也不解析假设存在的 `SYNC_GET BEGIN/DATA/END` 帧。

下列结论均不能由当前工具得出：

- Flash 中规则内容与上传规范 JSON 完全一致；
- 规则已经运行、每条映射成功，或无线下行已到达；
- 掉电后规则仍保留；
- 双 Radio、路由和三级级联已通过 HIL/现场验证。

## 已使用协议

```text
@STATUS\r\n
@CFG GET <owner>\r\n
@CFG SET <owner> <single-line-complete-json>\r\n
@CFG GET DeviceCapability0..31\r\n
@CFG SET DeviceCapability0..31 <single-line-complete-json>\r\n
@SYNC BEGIN <canonical-utf8-length> <CRC32-hex>\r\n
<exact canonical UTF-8 JSON bytes>\r\n
@SYNC COMMIT\r\n
```

| 结果 | 工具解释 |
| --- | --- |
| `OK <json>` | 解析为 `@STATUS`、owner 或 Capability 快照；仅限相应命令的字段语义 |
| `OK` | 当前命令得到正向回包；不自动升级为持久化、运行或 HIL 成功 |
| `OK_REBOOTING` | 进入已知串口的重启恢复窗口；随后重新读取状态/owner |
| `BAD_*`、`EEPROM_*`、`FLASH_ERROR`、`BUSY`、`TIMEOUT` | 记录失败并停止该事务；不盲目重试写入 |
| 本地超时 | 标记通信结果未知；不把摘要或旧快照当作本次成功 |

## 待固件补齐后再实现的能力

1. 同步规则完整读回：请求 ID、内容版本、总长度、规范化 hash、连续分片和确定错误/结束帧。
2. 每条规则/映射的运行统计、源点缺失、目标失败、路由和重试诊断。
3. Radio 实时状态（区别于 EEPROM owner）：网络名、功率、地址、状态机、帧错误、恢复原因和有效位。
4. 重启/掉电后的同步配置 version/hash 与恢复完成状态。

详细接口建议和验收边界见 [STM32_XTQ 的 NP-Tools 固件接口差距记录](../../STM32_XTQ/docs/NP-Tools固件接口差距记录.md)。

## 验证边界

当前可用的前端构建和主机协议测试只验证工具的解析、边界处理和命令构造；它们不等于串口实板、Flash 擦写、无线链路、F407/F427 启动、掉电恢复或三级级联现场验证。
