# KZ3 在线调试工具软件验收记录

> 验收日期：2026-08-28
>
> 结论：桌面工具的在线监视和受控北向写入测试能力达到软件交付条件；HIL、真实设备链路、写入逻辑/物理
> 效果和现场验证尚未通过，须由工程师执行并记录。
>
> 注：本记录保留 2026-08-28 时的软件验收范围和产物信息；v1.0.4 后续新增的 U32 parameter 写入不在本历史记录的验收结论内。

## 1. 本次验收对象

- 独立 KZ3 在线调试路由与工程组态模式隔离；
- KZ3 HTTP v1 固定诊断代理；
- 北向点位监视表、质量与时效展示；
- BOOL/FLOAT parameter 和 BOOL command 受控写入、写前读、写后读回与 10 分钟许可；
- 暂停、继续、立即采样、单点读取和本机监视组；
- 诊断侧栏、会话日志和 JSON 会话报告；
- 断开/重连旧响应隔离、工程变化门禁、点位类型核对和 Rust 后端写入白名单；
- macOS arm64 桌面 bundle。

## 3. 桌面尺寸与交互验收

使用本地生产等价页面检查以下尺寸：

| 窗口 | 页面全局尺寸 | 监视区 | 结果 |
| --- | --- | --- | --- |
| `1300×800` 宽屏窗口 | `body.scrollWidth=1300` | 诊断默认 400 px；监视区宽约 816 px | 并排显示无页面级横向溢出；点表无需横向滚动 |
| `1100×760` 默认窗口 | `body.scrollWidth=1100` | 主工作区宽约 1022 px；诊断覆盖宽 400 px；监视区高约 369 px | 无页面级横向溢出；诊断不改变监视表宽度 |
| `850×600` 最小窗口 | `body.scrollWidth=850` | 主工作区宽约 772 px；实测诊断覆盖宽 544 px；监视区高约 209 px | 无页面级横向溢出；诊断独立纵向滚动且不改变监视表宽度 |

已人工检查：

- 工程组态和在线调试可以双向切换；在线模式自动折叠侧栏并隐藏串口状态；
- 诊断侧栏在默认窗口覆盖打开，不挤压监视表，不产生全局溢出；
- 无设备数据时显示“无采样”、`UNKNOWN` 和 `—`，不显示伪造的 `0/OFF`；
- “全部点”与“监视组”切换有效，点位可以加入监视组；
- “Modbus 地址”列只显示 5 位 `reference`；`bind` 和值语义保留在悬停详情及搜索中；
- 最左监视列和最右操作列冻结；
- 诊断侧栏左边缘可拖拽，340～620 px 边界和左右方向键调整有效；本机宽度保存/读取路径已代码核对；
- 写入默认锁定；只有工程师身份、连接、工程身份、四项健康和 active fault 门禁满足时才可解锁；
- 解锁后只对工程标记为 `read_write` 的 BOOL/FLOAT parameter 和 BOOL command 显示写入流程；
- 解锁时一次填写本组测试依据，单点写入自动带入；每次写入仍需核对目标值并显式确认；
- command 只触发一次、不保持且失败不自动重试，成功后保留当前 10 分钟许可；
- 写入证据支持标注逻辑效果、物理效果和观察备注。

在线调试工作台采用白色/浅灰工作面和深色文字，状态色仅用于在线、待验证和故障语义。可见文本审计未发现
低于 9 px 的文字，点名与实时值为 12 px；主要文字组合的对比度为 5.18:1～16.29:1，达到 WCAG AA
普通文本对比度要求。诊断侧栏默认宽 400 px；实测拖到 620 px 上限仍不改变页面全局宽度，小窗口下可
独立纵向滚动。宽屏主动拉宽会减少监视表可视宽度，点表按内部滚动处理，不产生页面级横向滚动。

浏览器开发环境会因为缺少 Tauri IPC 而记录既有串口枚举错误；该错误来自 `GlobalSerialBar` 在浏览器
开发模式调用串口 IPC，不是在线调试页面错误。桌面生产构建已完成 Rust/Tauri 链接。

notarization；Windows 安装包必须在 Windows 构建机执行并验证，当前 macOS 构建不能证明 Windows 包可用。

## 5. 未验证边界

以下结论仍为“待 HIL/待现场”，不能写成已通过：

- 真实 KZ3 设备八个诊断端点的响应兼容性；
- 实际网络断连、设备重启、长时间轮询和多客户端压力；
- 修复后的 macOS WebView 参数弹窗在持续轮询下长时间无白帧，需使用本次新包现场复验；
- DI/DO/AI/AO 端子电气事实和负载动作；
- parameter/command 写入 owner、读回、逻辑和物理效果；
- 现场工程师完整任务走查和误操作率；
- Apple 公证包、Windows 安装包和目标现场电脑兼容性。

## 6. 交付判断

可以把本版本作为“KZ3 在线诊断与受控北向写入测试工具”交给内部工程师执行验证，但安装包发布负责人
仍需根据目标平台完成正式签名/公证或 Windows 构建。写入测试开放不等于 HIL 通过，不得对外宣称已经
具备生产写控制、HIL 闭环或现场投产验证。
