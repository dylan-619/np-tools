# NP-Tools 整体 UI 优化方案

> 文档状态：已实施（待设备联机/现场环境回归）  
> 适用版本：NP-Tools v2.0  
> 目标：在不改变现有功能、协议、业务流程和安全边界的前提下，提升工业自控调试场景下的界面密度、信息层级、状态辨识和长时间使用舒适度。

## 1. 工具定位与设计对象

NP-Tools 不是单一串口助手，而是一个面向生产、现场调试和工艺组态的工业硬件工作台。目前包含四类能力：

1. SJZDV3 设备生产与现场调试：设备信息、SN 固化、SLE 配置、Modbus 点位、模拟量监测和系统维护；
2. KZ3 工艺项目配置：硬件拓扑、南向设备、I/O 点表、应用变量、北向映射、YAML 诊断与工程检查；
3. 公共调试工具：通用串口终端和 ST-Link 固件烧录；
4. 全局基础能力：串口连接、收发统计、通知、确认和应用设置。

主要用户是生产人员、现场调试工程师、PLC/工艺工程师和固件工程师。与普通后台管理系统相比，本工具更看重：

- 一屏内可见更多有效数据；
- 连接、运行、告警、错误和危险操作能被快速区分；
- 表格、日志、地址、点位和协议值适合连续录入与对照；
- 操作结果明确、可追溯，避免误操作；
- 在 Windows 现场笔记本和默认 1100×760 窗口下仍可高效工作；
- 长时间使用不过亮、不刺眼，不依赖单一颜色传达含义。

## 2. 现状审查

### 2.1 已有优点

- 已采用统一暗色基调，适合终端、日志和现场弱光环境；
- 全局串口连接由 Pinia 共享，产品页切换不会打断物理连接；
- 主要页面已经形成标题区、操作区、内容区的基本层次；
- 串口终端采用“顶部过滤工具栏 + 中部日志 + 底部发送坞”，符合专业调试工具心智；
- KZ3 已按工程步骤划分六个工作区，业务流程基本清晰；
- 高危操作已有确认弹窗，成功、告警、错误也已有基本视觉反馈。

### 2.2 主要问题

#### 2.2.1 全局框架重复占用空间

当前同时存在顶部品牌、侧栏品牌和页面级大标题，串口状态也同时出现在标题栏和侧栏底部。默认窗口宽度为 1100px，固定 250px 侧栏使主内容区仅剩约 850px。对 Modbus 表格、KZ3 点表和日志类页面而言偏窄。

具体表现：

- 同一页面最多出现三层“应用/模块/页面”标题，但有效操作和数据被向下推移；
- 侧栏底部串口卡片在错误信息出现时明显增高，进一步压缩导航；
- Modbus 顶部工具栏在默认宽度下已经换行，操作顺序被打断；
- KZ3 顶部六个页签总宽度过大，且 `.nav-tabs-bar` 未禁止 Flex 收缩，在内容较高时可能被压缩到接近横向滚动条高度；
- 页面切换后的滚动位置、页头和局部导航缺少统一的固定策略。

#### 2.2.2 页面密度缺乏统一基线

当前不同页面分别定义 `padding`、`gap`、按钮高度、卡片圆角和表格行高。同级信息有时使用大卡片，有时使用紧凑行，导致视觉节奏不稳定。

- 状态概览大量使用独立卡片，单位面积承载的信息偏少；
- 页面说明文字较长并长期占据首屏，应把“使用说明”与“当前任务”分开；
- 空表格、空日志仍保留较大的固定高度，首屏空间利用率不高；
- 工具栏中主操作、次操作、文件操作和危险操作没有稳定分组；
- 表单标签、帮助说明和单位经常占用三行，连续录入效率不足。

#### 2.2.3 颜色语义不稳定

全局基础色集中在 `App.vue`，但各页面仍存在大量硬编码颜色。代码审查中，`#2a2f42`、`#94a3b8`、`#3b82f6` 等颜色在各 Vue 文件中被重复使用数十到上百次，并出现多套蓝、绿、紫、黄、红。

当前颜色同时承担以下不同含义：

- 蓝色：主操作、当前选中、输入值、DI 类别；
- 绿色：成功、在线、INFO 日志、DO 类别、测试操作；
- 黄色：告警、模拟量、提示信息；
- 紫色：产品分类、AO 类别、变量模块和装饰强调；
- 红色：错误、断开、删除、高危操作。

同一颜色跨“状态色”和“分类色”使用，会让现场人员难以在短时间内判断它代表状态还是对象类别。部分禁用态直接降低整块透明度，也会使文字对比度过低。

#### 2.2.4 视觉层级偏“卡片化后台”，不够像工程工具

当前多个页面使用大圆角卡片、渐变图标底色和彩色发光效果。单独看较现代，但大量重复后会削弱表格、日志、点位、端子和状态这些真正重要的信息。

工业调试工具更适合：

- 清晰边界而不是重阴影；
- 紧凑行和分区标题而不是层层套卡片；
- 稳定的状态栏和工具栏而不是装饰性大标题；
- 数字、单位、地址和协议值对齐；
- 少量且稳定的颜色语义。

#### 2.2.5 基础组件重复实现

按钮、面板、状态徽标、表格、Toast、输入框和空状态散落在各页面的 scoped CSS 中。当前已经出现多套 `.btn-primary`、`.panel-card`、`.data-table` 和 Toast 样式。继续逐页微调会增加视觉分叉和维护成本。

## 3. 总体设计方向

### 3.1 视觉方向

采用“克制的工业仪表工作台”方向：深色石墨背景、冷灰层级、单一蓝色交互强调、严格的状态色和少量设备类别色。

界面应让用户首先记住：**这是一个信息密集、状态明确、操作可靠的工程工具，而不是由大卡片组成的后台系统。**

### 3.2 设计原则

1. **数据优先**：首屏优先展示设备状态、点表、日志和当前任务，说明文字默认收敛；
2. **状态先于装饰**：颜色只帮助判断，不为了“丰富”而平均分配颜色；
3. **稳定布局**：全局标题栏、上下文工具栏、局部导航和状态区位置保持稳定；
4. **紧凑但不拥挤**：主要控件高度保持 30–32px，表格行高保持 34–38px，并保留清晰分组；
5. **危险操作隔离**：删除、擦除、复位、清空配置不与日常主操作并排混色；
6. **不只依赖颜色**：状态同时使用图标、文字、形状或边框；
7. **渐进实施**：先统一 Token 和框架，再调整页面，不在视觉改造中修改协议与 Store 行为。

## 4. 全局布局方案

### 4.1 推荐结构

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 32px 原生标题栏：NP-Tools / 当前模块                 串口状态 / 端口 / 收发 │
├──────────────┬─────────────────────────────────────────────────────────────┤
│              │ 48px 上下文栏：面包屑 / 页面标题        页面级主要操作      │
│ 218px        ├─────────────────────────────────────────────────────────────┤
│ 全局导航     │                                                             │
│ 可折叠 52px  │                    主工作区                                 │
│              │   表格 / 日志 / 表单 / 图表，按页面独立滚动                 │
│              │                                                             │
│              ├─────────────────────────────────────────────────────────────┤
│ 串口快捷区   │ 可选 28px 状态栏：任务、校验、通信统计、提示                │
└──────────────┴─────────────────────────────────────────────────────────────┘
```

### 4.2 全局标题栏

- 高度由 38px 收紧到 32–34px；
- 只保留一次应用品牌和当前一级模块名称；
- 右侧集中显示串口连接状态、端口名、RX/TX 活动；
- 在线、离线、连接中、超时均使用“图标 + 文案 + 状态色”，不只使用圆点；
- 页面长标题、版本标签和说明不再放进原生标题栏。

### 4.3 全局侧栏

- 展开宽度由 250px 调整为 218–224px；折叠宽度为 52px；
- 删除与顶部标题栏重复的完整品牌头，侧栏顶部只保留产品切换或折叠按钮；
- 导航组高度收紧，导航项建议 34px，组间距 10–12px；
- 选中态使用左侧 2px 蓝色标线 + 稳定底色，不使用发光描边；
- 产品标签只在确有业务意义时显示，不用紫色作为纯装饰；
- KZ3、Modbus 等横向空间敏感页面可记忆用户的侧栏折叠状态；
- 导航区域独立滚动，底部串口快捷区不得因错误文本改变导航高度。

### 4.4 串口连接区

保留当前全部连接功能，但压缩成两级呈现：

- 常驻态：状态、端口、连接/断开按钮、刷新按钮；
- 展开态：波特率、数据位、校验位、DTR、RTS 和错误详情；
- 错误常驻区只显示一行摘要，完整错误通过展开或 Tooltip 查看；
- 顶部状态与侧栏连接区共享同一状态组件，避免样式和文案分叉；
- “断开”属于连接切换操作，不应默认使用与“清空 EEPROM”同等强烈的高危红色，可用中性按钮配红色图标和明确文案。

### 4.5 页面上下文栏

将现有页面大标题、短说明和右侧按钮统一为 44–48px 高的上下文栏：

- 左侧：面包屑、短标题、必要的对象标识；
- 右侧：1 个主操作和若干次操作；
- 长说明移入帮助按钮、可折叠说明或首次使用提示；
- 上下文栏在页面内容滚动时保持可见；
- 页面不再额外创建大尺寸“Hero Header”。

## 5. 密度与尺寸基线

建议建立三档密度，默认使用 `compact`，终端和点表可使用 `dense`，确认弹窗与引导页使用 `comfortable`。

| 项目 | Dense | Compact（默认） | Comfortable |
| --- | ---: | ---: | ---: |
| 控件高度 | 28px | 32px | 36px |
| 表格行高 | 32–34px | 36–38px | 42px |
| 工具栏高度 | 34px | 40px | 44px |
| 面板头高度 | 34px | 38px | 44px |
| 页面外边距 | 8px | 12px | 16px |
| 面板内边距 | 8px | 10–12px | 16px |
| 同组间距 | 4px | 6px | 8px |
| 分组间距 | 8px | 12px | 16px |
| 圆角 | 3–4px | 5–6px | 8px |

实施规则：

- 表格和日志使用 `dense`；
- 普通表单和工具栏使用 `compact`；
- 高危确认弹窗可以使用 `comfortable`；
- 不允许页面自行新增第四套尺寸；
- 点击目标在主要操作上仍应达到约 32px，高频图标按钮不得小于 28px；
- 通过分组、分隔线和标题建立秩序，而不是依靠大面积留白。

## 6. 颜色系统

### 6.1 基础色 Token

以下为建议初稿，最终需在实际 WebView 和目标显示器上做对比度验证：

```css
:root {
  /* Surfaces */
  --color-canvas: #0b1016;
  --color-surface-1: #111820;
  --color-surface-2: #17212b;
  --color-surface-3: #1d2a35;
  --color-overlay: #22313d;

  /* Borders */
  --color-border-subtle: #24323d;
  --color-border-default: #31424f;
  --color-border-strong: #425766;

  /* Text */
  --color-text-primary: #e6edf3;
  --color-text-secondary: #a8b6c2;
  --color-text-tertiary: #718391;
  --color-text-disabled: #586874;

  /* Interaction */
  --color-accent: #3b82f6;
  --color-accent-hover: #5593f7;
  --color-accent-active: #2f6fd2;
  --color-focus-ring: #79a9ff;

  /* Semantic status */
  --color-info: #4aa3ff;
  --color-success: #38b276;
  --color-warning: #d89b31;
  --color-danger: #df5b5b;
}
```

色面之间应依靠亮度层级和边框区分，不大量使用阴影。暗色背景不使用纯黑，正文不使用纯白，以降低长时间观看疲劳。

### 6.2 状态色规则

| 状态 | 颜色 | 必须同时出现的非颜色信息 |
| --- | --- | --- |
| 已连接、运行正常、校验通过 | Green | Check/Link 图标 + 明确文案 |
| 连接中、正在读取、正在烧录 | Blue | Spinner/Progress + 当前步骤 |
| 未连接、未配置、未运行 | Neutral Gray | 状态文案，不使用红色 |
| 超时、差异、待确认 | Amber | Warning 图标 + 原因或数量 |
| 故障、校验失败、操作失败 | Red | Error 图标 + 可定位信息 |
| 删除、擦除、不可逆操作 | Red | 操作动词 + 二次确认 |

关键约束：

- 红色不用于普通断开状态；离线是中性状态，异常断开才是错误；
- 绿色只表示成功/正常，不再承担普通分类强调；
- 选中和主操作统一用蓝色；
- 告警用琥珀色，不与一般提示混用；
- Disabled 使用固定的文字、边框和背景 Token，不对整块组件简单设置低透明度；
- 成功、错误和告警背景采用低饱和色面，正文保持足够对比度。

### 6.3 工业对象类别色

DI、DO、AI、AO、协议区、变量区等属于“类别”，不属于“状态”。类别色只用于小面积标签、图标或左侧标线，并始终显示文本缩写：

| 类别 | 建议色相 | 示例 |
| --- | --- | --- |
| DI | Cyan/Blue | `DI 低电平有效` |
| DO | Indigo | `DO safe:false` |
| AI | Amber | `AI 4–20mA` |
| AO | Violet | `AO 0–20mA` |
| RTU/协议 | Teal | `RS485-1 / 03H` |

类别色不得被用于“通过/失败”背景；例如 DO 标签即使采用 Indigo，在线状态仍必须使用独立的 Green 状态标识。

## 7. 字体、数字与图标

### 7.1 字体层级

- UI 字体继续优先使用系统字体，保证 Windows/macOS 一致可用；
- 中文正文建议 13px，次要说明 12px，表头 12px，页面标题 15–16px；
- 不使用过多 `font-weight: 700`，常规标签使用 500，关键数值使用 600；
- 协议、SN、地址、寄存器、Hex、日志和版本统一使用等宽字体；
- 数字列使用 `font-variant-numeric: tabular-nums`，保证刷新时不跳动；
- 数值与单位分离但保持同一基线，例如 `12.350` + `mA`。

### 7.2 图标规则

- 统一使用 Lucide，常规 14–16px，页面主图标不超过 18px；
- 同一个动作只使用一个固定图标，例如刷新、导入、导出、删除；
- 图标按钮必须提供 Tooltip 和可访问名称；
- 不使用 Emoji 作为正式工具栏图标，避免平台差异；
- 不使用图标发光表现状态，活动状态可用轻微脉冲或描边，但动画必须克制。

## 8. 公共组件规范

建议新增统一样式层与基础组件，逐步替换页面内重复 CSS：

```text
src/styles/
├── tokens.css       # 颜色、字号、间距、圆角、层级
├── reset.css        # 全局基础样式
├── utilities.css    # 少量布局与文本工具类
└── themes.css       # 后续主题扩展，首期只保留工业暗色

src/components/ui/
├── UiPageBar.vue
├── UiToolbar.vue
├── UiPanel.vue
├── UiButton.vue
├── UiIconButton.vue
├── UiStatusBadge.vue
├── UiDataTable.vue
├── UiEmptyState.vue
├── UiInlineMessage.vue
└── UiToastHost.vue
```

### 8.1 按钮

- `primary`：每个上下文区最多一个，用于查询、保存、下发、开始等当前主任务；
- `secondary`：导入、导出、复制、回读等普通操作；
- `ghost`：工具栏低权重操作和图标按钮；
- `danger`：只用于删除、清空、复位、擦除；
- `danger-soft`：进入危险流程，最终确认按钮使用实色 Danger；
- Loading 状态保留按钮宽度，显示当前动作文本，不只显示 Spinner。

### 8.2 面板

- 默认使用 1px 边框和 4–6px 圆角，不使用大面积阴影；
- 面板嵌套最多两层；第三层改用分隔线、标题行或底色变化；
- 面板头统一支持标题、状态、计数和右侧操作；
- 可折叠面板明确展示展开状态，折叠后只占一行。

### 8.3 表格

- 表头 Sticky，行高 34–38px；
- 数字、地址、功能码和操作列固定宽度，名称与说明列弹性伸缩；
- 行内编辑控件与只读单元格高度一致，避免进入编辑态后整行跳动；
- Hover 只轻微提升背景亮度，选中行使用左侧蓝色标线或稳定底色；
- 错误定位到单元格和行，同时在统一诊断区显示；
- 操作列固定在右侧，危险操作与测试操作保持距离；
- 空状态控制在一到两行，不占用 200px 以上高度；
- 横向滚动时冻结关键标识列和操作列，并显示明确的滚动阴影。

### 8.4 消息与反馈

- 全局只保留一个 Toast Host，禁止页面各自实现 Toast；
- 成功提示 2–3 秒自动消失；错误提示保留更久，并提供“查看详情”；
- 表单校验优先显示在字段附近，Toast 不代替字段错误；
- 长任务使用进度区或状态栏，不连续弹出多个 Toast；
- 所有硬件动作明确区分“命令已发送”“设备已响应”“回读一致”三个层级，不能把发送成功写成设备配置成功。

## 9. 页面级优化方案

### 9.1 SJZDV3 设备信息与 SN 烧录

- 将五个设备信息大卡片改为紧凑的两行状态矩阵或 Definition List；
- SN、型号、固件版本等识别信息放在首行，上电次数、运行时间、上报频率放在次行；
- “查询设备信息”放入上下文栏作为主操作；
- SN 烧录区保留视觉重点，但输入、格式状态、写入、回读校验放在同一任务流内；
- 长操作指引默认折叠为“SN 写入规则”，校验错误在输入框下就地显示；
- Hex Payload 预览默认折叠，高级用户可展开；
- 批量生产模式使用明确的模式开关，并持续显示“下一条 SN”。

### 9.2 SLE 无线配置

- 以 EEPROM 与芯片回读对比表作为主内容，不用两组分散卡片；
- 每行显示字段、期望值、实测值、一致性和行级操作；
- 差异使用 Amber 行标识，真正错误使用 Red；
- 修改表单放在右侧 280–320px 检查器或可收起抽屉中；
- AT 透传终端放在底部可调整高度的 Dock，未开启透传时保持一行折叠态；
- “读取全部”“同步差异”“保存单项”区分主次，不把所有操作都做成蓝色按钮。

### 9.3 Modbus 点位管理

- 页面首屏主体应是点位表，不让说明和空调试区抢占高度；
- 工具栏分组：回读/添加/预设、导入导出、批量下发、危险清空；
- “清空”固定在最右危险区，不因换行落到下一行左侧；
- 当前计数和 32 位长度约束放到表格状态栏；
- 点位表头 Sticky，序号、从站、功能码、寄存器、长度使用紧凑列宽；
- 调试抓包区改为底部可折叠、可调整高度的 Dock；空闲时只占 36px；
- 单点测试后自动展开 Dock，并高亮对应点位，不改变表格滚动位置；
- 在 850px 主区宽度下优先隐藏冗余解释文字，而不是让主操作无规则换行。

### 9.4 实时数据与硬件监测

- 两路 AI 使用紧凑数值块，突出数值、单位、状态和最新采样时间；
- 折线图占主要区域，采样控制固定在图表工具栏；
- 断线、低于量程、正常、超量程使用图标和文字，不只改变曲线颜色；
- LED 测试作为右侧窄控制区或底部工具条，标明其为“手动硬件覆盖”；
- 采样运行时持续显示频率、样本数和丢帧/超时状态。

### 9.5 系统维护与 EEPROM

- 分成“常规参数”“诊断操作”“危险区域”三段；
- 常规保存使用蓝色，清零/复位使用 Amber 引导，EEPROM 擦除使用 Red；
- 危险区域使用边框和标题，不铺满高饱和红色背景；
- 确认弹窗明确列出影响、设备、当前端口和不可恢复项；
- 输入确认词只用于真正不可逆操作，不滥用于普通重启。

### 9.6 通用串口终端

保留现有三段式布局，并做以下收敛：

- 顶部工具栏高度固定，收发统计、过滤、复制、滚屏、清空按组分隔；
- 日志时间、方向、级别和正文列对齐；RX/TX 与 INFO/WARN/ERROR 不共用同一套颜色语义；
- 底部发送坞默认紧凑，循环发送参数仅在开启后展开；
- 快捷指令支持横向滚动或“更多”菜单，不挤压发送框；
- 未连接时保留可读的终端内容与历史，不把整个发送坞整体降透明度；
- 空状态垂直居中但不使用过低对比度文字。

### 9.7 ST-Link 固件烧录

- 使用“固件—探针—烧录—校验—SN”横向步骤状态，清楚展示当前步骤和结果；
- 固件路径、探针和目标设备采用紧凑表单；
- 进度和日志放在主区域，不使用多张等权重卡片；
- 产线模式突出当前 SN、成功/失败计数和下一步动作；
- “开始烧录”与“中止”位置固定，避免任务开始后按钮跳位；
- 编程器缺失、探针未发现和烧录失败采用不同状态文案。

### 9.8 KZ3 I/O 可视化配置工作台

- 删除页面内部的大型 Hero 卡片，项目名、版本、校验状态、导入导出收敛到上下文栏；
- 六步导航固定在上下文栏下方，设置 `flex-shrink: 0`，并提供明确横向滚动提示；
- 页签名称可收敛为“总览 / 硬件与南向 / I/O 点表 / 变量与逻辑 / 北向 / YAML 检查”，计数使用独立 Badge；
- 默认窗口下自动建议折叠全局侧栏，为点表和拓扑释放宽度，但尊重用户手动选择；
- 项目总览的统计卡改为单行紧凑指标条；
- 硬件拓扑页保留“左侧设备树 + 右侧检查器”，左栏建议 240–260px，并允许折叠；
- 点表、变量表、北向表统一列高、校验样式和操作列；
- YAML 预览与诊断采用左右分栏或可拖动 Split View，错误点击后定位到代码和业务对象；
- 发布地址、符号、安全值和未验证状态必须通过锁图标、文本和状态色共同表达；
- 主机校验、HIL、实板和现场验证继续保持不同状态，UI 优化不得将其合并为一个“通过”。

### 9.9 应用设置

- 设置页使用窄表单列和清晰分组，不使用大卡片网格；
- 当前生效值和待保存值有明确差异提示；
- 与调试密度直接相关的设置可预留“界面密度”“侧栏默认状态”“终端字号”，但首轮 UI 改造不必新增这些功能；
- 保存操作固定在上下文栏或底部操作条，避免滚动后找不到。

## 10. 响应式与窗口策略

以桌面窗口为主，不把工业工作台强行改成移动端卡片流。

### 10.1 验证尺寸

| 尺寸 | 目标 |
| --- | --- |
| 850×600 | 最小可用；导航可折叠，主要操作可见，表格允许受控横向滚动 |
| 1100×760 | 默认基线；常用页面主操作不应无规则换行 |
| 1440×900 | 扩展布局；允许表单分栏、日志与表格同时可见 |
| 1920×1080 | 不无限拉宽；表单和文本设置合理最大宽度，表格/日志可使用剩余空间 |

### 10.2 断点建议

- `< 960px`：全局侧栏默认折叠为 52px，长说明隐藏到帮助入口；
- `960–1279px`：218px 侧栏 + 紧凑主区；
- `≥ 1280px`：允许双栏检查器和更完整的工具栏文本；
- 表格不改成卡片列表，优先固定关键列并横向滚动；
- 窗口尺寸变化不能导致正在编辑的输入丢失或日志滚动跳动。

## 11. 可访问性与工业现场可用性

- 常规正文和背景目标达到 WCAG AA 4.5:1；大字和关键控件至少达到 3:1；
- Focus Ring 独立于 Hover，键盘 Tab 可遍历所有工具栏与表格操作；
- 错误、告警、在线和离线均有文字；红/绿状态使用不同图标；
- 状态闪烁只用于短时通信活动，不使用持续高频闪烁；
- 支持 100%、125%、150% 系统缩放下的布局检查；
- 中文、英文标识、协议名和单位之间保持稳定间距；
- 关键按钮文案使用具体动词，例如“下发 8 个点位”“擦除 EEPROM”，避免只写“确定”；
- 异步操作期间禁止重复提交，但允许查看日志、复制信息和中止可中止任务。

## 12. 技术落地策略

### 12.1 第一阶段：视觉基础设施

1. 新建全局 Token 和密度变量；
2. 统一按钮、输入、面板、表格、Badge、Toast 和空状态；
3. 保持原有组件 Props、事件、Store 调用和 Tauri Command 不变；
4. 建立 850×600、1100×760、1440×900 三组视觉基线截图。

### 12.2 第二阶段：全局框架

1. 收紧标题栏和侧栏；
2. 合并重复品牌与串口状态；
3. 引入统一页面上下文栏；
4. 修复 KZ3 页签收缩、页面滚动容器和工具栏换行；
5. 统一 Toast 和确认弹窗宿主。

### 12.3 第三阶段：高频工具页

优先级建议：

1. 通用串口终端；
2. Modbus 点位管理；
3. KZ3 点表、硬件拓扑和 YAML 检查；
4. SLE 配置与实时监测；
5. SN 烧录、固件烧录、维护和设置。

优先处理高频、信息密集且当前布局问题最明显的页面，可以尽早验证密度体系是否合理。

### 12.4 第四阶段：一致性与回归

- 删除已经被 Token/公共组件替代的局部硬编码颜色；
- 检查所有 Loading、Empty、Disabled、Error、Offline 和 Partial Success 状态；
- 验证页面切换、折叠侧栏、缩放窗口和长文本；
- 验证键盘操作、焦点、滚动、弹窗和 Tooltip；
- 运行现有构建、Lint 和业务测试，确认 UI 调整未改变数据流和设备命令。

## 13. 功能不变边界

本轮 UI 优化明确不包含：

- 修改串口、SLE、Modbus、SN、ST-Link 或 KZ3 协议；
- 修改 Tauri Command、Rust Actor、Store 数据结构或设备状态机；
- 改变危险操作的确认级别；
- 把“命令发送成功”提升为“设备配置成功”；
- 放开设计文档中已明确禁用或尚未验证的 KZ3 数据类型、生成器和运行时能力；
- 修改项目 YAML 语义、地址分配、硬件 Profile 或现场安全值；
- 在没有证据时自动推断硬件状态或现场验证结论。

允许的交互级调整仅包括：布局重排、控件外观统一、说明折叠、工具栏分组、局部面板展开/收起、滚动容器修复和不改变结果的状态反馈优化。

## 14. 验收标准

### 14.1 布局与密度

- 默认 1100×760 下，所有页面上下文标题、主操作和关键状态首屏可见；
- Modbus、KZ3 和串口终端的主要工具栏不出现无规则换行；
- KZ3 六步导航始终保持可操作高度，不被 Flex 压缩；
- 全局侧栏展开不超过 224px，折叠后不超过 52px；
- 常用表格至少比现状多显示 20% 的有效行数，且不牺牲可读性；
- 空状态不长期占据大块主工作区。

### 14.2 颜色与状态

- 所有交互色和状态色来自 Token；业务页面不再新增未经定义的硬编码状态色；
- 在线、离线、连接中、超时、失败和危险操作可在 2 秒内通过图标和文案区分；
- 红色只用于失败、异常和危险动作；离线使用中性色；
- 状态不依赖红绿颜色单独表达；
- 正文、次要文字、边框和焦点环通过对比度检查。

### 14.3 一致性

- 全局只有一套按钮、表格、面板、Toast、状态 Badge 和空状态规范；
- 相同操作在不同页面使用相同图标、文案和位置逻辑；
- 所有页面使用统一的页面上下文栏和间距节奏；
- 协议值、地址、SN、Hex 和日志统一使用等宽字体与等宽数字。

### 14.4 功能回归

- 页面路由、串口连接、设备查询、配置下发、导入导出、日志、图表和确认流程行为不变；
- 页面切换不重置连接、不丢失表单草稿、不改变正在运行任务；
- 850×600、1100×760、1440×900 以及 125% 系统缩放完成视觉回归；
- `pnpm build` 和 `pnpm lint` 通过；涉及交互结构调整的页面完成定向操作回归；
- 编译或模拟通过不得表述为实板、HIL 或现场验证通过。

## 15. 当前建议结论

本次优化不建议从单个页面“换颜色、加圆角”开始。最有效的实施顺序是：

1. 先统一 Token、密度和基础组件；
2. 再压缩全局标题栏、侧栏和页面上下文区；
3. 以串口终端、Modbus 和 KZ3 三个高密度页面验证体系；
4. 最后迁移其余页面并进行多窗口尺寸回归。

这样可以保持现有功能和安全语义不变，同时解决当前最影响工业调试效率的三个根因：**有效工作区不足、颜色语义混乱、页面组件缺乏一致性。**
