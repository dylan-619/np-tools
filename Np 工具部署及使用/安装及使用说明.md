# NP-Tools / OpenCode：Mac 开发环境使用说明

给接收方两样东西：**NP-Tools 的 DMG 安装包**，以及本配套目录。对方是开发工程师，按普通开发环境安装即可，无需另外部署技能。

## 目录结构

```text
Np 工具部署及使用/
├── scripts/
│   └── setup.sh
├── opencode.example.json
├── opencode.json             # 可预填 Key，或首次运行时从模板生成
├── NP-Tools工具介绍.html
└── 安装及使用说明.md
```

脚本集中放在 `scripts/`，配置和说明文件直接放在顶层。后续功能介绍也放在顶层即可。脚本从交付根目录读取配置；首次生成的 `.env` 和按需创建的 `.venv` 也位于根目录。

从 GitHub 获取本目录时，脚本会将 `opencode.example.json` 复制为 `opencode.json`，已有配置则保留。模板通过环境变量读取 Key，不包含个人密钥。

## 这些依赖分别做什么

| 组件 | 用途 |
| --- | --- |
| NP-Tools 安装包 | 桌面界面、案例、SDK 和工程技能；直接安装。 |
| OpenCode + DeepSeek | 提供 AI 对话服务，供 NP-Tools 通过本机 HTTP 连接。 |
| Python 3.9+、PyYAML | NP-Tools 用来读取 YAML 点表、生成和校验工程、导出文件。不是 OpenCode 的依赖。 |
| `cc` / Apple Command Line Tools | 编译并运行案例的 C 控制程序，供本机仿真使用。 |

目前 DMG 包含 Python 脚本，但没有内置 Python 解释器，所以完整工程案例仍需系统中有 `python3`、PyYAML 和 `cc`。Python 不要求固定为 3.9，更新版本也可。

装过 Xcode / Command Line Tools 的 Mac 通常能找到 Python，但不能假定所有 Mac 都预装可用的 Python；以 `python3 --version` 为准。有环境就直接使用，不用重复安装。

## 安装和启动

1. 打开 DMG，把 `NP-Tools.app` 拖到窗口内的“应用程序”图标，再退出已经打开的 NP-Tools。仅打开 DMG 不等于完成安装。
2. 在本配套目录打开终端，运行：

```sh
bash scripts/setup.sh
```

脚本只检查现有环境，按需执行 `npm install -g opencode-ai@1.19.2`，加载顶层的 DeepSeek 配置，然后启动 OpenCode 和 NP-Tools。缺少 Node.js、Python、PyYAML 或编译器时，会提示需要补什么，不会自动接管这些环境。

支持两种 Key 配置方式：

- **本次预填 Key 的交付方式**：`opencode.json` 已填写临时 Key，脚本直接使用，不再要求接收方输入，也不创建 `.env`。
- **环境变量模板方式**：`apiKey` 为 `{env:DEEPSEEK_API_KEY}` 时，优先使用已有环境变量，其次读取顶层 `.env`；都没有才提示输入并保存。之后运行相同命令即可，也可提前提供环境变量：

```sh
export DEEPSEEK_API_KEY="你的 DeepSeek API Key"
bash scripts/setup.sh
```

**保持终端开启，Ctrl+C 停止 OpenCode。** 请通过本脚本启动 NP-Tools，让应用继承终端中能用的 Python 环境。

## GitHub 包和本地构建放在哪里

- GitHub 下载的 DMG、本地构建的 DMG 使用相同安装方式。拖入系统“应用程序”后，实际路径为 `/Applications/NP-Tools.app`。
- 如果自行放入当前用户的“应用程序”，路径为 `~/Applications/NP-Tools.app`，脚本也会自动检查。
- 本地 `pnpm tauri:build:macos-local` 生成的 `.app` 通常在 `target/release/bundle/macos/NP-Tools.app`，构建不会自动复制到 `/Applications`。可以复制到应用程序目录，也可以用下文的 `NP_TOOLS_APP` 指定实际完整路径。
- 直接解压得到 `.app` 的，也按上面两种方式放置或指定路径。脚本不会从下载目录、挂载的 DMG 或多个构建目录中猜测版本。

脚本优先检查 `/Applications`，再检查 `~/Applications`，选择包含 AI 案例资源的应用；显式设置 `NP_TOOLS_APP` 时只使用指定路径。随后核对应用标识 `com.nptools.desktop`，从 `Info.plist` 读取真正的可执行文件名，并检查文件可执行性和 AI 案例资源。旧版本缺少 AI 资源时会明确报错，不会启动错误的包。

因此，交付前既要确认安装位置，也要确认发出的 DMG 包含本次 AI 辅助工作台。不能仅根据应用名称或版本号判断资源是否齐全。

历史发行版 [v1.0.8](https://github.com/dylan-619/np-tools/releases/tag/v1.0.8) 的应用归档未包含 AI 工程资源。本次请使用从 `show-ai-coding` 分支构建的 v1.0.9，或后续包含 AI 工作台的版本；安装后仍由脚本核对工程资源。

## 缺少依赖时

- Node.js/npm：按平常的 Node 开发环境方式安装。
- Python：已有 3.9 或更新版本就用现有版本。缺少时自行安装 Python 3。
- C 编译器：运行 `xcode-select --install`，完成 Apple 的安装提示。
- PyYAML：在本配套目录创建普通虚拟环境即可：

```sh
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install PyYAML==6.0.3
bash scripts/setup.sh
```

脚本会自动使用本目录已有的 `.venv`，后续不必每次手动激活。已经在其他 Python 环境装好 PyYAML 的，激活该环境后直接运行脚本即可。

## NP-Tools 里怎么连接和使用

进入“AI 辅助工作台”，选择案例并载入点表，在需求设计页的智能服务设置里填写：

- 地址：`http://127.0.0.1:4096`
- 模型：`deepseek/deepseek-flash`
- 默认没有设置服务密码，密码留空。

点击“连接本机服务”，发送页面里的完整需求示例，确认方案参数并生成工程，随后部署到本机仿真、生成工艺画面。应用会在工作副本中准备好 AI 角色，**不用复制 KZ3 的 `.opencode` 目录**。

端口被占用时，停止已有服务，或者换一个端口运行，并同步修改 NP-Tools 页面地址：

```sh
OPENCODE_PORT=4097 bash scripts/setup.sh
```

应用安装在其他目录时：

```sh
NP_TOOLS_APP="/实际安装位置/NP-Tools.app" bash scripts/setup.sh
```

DeepSeek 配置就在 `opencode.json`，默认 API 地址是 `https://api.deepseek.com/v1`。已经在配置里填写 Key 的，更换时直接编辑该文件并重启脚本；只有环境变量模板方式才通过 `.env` 或 `DEEPSEEK_API_KEY` 更换。配置中的固定 Key 不会被新输入的环境变量覆盖。

转交其他人时，发送本目录中的 `scripts/`、配置、本文档、工具介绍 HTML 和配套的 NP-Tools 安装包。本次按你的临时授权，可一并发送已填 Key 的 `opencode.json`，接收方无需再输入；如果让接收方使用自己的 Key，则只带 `opencode.example.json`，由脚本首次生成配置并询问 Key。无需附带本机 `.env` 或 `.venv`。

参考：[Tauri DMG 的拖拽安装方式](https://v2.tauri.app/distribute/dmg/)、[OpenCode 官方 npm 安装说明](https://opencode.ai/docs/)、[OpenCode 服务](https://opencode.ai/docs/server/)、[Python 在 macOS 上的安装说明](https://docs.python.org/3/using/mac.html)。
