# 清水箱补水与双泵供水

固定工艺模板 1.0.0。原有两设备顺序启停仍在 `../../case/`，新工程默认使用本案例。

用户在 NP-Tools 载入点表、沟通工艺、确认参数，工具复制本目录的 C 模板并生成点表、北向字段和工艺 HMI。AI 负责需求与配置，不重新实现状态机。

- 11DI：低/高液位、水源、需求、两泵运行/故障、阀开/关到位、运行许可。
- 4DO：两泵启动、电动阀开/关驱动。
- 低位补水、高位关阀；缺水停泵；主泵故障经输出全断、反馈停机和切换间隔后投入备用。
- 泵反馈检查、阀到位/行程超时、双向互斥和最终全断后 2 秒换向间隔。
- 独立设备故障复位；许可和质量恢复不自动投入。正常停止受控关阀；立即停止撤销全部输出。
- 参数范围、默认值与角色来源见 `../catalog.json`；输出状态、故障与北向契约见 `project_io.yaml`。

`../../host-runtime/water_runner.c` 为软件设备模型。它读取 C 输出，产生水位和设备触点，再输入真实 DataManager/LogicManager。前端只负责展示与下发操作。联调时钟按每次扫描10ms推进，操作系统暂停调度期间工艺时间不跳变；这不是硬实时或实板扫描周期保证。水箱百分比来自模型，不是 KZ3 模拟量采集，也不代表水力计算。

运行验证：在 NP-Tools 根目录执行 `pnpm test:engineering`。更新本模板后同步 `case.json` 文件散列。生产实板部署前仍需单独核验接线、触点极性、行程参数及电气保护。
