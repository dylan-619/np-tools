# NP-Tools 工程演示资源

全部资源位于本项目内。支持 macOS 本机仿真，提供顺序启停、清水供水泵站和三泵集水井液位控制三个固定案例。仿真不调用串口、烧录器或实板网络；实板准备页可转入工具现有的烧录流程，需另行提供匹配的 ARM 固件。

- `case/`：固定3DI/2DO点表、C模板、真实管理器测试、案例哈希。
- `cases/`：清水供水泵站与三泵集水井案例，包含点表、C模板、设备模型、控制测试和案例哈希。
- `sdk/`：KZ3 SDK与工程师技能快照。原始固件工程不被修改。
- `host-runtime/`：有界JSONL解析和C扫描适配。
- `engineering.py`：校验、合并、生成、严格检查、主机编译、ZIP导出。
- `sdk-manifest.json`：来源提交与快照哈希。只有明确限定为本案例的host范围才适用无故障复位的检查例外，硬件工程门禁保持。

展前需要可从应用环境启动的 `python3`、`cc` 与 `PyYAML==6.0.3`。应用会实际编译运行小程序进行预检，不会现场联网安装依赖。OpenCode是唯一需要另行启动的服务，NP-Tools默认连接 `http://127.0.0.1:4096`，在页面选择服务真实发现的模型。

维护案例时同时更新 `case.json` 对应文件的SHA-256，再执行 `pnpm test:engineering` 和桌面排练。调整SDK要更新快照清单并复核host例外没有扩大。不能只修改哈希来绕过失败检查。

点表原文保持不变。生成点表将输入别名规范化为固定案例别名，映射写入 `point-role-map.json`；原始描述、未知元数据保留。涉及其他工艺、额外功能或不兼容北向字段时明确拒绝，不静默覆盖。

临时构建在工作副本的 `.building/` 中进行，成功后发布独立版本。取消/失败不替换上一成功交付；下次构建清理未发布候选。主机日志每文件最多10MiB、最多20份。导出时隐去工作目录，并重新计算导出文件清单哈希。

主机运行期间参数仅保存在当前进程内。重置/重新部署后参数恢复生成默认值，需要新的启动动作。顺序启停案例的DI与许可初始关闭；泵站与三泵案例按各自设备模型初始化输入，自动控制初始未投入。DO表示输出命令，模型运行反馈表示软件设备模型的响应，均不能作为实板运行证据。
