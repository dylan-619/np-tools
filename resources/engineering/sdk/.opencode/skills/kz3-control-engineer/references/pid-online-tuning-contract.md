# PID 上位机整定契约

仅在 KZ3 实际拥有 PID 回路时使用本契约。厂家成套柜自行闭环、KZ3 只给目标值或启停时，不为其
虚构本机 KP/KI。每个 KZ3 PID 回路都必须把 KP、KI 建模为应用参数并向上位机开放调整；不能只在
顶层 `pids` 中写死增益，也不能把可写字段绑定到不会被 `PID_STEP` 使用的影子变量。

## 配置和北向

每个回路分别声明两个 `float` parameter：

- KP：有限、非负；闭环投用时通常要求 `> 0`；
- KI：有限、非负；允许 `0` 表示 P 控制，但字段仍保留；
- `min/max`、默认值和单位来自回路工程单位及整定证据，不跨项目复制；没有整定值时用 `0.0` 占位，
  PID 保持禁用或未投用；
- 现场整定参数默认 `persistent: true`，使经确认的值掉电保存。项目明确要求易失时可例外，但必须写明
  上电来源和禁止误投规则；HMI 不得周期重复写入，避免无意义的持久化磨损；
- 单回路可使用 `parameter.pid_kp/pid_ki` 与 `PID_KP/PID_KI`；多回路必须增加稳定对象/回路前缀，
  例如 `P1_PID_KP/P1_PID_KI`，避免不同回路共用参数或短名；
- 北向字段必须是 `float + read_write`，说明中写清回路、比例/积分增益及单位。README、YAML、生成点表
  和交付点表使用同一名称、bind、类型、权限和地址。

`pids[].kp/ki` 是生成配置基线，不是上位机写入口。项目调用 PID 时必须：

```c
input.use_runtime_gains = true;
input.runtime_kp = context->param.<loop_kp>;
input.runtime_ki = context->param.<loop_ki>;
```

当前运行时只支持在线覆盖 KP、KI。KD、方向、采样周期、微分滤波和输出限幅仍来自冻结的 PID 配置；
不得生成一个可写 `PID_KD` 却继续使用静态 `pids[].kd`。若以后平台增加 runtime KD，须先更新 API、
生成契约和测试，再开放对应字段。

## 在线修改安全行为

上位机写 KP/KI 不得在正在闭环的扫描中直接热切换。项目对每回路保存增益签名或等价变更检测：

1. 任一增益改变后，立即撤销该回路自动闭环许可，执行 `PID_RESET`，输出进入冻结的安全值、手动值或
   tracking 值，并置“需重新投入”；不得由故障复位代替该动作；
2. 完整校验 KP/KI 均为有限数且位于各自范围内。两次独立写入之间的中间组合不得自动运行；
3. 操作员完成整定后重新选择/投入自动，PID 按当前测量建立新基线；不恢复旧积分或旧自动请求；
4. 多回路只退出被修改的回路；系统级工艺确有共同 owner 时按冻结关系扩大影响，不默认全组退出；
5. 参数写入失败、持久化故障、坏质量、STOP 或许可丢失继续服从原安全路径，不能因在线整定绕过。

若项目具备原子参数组提交，可以用一次提交替代两次写入的中间窗口，但仍执行退出闭环和重新投入。
当前项目没有该能力时，不虚构 revision/CAS 或“同时写入”保证。

## 需求、生成和验证

需求阶段逐回路冻结：PID owner、PV/SP/AO、KP/KI 参数和单位、范围/默认/持久化、北向短名、增益改变
后的安全输出及重新投入方式。没有整定值不阻止生成受禁用的调试配置，但阻止闭环投用。

生成检查必须证明：

- 每个 KZ3 PID 回路恰有一组独立 KP/KI parameter 和北向 `read_write` 字段；
- `LogicPidInput` 实际启用 runtime gains，并从对应 parameter 取值；
- 非有限、越界、KP/KI 单项修改、两项依次修改及其他回路不受影响都有实际扫描断言；
- 增益变化当拍不继续闭环，不误启，重新投入才恢复；掉电恢复值和 PID 默认禁用策略一致；
- HIL 记录参数组、固件身份、趋势曲线、输出限幅、超调/稳态误差和回退值。主机测试不能证明整定稳定。

必需总场景 ID 为 `PID_TUNING`；复杂项目可再拆分 `PID_GAIN_INTERFACE`、`PID_GAIN_VALIDATION`、
`PID_GAIN_CHANGE_REARM`、`PID_GAIN_PERSISTENCE`。原有 `PID_OWNER`、`PID_TRANSFER`、坏质量、限幅及手自动场景
仍必须保留。
