# 现有点表与综合需求

## 接收方式

直接接收 YAML/JSON、CSV/Excel、Markdown 点表和需求文本。用环境已有的解析能力读取；二进制表格
不能按文本猜读。工具缺失时准确指出未读取的文件，可继续其他材料。无需用户转换成新格式。
先辨别：空白样模、角色已填但物理绑定未填、物理绑定齐全、已有投产配置。保留现有字段与发布接口。
“样模中的默认值”“示例端子”“备用”不等于现场证据。需求中的设备名称可映射原点名，不擅自重命名。

## 两次校核

第一次检查需求能否由现有能力实现；第二次在生成前重新核对绑定、类型、质量、安全值与源文件漂移。
逻辑角色齐全但端子未填，结论应是“能力匹配，物理绑定待补”，不能简单判整张点表不合格。

逐行保存：原文件/行或字段、原描述、设备、业务角色、I/O 类型、方向、数据类型、单位/量程、物理来源、
归一化/有效状态、质量来源、输出安全值、是否接线/备用、核查结论。未提供的内容写未知，不填推测值。
每条需求记录所需能力、候选点、选择依据、缺点和影响；一个点服务多个只读需求合法，一个物理输出
有多个最终写入者不合法。同一模块的地址必须带总线/设备/地址空间，不能把不同从站的相同寄存器判为重复。

校核重点：
- 点名/描述与类型冲突；输入输出方向；运行反馈与 DO 请求/回读的区别；物理绑定重复与 AO/DO 能力差异。
- 压力、液位、频率、电流各自的工程量、量程和质量。AO 为频率还是压力目标必须有证据。
- 所需反馈缺失时列出受影响的监督和能力；不得造 DI、把常量 true 当有效反馈、或悄悄降级控制。
- 接触器切换拓扑、独立变频拓扑、成套柜 PID 各自能力不同；未提供切换接触器不生成跨泵切换。
- 板载点与扩展 Profile 分开校核；软件 DO=false 不等于物理设备已停止。
- 未使用/备用点保留原件但不自动加入业务和 HMI。既有发布地址不得重排。

可将已读事实转为 [点位审计格式](point-audit-format.md)，运行
`python3 <skill>/scripts/audit_points.py <归一化JSON>` 做结构检查；此格式由智能体填写，不让工程师重抄。
工具不理解工艺或原始 Excel，不代替语义核查；工具 OK 不能直接冻结需求。

## 工艺设计与方案选择

默认用户是熟悉实施现场、未必熟悉 PLC 逻辑设计的人员。输入可以只有“恒压供水”“自动轮换”或
几项关键参数。无需等用户明确说“从零设计”，就应在其目标范围内主动完成工艺控制方案建议。
已有专业方案则保留明确约束、补全缺口；发现矛盾、不具备实施条件或明显不合理的要求，应说明具体
后果并给出修订建议，不机械照写，也不静默改成另一种工艺。

### 先形成方案，再集中沟通

1. 从原材料提取工艺目标、设备能力、测量与执行接口、既定约束；将不确定解释写为设计前提。
   关键目标尚不明确时给出可能解释和判别依据，不凭单个点名决定补水/排水或 PID 控制者。
2. 对照匹配案例检查遗漏：设备职责、投入/退出条件、手自动、顺序/并行、调节/分级、轮换与容量、
   防频繁启停、反馈监督、许可/保护、故障影响、复位及重新运行。只补与当前目标有关的内容。
3. 主动设计正常、异常、恢复三条路径，形成设备关系和动作顺序草案。每个等待有完成判据与超时，
   每个输出有控制者与禁止条件，每个恢复有再启动条件。状态机、实例分配和参数关系由智能体完成。
4. 先给一个有依据的推荐方案。有实际取舍时再给一至两个可行备选，不为凑数量制造选择。
   说明所需点位/设备、运行效果、连续运行能力、调整或维护要求，以及未满足的实施前提。
   需要新增硬件的方案单独标明，不能混入“现有点位可实现”的方案；不捏造节能、精度或费用数字。
5. 将选择转换为现场语言，例如“主调泵故障后停止自动供水，还是允许备用泵按压力上下限间歇供水”。
   同时说明后者不保证原有恒压效果及所需条件，不让用户自行选择状态枚举、锁存算法或 PID 内部实现。
6. 采纳后整合为一套一致的需求与控制方案，更新点位、参数、状态转移、异常恢复和验收场景。
   未采纳的重大分支保持候选；已有明确决定不重问，常规软件细化按既定共性规则落实。

方案说明至少包含：要实现的现场效果、正常运行过程、主要异常与恢复、采用理由、现有能力与缺口、
需要用户选择的事项。简单任务用一段话即可；复杂方案用对照表。第一轮应有可审阅的设计草案，
不能只有“请补充启停条件/联锁/故障策略”的问题清单。

### 三种信息分开记录

| 信息 | 处理方式 |
| --- | --- |
| 现场事实与已确认要求 | 标注来源；有矛盾时核实，不用案例覆盖或把原文自动视为合理 |
| 控制设计与建议 | 智能体负责提出完整做法、依据及影响；常规结构沿用共性规则，重要工艺取舍记录采纳 |
| 待核实的物理条件与参数 | 列明获取方法和受影响功能；可继续设计，不猜接线、量程、安全值、PID 整定或设备能力 |

设计能力覆盖现有设备与目标范围内的运行组织和工艺控制，不等于擅自完成泵型选型、管路计算、
电气保护设计或现场安全论证。需求确实依赖这些外部结论时，说明具体所需资料并继续不依赖它的部分。

### 简略供水需求的处理示例

用户只说“压力不足自动加泵”，点表显示一台可调速泵和一台仅启停泵。先核实调速接口及闭环控制者，
给出“变频泵主调、工频泵辅助”的候选方案，补出压力调节、加减泵滞回与连续确认、启停反馈、容量、
手自动隔离、故障退出与恢复的设计。不能只问“加泵条件是什么”，也不能把工频泵纳入变频轮换池。
若主调泵故障时的供水策略未定，比较停止相关自动与有条件的工频降级，并说明断供/压力波动的取舍。
没有频率反馈时，不能用频率给定当实际满频；可提出另行确认的压力判据方案或补充反馈的方案。
现场压力限值、设备最小启停时间与 PID 增益依据资料/调试确认；候选方案不是已批准的投运程序。

## 有限沟通与可恢复记录

先给“当前可实现/缺少/冲突”的结论，再按控制者与拓扑、运行与切换、异常与恢复分组给推荐答案。
示例：现有 P1 有调速口、P2 只有启停口，建议 P1 固定变频主调、P2 工频辅助；P1 故障时停自动供水，
还是按另定压力上下限运行 P2？这是工艺选择，不可由编号推断。

事实优先级：本项目有效修订和明确用户决定 → 当前硬件/接口证据 → 已接受的软件共性规则 → 参考案例。
发生相互冲突时展示具体条款与点，不按“后读到的文件”覆盖。原文仍保留，以新决策明确取代范围。
每次答复更新需求版本、已确认项、未决项、下一步；新输入使已有绑定/拓扑/安全策略失效时撤回相关冻结，
其他已确认项不重问。不将用户未回答、超时、模板默认或 AI 自审写成用户确认。

工程细化至少包括逐设备职责、手自动、启停/切换条件、互锁、参数、时序、异常/恢复、HMI 与验证。
参数记录单位、范围、默认依据、关系约束、生效时机和持久化；PID 增益/方向、现场阈值和安全值不能猜。
