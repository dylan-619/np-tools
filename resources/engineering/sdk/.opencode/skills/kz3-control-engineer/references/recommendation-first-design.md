# 少量确认的需求补全协议

先按 [点位表到控制代码](table-to-control.md) 的默认继承与加载策略执行。
本文的建议卡/确认仅用于新增实质工艺分歧；已经确定的共性不再请用户采纳。
首轮先完成控制模型，落盘/冻结才读取对应契约与门禁，不递归加载全部参考资料。

目标：收到点表与简述后，首轮就交付可以审阅的控制方案与需求草案，而非问题清单。用户不必具备
PLC 设计经验；智能体负责主动设计、缺陷分析与工程细化，用户选择涉及运行效果的实质取舍。
先按 [工艺设计与方案选择](engineer-intake.md#工艺设计与方案选择) 给出推荐和必要备选。
以下是工程工作方法，不是工业标准规定的工艺算法。

## 先建立控制模型，再决定问什么

在内部用一张控制关系表整理：`对象 → 测量/质量 → 工艺需求 → 许可/保护 → 调度 → 执行输出 → 真实反馈`。
逐项注明设备能力、控制者、输入来源、并联/互斥、共享资源及影响范围。只读取所需案例，不要求用户填表。

1. 按柜体/模块/通道还原点表；保留原条款、使用/备用数量、当前有效版本。迁入本柜 AI 的测量不是外部写入。
2. 从原文识别抽排/补水、开环/闭环、独立/联动、固定/可互换设备；点位只能支持能力判断，不能证明接线。
3. 对照原文检查四种冲突：控制者（谁做 PID）、排序（最后启动 vs 最长时间先停）、数量（总设备 vs 同时运行）、
   接口（频率设定 vs 工艺目标）。事实不足时给首选修订，不能静默选一个解释。
4. 命中经典案例后主动完成正常、异常、恢复三条路径。每个动作写清前态、条件及质量、比较符、连续时间、
   取消条件、目标状态、输出、反馈完成判据、超时结果和再启动条件；不要把这些工程细节抛回用户。
5. 做一次“反向走查”：从每个 DO/AO 找唯一控制者，从每个启动找许可，从每个等待找超时，从每个恢复找
   再启动条件，从每个需求条款找正常和禁止动作测试。无法唯一解释的行为不能写成已完备。

多台设备只写“手动”属于可直接推荐的常规细化：默认每台设备独立启停，手动请求与自动请求分开，
自动顺控、轮换、加减机、PID 和工艺联停不进入手动分支。将这一组已定结果直接列入沿用规则，
不逐台追问。只有 PLC 初步需求明文手动联动、共享执行器互斥或客观共用安全保护时，才增加跨设备动作及其恢复。

多设备存在自动业务时，同一建议卡还须写明逐台自动选择；自动联动/轮换/加减机只选已开自动且可用的
设备。手动运行占用真实容量，但自动逻辑不能启停它。候选不足、下游未选自动和逐台退出/重入自动的
首选处理先由智能体提出，再让用户整组确认；全局自动使能不能替代逐台选择。
故障复位也按设备归属给出整组建议：复位一台只清该台可复位软件故障，另一台故障/总故障保持；
系统级故障另定系统范围，不能用一个全局复位替代所有设备。用户只确认业务结果，不逐路设计锁存。

## 三类待办，不混成一批问题

| 类别 | 智能体的动作 | 用户需要做什么 |
| --- | --- | --- |
| 软件细化 | 沿用已有明确授权/规则，给出停止优先、单一控制者、拓扑驱动、质量和定时建议；记录依据 | 未授权的建议可整包采纳，不逐项问类型、算法、状态字段 |
| 工艺裁决 | 明文冲突、降级能力、异常停机与溢流/断供取舍、容量上限等形成稳定决策卡 | 通常集中 1～3 组选择；每项实质变化需明示，不能把无关决定藏进一张卡 |
| 调试与物理证据 | 建立参数/证据表，说明值从何处取得、未就绪禁止哪些动作、谁填写及如何验收 | 现场工程师补手册/接线/实测，不要求用户猜工程数字 |

一次展示“原规则保持哪些 + 推荐补哪些 + 只需选择哪些”。已有明文、已采纳卡和同版证据直接复用；
“按推荐做”只接受已展示范围；未答项保留，不反复换措辞询问。若有超过三组独立重大冲突，如实说明，
按依赖先问关键组；少量沟通是目标，不是隐藏风险的硬配额。

未知工程量上下限、液位限值允许 float 0.0 调试占位；需求明确占位识别、禁用路径、提示及解除验证后，
可以冻结此软件行为并继续生成。不得把物理安全态、PID 控制归属、联锁后果或必需安全时限伪装成调试占位。
默认建议时间仍以共性目录为准；不能为了少提问猜 PID 增益、设备最小启停时间或故障停机能力。

## 完备的交付，而非完备的口头承诺

正文必须包含：原要求保留与差异、点位表、逐级/逐步转移表、模式与优先级、故障影响/恢复表、参数与
生效门禁、最小北向语义/短名/bind/权限表、逐条验收场景和待办责任。DRAFT 允许候选分支，但要明确
推荐哪条；FROZEN 必须只剩唯一已采纳行为，不能留“保持或停止”“按需替补”等实现者二次猜测。

涉及多设备手动、分级、异构设备池或闭环时，在 `engineering_review.control_features` 声明命中特征，并按
[需求契约](requirements-contract.md) 添加对应场景。不适用的功能不声明；特征列表不是安全证明。

## 五泵输入的回归判据（不是固定五泵方案）

对“1 台有 AI 频率反馈/AO 给定、4 台仅 DO、液位分段、均衡与故障替补”的输入，首轮应：

- 识别异构能力，匹配 [变频主调与工频辅调](water-process-boundaries/09_mixed_speed_group.md)；
- 点出原文 PID 控制者与点表的矛盾，不直接启动第二套闭环；
- 明确总台数与同时运行上限不同，备用可以轮换但须符合原文，不默造第五级；
- 给逐级下降与故障降级的首选建议，保留“最后启动/最长时先停”等冲突的裁决记录；
- 把 30 秒工艺确认与 PID 周期、通信时效、反馈时限分开；未知量程以受禁用门禁保护的占位处理；
- 给手动/就地/启动中/未知运行占容量、唯一变频泵不可等价替补、本机复位不改共享工艺步骤的反例测试。

再用“全工频排水”“厂家成套柜内部 PID”“明确禁止降级”“仅采集”作反例复核：不得无条件套用变频
主泵、KZ3 PID、工频降级或任何 DO 控制。参考库支持主动设计和边界补全，不替代现场证据，
也不能未经采纳更改已明确的工艺要求。
