# STM32-Logic 自动执行策略

## 先识别用户要智能体做到哪一步

按用户原始请求确定执行模式，后续阶段不反复索要相同授权。

判定的是动词的对象与上下文，而不是关键词：“完善技能”“做需求分析”“检查案例”不授权创建实际
控制项目；“继续”只延续当前项目和既有范围。范围不明时先做需求草案，不能因出现“做/完成”就生成源文件。

| 模式 | 常见表达 | 自动执行范围 |
| --- | --- | --- |
| `AUTO_PROJECT` | 做一个、实现、生成代码、创建项目、完成、跑通、自动执行，或继续已授权的完整交付 | 需求补齐 → 完整配置与项目源 → 登记但不激活 → 安全/稳定性验证 → 自动修复 → HIL 计划与交付 |
| `REQUIREMENTS_ONLY` | 只整理需求、先讨论、仅检查遗漏/补全边界，或单独调用需求技能 | 原方案保留 → 内置案例边界匹配 → 需求文档 → 未决项/冻结摘要 |
| `VERIFY_ONLY` | 验证这个项目、检查为什么失败 | 只读检查 → 隔离生成/编译/测试 → 诊断；未获修复授权时不改源文件 |
| `ACTIVATE_OR_BUILD` | 激活这个项目、切换活动项目、构建固件 | 只执行用户明确提到的激活或构建动作，并遵守仓库工具链门禁 |

`stm32-logic` primary agent 是完整交付的单一入口。先读取 [端到端交付契约](end-to-end-delivery.md)。
不能仅因最新消息提供点表或确认边界就降级为 `REQUIREMENTS_ONLY`；已有完整交付授权持续有效。
首次意图确实不明时先交付需求草案并说明可继续的交付范围，不自行操作硬件。需求模式可脱离工程执行，
但“可独立整理需求”不是完整任务的默认终点。

## AUTO_PROJECT 连续执行

1. 建立轻量计划，读取规则、点位文件、相近案例和工作树状态。目标目录已有需求 README 时，把它作为
   可恢复的阶段记录，先读取已确认事实、未决项和最近验证结果，不从头重复提问。
2. 用白话复述目标，解析点位描述，立即把当前理解写入需求草案；同时继续所有不依赖用户回答的工作。
3. 只把会改变控制结果、安全、硬件绑定或协议兼容的缺口视为阻塞。将相关问题合并成一次简短询问，
   不要求用户理解 schema、parameter、command、quality 等内部术语。
4. 用户答复解决阻塞后，原始 `AUTO_PROJECT` 授权继续有效。更新需求状态和证据，直接生成正式项目源；
   不再要求回复“确认生成”。
5. 登记新项目但保持当前 `active_project`，在临时目录生成点表、严格编译并运行项目测试。
6. 本次代码或配置导致的失败自动修复并重试。同一根因最多自动修复两轮；若仍失败、冻结需求互相矛盾
   或缺少外部硬件事实，停止自动循环并给出精确阻塞证据。
7. 自动完成完整配置说明、安全/稳定性报告及可执行 HIL 计划，不把调试材料留给用户另行索要。
8. 获得硬件动作授权且测试条件具备时，按 HIL 计划实测并回填证据，失败后在授权内修复和回归；条件
   缺失时交付已完成的软件及精确待实板项，不能把 host-only 说成硬件可靠性验收通过。

每次取得用户答复、冻结需求或完成验证后，都同步更新项目 README 的状态、证据和剩余事项。新 OpenCode
会话收到“继续这个项目”时，应从 README 与现有项目源恢复进度；只有记录与当前点位文件冲突时才重新
确认相关部分。

阶段名称只是智能体内部控制，不是用户要逐项操作的菜单。除非用户主动要求查看过程，不输出冗长阶段
报告；使用简短过程消息告知正在解析、生成或验证即可。

## 可以自动采用和不能自动采用的内容

可以从仓库确定且不改变外部契约的机械细节自动处理，例如目录结构、schema 版本、代码风格、测试框架、
临时验证目录和保持现有 `active_project`。

以下内容不能因“自动完成”而猜测：

- 端子和设备绑定、有效电平、模拟量单位/量程、输出安全值；
- 急停和硬保护边界、两输出能否重叠、故障后切备用泵还是整组停机；
- 通信恢复、重新上电后是否允许设备自动启动；
- 已发布北向地址的删除、重排、复用或其他破坏兼容性的变更；
- PID 方向、限幅、采样周期和整定来源。

缺少设计必需事实时保留 DRAFT，提出最少问题；不要用案例值代替现场证据。已冻结占位禁用行为的调试
参数，以及纯 HIL/产品放行待办，按 [完整性门禁](completeness-gate.md) 分层，不一律阻止软件交付。

## 授权边界

- `AUTO_PROJECT` 自动写普通项目 README/YAML/C/测试并做隔离 host-only 验证；
- 新项目可自动登记，但默认不改变 `active_project`；
- 只有原始请求或后续回复明确要求“激活/切换项目”时才物化活动副本；
- ARM Debug/Release 构建只有明确要求时执行，并且必须找到批准工具链；
- 烧录、在线控制、现场命令和真实负载动作必须获得针对该动作的明确授权；
- 不创建 commit、不推送、不创建 PR，除非用户明确要求。
