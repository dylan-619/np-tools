# PLC 工程建议与经典场景目录

本文件把常见 PLC 工艺经验转换为 KZ3 需求阶段可直接采用的建议。它不是现场安全设计，也不提供端子、
极性、量程、阈值、时序或 PID 整定值。智能体应先形成建议，再让用户确认业务结果；不要把状态机设计
问题原样抛给不熟悉 PLC 的用户。PLC 已有方案时，本目录仅补其未写明的边界，明文要求优先保留。
水处理、供水、冷热水按 [PLC 边界匹配](plc-boundary-matching.md) 路由到技能内置的 W01–W08 案例。

## 建议优先协议

对每个不完整需求，按以下顺序处理：

1. 从白话、点位和现有项目中识别主对象、工艺目标、危险动作和已有反馈；
2. 匹配下表一个主场景，可组合一个或多个辅助场景；
3. 已明确内容直接保留，仅为缺口形成建议卡：`原文依据 / 待补边界 / 建议及理由 / 替代影响 / 待补证据`；
4. 对软件结构、命令冲突、复位、不误启、滞回、切换空窗、反馈超时等常规工程决策，主动给出首选方案；
5. 缺失的物理证据和未采纳的工艺决策均阻止冻结，但不阻止交付带推荐选项的完整草案；
6. 用户说“按标准做”或“你来决定”时，可采用下列软件工程建议并记录为“智能体建议、用户授权采用”；
   不得凭经验替用户确认未被当前板型/Profile 覆盖的端子、电平、安全值、硬保护能力或真实反馈含义；
   标准板已定义的软件 DI/DO 语义直接沿用，不重复询问。

按 [点位表到控制代码](table-to-control.md) 直接继承已定规则，停止优先、逐台手动/复位等不再询问。
新增实质工艺决策才提问，并附建议答案与影响；集中处理关键选择，不让用户设计状态机。
已定 A11/A12 等模块归属及串口默认不属于无证据缺口，只有当前资料冲突或超出约定才列阻塞。

## 决策分级

| 级别 | 处理方式 | 典型内容 |
| --- | --- | --- |
| `ADOPTABLE_RECOMMENDATION` | 给出首选方案；用户已授权“按标准”时可采用并记录依据 | 停止优先、输出单一 owner、命令 one-shot、状态只读、切换先停后启、软件锁存人工复位 |
| `CONFIRM_RECOMMENDATION` | 给出首选与影响，请用户确认业务结果，不要求其设计状态机 | 故障恢复后是否自动恢复自动运行、断线时保持还是撤销目标、批次计数停机后是否保留 |
| `EVIDENCE_BLOCKER` | 保持 DRAFT/安全禁用，说明需要哪份证据 | 未被当前板型/Profile 覆盖或与基线冲突的端子/极性、输出物理安全态、急停/热继硬接线、传感器量程、真实反馈、RTU Profile/站号、PID 参数 |

工艺安全值不能因为“经典案例通常如此”而自动填入。延时、阈值、最小启停时间和 PID 整定没有设备或
工艺证据时，给出所需选型依据和计算/试验方法。允许使用下文明确列出的“调试占位值”和“接口拓扑
建议值”，但必须标成未投用占位或待采纳建议，不能伪装成已验证现场参数。

## 点位拓扑驱动的接口默认建议

当 PLC 点表没有写出驱动方式、但点位组合满足下表且不存在手册/接线冲突时，智能体先生成一张是/否
建议卡，不再把“持续还是脉冲”作为开放题反复询问。用户采纳后才冻结；设备手册、接线图或既有兼容
契约始终优先。

| 点位拓扑 | 首选解释 | 默认控制规则 | 决策级别 |
| --- | --- | --- | --- |
| 电机/泵只有一个启停 DO | 保持型运行请求 | `true` 持续运行，`false` 停止；STOP/保护路径撤销请求 | `ADOPTABLE_RECOMMENDATION` |
| 电机/泵分别具有启动 DO、停止 DO | 双 DO 脉冲接口 | 启动、停止各输出单脉冲；停止优先；两路不得同拍导通；初始建议脉宽 `500 ms`，作为可调待采纳值 | `CONFIRM_RECOMMENDATION` |
| 阀门具有开 DO、关 DO、开到位 DI、关到位 DI | 双向行程保持接口 | 开/关输出在对应行程中持续保持，到达对应限位即撤销；两路互锁；双限位、超时或故障时撤销并锁存 | `ADOPTABLE_RECOMMENDATION` |

双 DO 脉冲的 `500 ms` 只用于形成完整草案和首选建议；接触器、变频器或设备手册给出脉宽时必须覆盖它。
阀门“持续保持”是指行程期间保持，不表示到位后继续长期励磁；若设备明确要求力矩关断、到位后保持
或三位控制，应按设备证据改写。

## 模拟量调试占位默认

- 点位已明确为 `4–20 mA` 时，电流缩放端点可先写 `4.0f` 和 `20.0f`；这只确认接口制式，不证明工程量范围。
- 未给出工程量上下限时，`eng_min`、`eng_max` 使用 `0.0f` 调试占位；液位高低限、报警限和控制阈值使用
  `float`，未给值时同样以 `0.0f` 占位并标记“调试前必填”。
- `eng_min == eng_max`、阈值顺序非法或占位未解除时，相关自动控制和报警计算必须安全禁用并给出配置
  错误；不得把 `0.0f` 当成真实液位或量程，更不得据此启动设备。
- 只要冻结需求明确“调试前必填”并把占位未解除设计成自动控制禁用，这些占位值可随需求进入
  `FROZEN` 并生成可运行代码；但不能声明量程/阈值已整定或 AI/HIL 已验证。现场工程师录入有效范围后，
  仍需覆盖端点、越界、断线和恢复测试。

## 工艺阈值连续确认默认

液位、压力、温度、流量等普通工艺值到达启泵、停泵、加泵、减泵或阀门切换阈值时，默认采用
`PROCESS_THRESHOLD_CONFIRM_30S`：条件必须连续成立 `30000 ms` 才改变工艺需求。需求阶段直接写入
`threshold_confirm_ms = 30000` 的可调建议，不先向用户开放提问；PLC 明确给出其他时间时以原要求为准。

- “到达”必须写明比较符和等号归属，例如启泵 `value >= start_level`、停泵 `value <= stop_level`；
- 确认期间只保持动作前的需求，不提前起停；条件退出、数值进入滞回区、质量非 GOOD、模式/owner 改变
  或相关参数变化（包括合法阈值、确认时间变更）/非法时，取消本次确认。再次满足时从 0 重新连续计时，不能累计零散满足时间；
- 到时条件统一为无符号差值 `>= 30000U`，并测试 `29999/30000/30001 ms`、扫描延迟和 tick 回绕；
- 每个独立阈值转换使用独立确认状态，不能用一个计时器同时确认不同级别或启停两个方向；
- 30 秒只用于普通工艺调节。急停、设备故障、许可丢失、坏质量安全收敛、干转/溢流等低低/高高保护
  不得等待该确认期；报警是否延时按冻结的报警需求另行定义。

多设备需求只写“手动”而未写手动联动时，C12 默认给出一张整组建议卡：“每台设备独立手动，手动与
自动请求隔离；除共同安全保护外，一台设备的手动操作不改变其他设备，是否采纳？”不逐台询问。
明文手动联动、共享执行器、电气互锁或安全联锁优先，并把跨设备影响逐项列出；自动联动不自动继承到手动。

多设备有自动业务时，同一建议卡默认补充逐台 `AUTO` 选择：自动轮换、加减机、替补和联动只选已开自动
且满足许可/质量/故障/能力要求的设备。手动运行设备占用真实容量但不受自动启停；候选不足或联动依赖
未开自动时提出“禁止越权动作、报告可用能力不足/联动受阻”的首选结果，再由用户整组确认具体降级。
依赖下游未选自动时，优先建议阻止上游自动启动；下游即便手动运行也不自动算作联动授权。
组级自动使能只可附加，不能作为唯一模式选择。逐台退出/重入自动的输出移交及防误启也随卡确认。
若自动按运行/停止时长循环或定时轮换，默认每台参与设备各开放一对可写时长，独立计时；初值可相同，
参数与 bind 仍逐台分开。先给 `*_RUN_M/*_STP_M` 分钟参数的整组建议，PLC 已给数值则沿用，未给则
标调试占位并禁止该设备自动周期；明文全组共用是需记录的例外，不直接覆盖 PLC 原始需求。

`Pxx/Txx` 是当前 skill 的模式和认证模板编号。没有认证模板命中的场景必须记录
`CUSTOM_REVIEW_REQUIRED`，但仍应给出完整建议、状态转移和测试方案，不能把“没有模板”变成让用户
自行设计控制逻辑。

## KZ3 硬接资源适配

标准板提供 12 路 DI、8 路 DO、4 路 AI 和 2 路 AO。当前板型配置及固件采样路径已定义：板载
DI1–DI12 低电平有效，进入逻辑块前已归一化，`GOOD + true` 表示该点业务状态成立；DO1–DO8 高有效，
`true` 为输出请求、`false` 为软件安全目标，默认按继电器式开关输出使用。同一标准板固件未改变时，
这些是可直接继承的软件接口事实，不把每个 DI 的极性或每个 DO 的软件安全目标反复列为用户确认项，
项目逻辑也不能再次反相。`board_io_hil: pending` 只表示端子真实电平、继电器触点、接触器/设备动作和
安全回路仍待实板/现场证明；不能据此否定既有固件接口或把这些验收项变成逐点需求问答。
A12/A13 等扩展模块按各自 Profile，不套用 A11 板载极性。

| 场景 | 典型预算 | 适配结论 |
| --- | --- | --- |
| 单电机/单泵 | 约 5DI + 1DO | 板载资源可规划；优先保留故障、运行反馈和急停/许可，不为省 DI 删除反馈 |
| 正反转/两位阀 | 约 6DI + 2DO | 板载资源可规划；软件互锁不能替代接触器电气互锁 |
| 两段输送 | 约 7DI + 3DO | 板载资源可规划；三段时重新核算反馈、堵料和报警点 |
| 双泵主备 | 约 8DI + 3DO | 板载资源可规划；若还需多液位开关或手自动选择，应先做完整 I/O 预算 |
| 三泵分级 | 约 1AI + 9DI + 3DO | 逻辑容量可规划；AI 电气准入和工程量缩放必须另有证据 |
| 六输出顺控 | 约 4DI + 6DO | 板载资源可规划；输出负载和互斥仍待实板/现场验证 |

I/O 超过预算时，先区分物理通道与重复逻辑别名；删除 HMI 字段不会释放物理通道。只能合并确属同一
信号的重复逻辑映射，不能为省点删除真实反馈或保护。物理通道仍不足时，提出经批准的 702/704/705
扩展方案；不能静默让两个业务角色共用一个物理点，也不能用输出回读冒充设备真实反馈。

## 通用首选项

在不与现场资料冲突时，建议卡优先采用：

- 安全与命令优先级：硬保护/急停 > 客观故障 > 停止 > 模式/许可 > 启动 > 正常调节；
- 同扫描启停冲突：停止胜出；同扫描双方向请求：两方向均不动作并给出冲突状态；
- 输出控制：一个最终 owner、每拍从安全目标开始计算、启动命令与真实反馈分离；
- 多设备手动：默认逐设备独立；手动/自动请求和状态分开，当前模式只选择对应请求域，自动调度不得污染
  手动。仅明文手动联动或已确认共用安全联锁允许跨设备影响；
- 多设备自动：每台受控设备独立选择自动，自动池只取已选且可用设备；手动运行计入真实容量但不受自动
  启停。候选不足、联动依赖缺席和逐台模式切换按确认策略处理，不以全局自动模式代替逐台选择；
- 故障复位：每台受控设备提供独立 `*_RST` one-shot，仅清本机软件故障，不掩盖现存客观故障，
  不清他机、复位本身不启动；系统级故障另设专属复位，不能用全局清除替代逐台控制；
- 切换：互斥组采用 break-before-make；允许并联的泵/风机组先按 PLC 拓扑核对重叠与容量，不套全关窗口；
- 质量：坏质量不解释为 0/OFF，不新增危险输出；是否立即停机或受控保持由工艺风险确认；
- HMI：command 用于一次动作，parameter 用于长期设定，state/runtime 只读；只发布用户需要的关键字段；
- 重启恢复：手动请求默认不自动恢复；自动过程是否按当前过程值恢复，给出“默认保持安全、重新使能”
  建议并让用户确认，不能偷偷改变连续工艺；
- 测试：正常路径之外，至少覆盖冲突、坏质量、反馈超时、复位不误启、STOP/FAULT_SAFE、时间边界，
  以及所有互斥切换的负向窗口。

## 面向用户的建议卡

```text
匹配场景：C04_DUTY_STANDBY（双泵主备）
适用前提：本例已经确认两泵互斥，不用于允许并联的泵组。
推荐方案：两泵按完整排水周期轮换；运行泵故障时先撤销旧泵并确认停稳，再启动备用泵；停止优先；
          复位清本机故障并恢复可用，默认等待新启动或重投。
推荐理由：避免固定首泵磨损、接触器重叠和故障复位误启，符合当前模板可验证的不变量。
可选替代：按确认运行时间轮换；仅在现场明确允许并行时才取消全关空窗。
请确认：是否接受“完整周期轮换 + 先停稳再替补 + 复位不误启”？
仍需证据：两泵真实运行反馈、故障输入语义、DO 物理安全态、是否允许并行。
```

用户已确认的工艺要求。
