# 控制逻辑安全与可靠性审查

编译和静态指标通过只证明部分结构性质。需求、代码、测试逐项对应后才能给出限定范围的行为结论。
使用 [点表工程规则](table-input-engineering.md) 的边界域建立审查表：规则/决策 ID、危险触发、期望输出、
禁止输出、实现位置、测试函数/断言、验证层级、结果与遗留项。空表、仅标签或“模板已通过”不能交付。

## 审查顺序

1. 对照 PLC 原始需求保留表与采纳的边界差异，从需求独立列出禁止动作和故障影响范围，再查看代码；
   检查是否误将案例建议覆盖原有同步/并联/手动独立等规则，不要只按已有代码反推预期。
2. 检查输入归属和质量，区分告警/控制阈值，量程缩放只做一次；排除 NaN/Inf、除零、整数溢出和越界索引。
3. 检查 owner 与优先级；手动仍通过项目确认的保护；停止与复位不得产生启动请求。持续自动需求下的
   恢复必须符合已冻结的重新使能条件，不得无意在下一拍重启，也不能用统一模板覆盖已确认恢复策略。
   多设备手动默认逐台独立：检查手动/自动使用不同请求状态，自动调度、轮换、顺控和联停没有进入手动
   分支；除明文手动联动或共用安全保护外，操作一台不得改变其他设备请求或输出。
   多设备自动时逐台核对自动选择及输出 owner；组级使能不能替代。自动候选不得包含手动设备，手动
   实际运行仍须占用容量/共用资源；候选不足和联动依赖未选自动时不得越权启停手动设备。逐台模式
   切换和恢复须防旧自动请求误启，不能顺带改变其他设备模式或请求。
4. 检查每个设备启动、运行、停止和不可用状态；失败有有限超时、有限重试、可诊断结果，未知结果不能
   自动重发启动；停止反馈不可信时不允许互斥设备启动。
   每台受控设备的总故障必须合并其全部可见故障分项（含硬接历史锁存），并作为只读 `*_F_L` 北向
   发布；逐个故障来源注入验证，复位后硬件故障仍在时总故障不能清除，其他设备不应被误置故障。
   远程许可 GOOD+false 只影响控制资格，不是设备故障来源；按设备归属契约核对总故障不含 !REM，
   许可移交不新报启停/行程超时或运行丢失，真实故障保留、坏质量另判；旧案例相反行为不得照搬。
5. 检查组级需求合成和物料流向：下游失效对上游的影响、清料开始依据、延时期间再启动、联动循环依赖。
6. 检查生命周期：`Logic_Init/Stop`、框架 STOP/RESET/FAULT_SAFE、首拍高电平、one-shot 消费、功能块实例
   复位；项目软件故障复位、平台复位、运行累计清零分开验证。逐设备复位按
   [恢复白名单](reset-recovery-contract.md) 核对：可清本机故障、恢复 READY、监督计时及重投许可，
   丢弃旧请求；不直接写物理输出，不改模式、参数、runtime、他机或共享工艺。健康运行复位幂等。
   多设备分别注入软件故障，单独复位某台后检查他机软件故障及总故障不变；双复位同拍各自生效，
   `SYS_RST` 若存在不得扇出。仍存在的硬件故障/坏质量不能被复位掩盖。
7. 检查参数在线更新、成组关系、单位转换和时间界限；在待确认/停止/运行/延停各阶段修改参数测试一次；
   数值变化不能因计时基线错误造成脉冲重复或越限输出。
   自动按时运行/停机或定时轮换时，逐台核对可写运行/停止时长、实际使用的 bind 和独立计时状态；
   同组数值相同也不能隐式共用参数。改单台时长不得影响其他设备，零值/非法值不能引发快速振荡；
   运行/停止起算与真实反馈、故障中断和保护停机的关系必须与冻结需求一致。
8. 检查南向离线、北向失联、保持存储故障的不同影响范围；监控仪表坏质量不应无依据联停无关设备；
   控制传感器坏质量也不能未经批准切为更危险的定时备用。
9. 有 external input 时按 [外部实时输入契约](external-input-contract.md) 检查 INIT 不授权、同值刷新、
   时效等号/超时、非法写入不污染旧样本、断流计数、恢复不清锁存/不误启，以及外部数据不冒充物理反馈。
10. 检查 HMI 显示可区分请求、输出目标和真实反馈，未知不能显示为已停止；新增名称/类型/单位/地址
   与当前发布基线比对，不能只对地址做兼容检查。

## 可执行测试最低要求

分级、异构池和 PID 组合先对照 [W09](water-process-boundaries/09_mixed_speed_group.md) 的反例，
并检查 `control_features` 没有漏报。逐级上升/下降与总停、混合模式容量、唯一变频泵故障和调节归属
分别有断言；通用 NORMAL_PATH 不能替代这些场景。旧文档或示例存在相反解释时，以冻结决策为准。

- 各设备在启动等待、运行、停止等待、延停阶段逐一注入故障/坏质量/许可丢失；检查本机和其他设备；
- 对 GOOD+REM=false 单测首拍、持续超过动作超时、未获许可命令、运行中转就地及恢复；无真实故障
  时总故障始终 false，未许可命令不排队重放，不新报被中止动作故障，不因该许可状态要求复位。
  再叠加硬接故障/既有软件故障及 REM 坏质量，证明不能借“未远程不报故障”掩盖真实异常。
- 同拍 start+stop、reset+start、故障+reset、模式切换+start；持续高输入、重复命令、恢复后首拍；
- 多设备逐一手动启停并保存所有设备请求/输出快照；同时让自动需求跨阈值、自动计时到期、候选重选和
  自动联动故障发生，断言手动目标设备之外均无变化。再测试模式切换首拍，防止旧自动请求或阶段进入手动；
- 多设备逐一开启/退出自动，测试自动池只选择已开自动且可用设备；混合模式下手动运行计入容量但自动
  不碰其输出；候选不足、备用替补、联动下游不在自动、单台模式切换/重入和其他设备不串扰均有断言；
- 定时自动组给两台以上设备设置不同运行/停止时长，验证各自到时前/到时/之后、改单台参数与另一台
  周期保持、参数非法禁用、故障/模式切换后重入；单机项目也验证运行/停止参数分别生效；
- 每个阈值/定时的前一拍、相等、后一拍；回绕、延迟扫描及跨越多个阶段；不得靠循环补跑而瞬间串步；
- 普通工艺阈值动作默认连续确认 `30000 ms`：覆盖 `29999/30000/30001 ms`、条件短暂退出后从 0 重计、
  坏质量/模式切换取消、合法阈值或确认时间改变也从 0 重计，以及确认期间禁止提前起停；急停、故障和保护停机不得被该确认期延迟；
- 连续多扫描断言禁止输出：旧反馈未停、死区未到、下游未许可、故障未解除、自动尚未重新使能；
- 多次完整周期测试请求/计时不残留；不同设备实例互不串扰；测量短暂恢复后再次失败重新确认；
- `PLC_TEST` 只是追溯标签。每个已声明场景必须有实际输入注入、真实扫描、状态/输出断言，审查记录指向
  具体测试函数。对关键不变量至少做一次隔离变异检验：例如去掉 stop 优先或反馈互锁后应有对应测试失败，
  或提供等价的针对性反例；不得在正式工作树保留人为错误。

正式生成用 `--strict-quality --require-engineering-review --require-execution-evidence`；需求草案用
`--requirements-only --require-engineering-review`，冻结追加 `--require-frozen`。自动门禁只校验工程边界
表、采纳记录和场景关系的结构，不判断工艺是否正确，人工语义审查仍必要。旧 v1 项目未带新工程表时
可以沿用旧命令作兼容检查，但不能宣称通过新边界审查。

## 结果与物理边界

完整项目必须读取 [端到端交付契约](end-to-end-delivery.md) 的稳定性验收表和 HIL 流程，使用
[交付与 HIL 记录模板](../assets/project-delivery-validation-template.md) 或等价已有文档记录。
检查最大扫描/端到端延迟、长序列逐拍不变量、通信负载与恢复、掉电保持及适用的调节稳定性。
数值门限需有依据；未确定或未实测项不能 PASS。HIL 计划必需，真实执行另需环境与动作授权。

分别报告：需求门禁、静态结构、主机行为、目标固件构建、HIL/现场。只有真实执行才写 PASS，其余写
NOT_RUN、FAIL 或 NOT_APPLICABLE（给理由）。单项主机通过不能消除未决物理风险；不得承诺绝对安全。

物理停机延迟包括采样/去抖或 RTU 轮询、扫描调度、输出传输和接触器/机械动作。`scan_period_ms=10`
不能推导 10 ms 内物理停机。项目给出允许反应时间及测量方案；HIL 记录极性、断线、粘连、看门狗/重启、
通信异常、掉电保持、最大负载与长时间重复循环。急停和人身保护依赖经验证的硬件/安全系统。

依据 IEC 61131-3 的语言/功能块工程概念与 PLCopen 软件构造/质量度量进行审查；KZ3 C 逻辑、脚本或内部
`certified` 模板标记均不等于 IEC 61131-2 产品试验、IEC 61508/62061 功能安全、SIL/PL 或 MISRA 合规。
