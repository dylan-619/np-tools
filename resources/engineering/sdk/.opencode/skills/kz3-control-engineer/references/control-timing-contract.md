# 控制计时与清除契约

适用于定时周期、阀门换向与顺控、反馈监督、联动延停。本文是这些时间规则的统一来源；案例只用于选择
变体，数值来源仍是本次需求、有效决策、已定共性默认或明确标注的调试建议。不是 PLC 标准规定的固定工艺时间。
未指定反馈时限时按 [单体反馈默认表](device-ownership-contract.md#未指定时的反馈时限默认值)：直接
继电器控制泵/机器启动 5 秒、停止 30 秒、运行反馈丢失 5 秒；阀开/关到位各 120 秒。已给值优先，
直接说明沿用，不重新确认；普通阈值和外部数据的 30 秒不变。

## 不混用时间与清除操作

需求中的“清除时间”先按上下文区分为故障复位、累计清零、计时取消或清料延停；不得当成同一命令。

| 时间/操作 | 起点与结束条件 | 取消/恢复与副作用 |
| --- | --- | --- |
| 周期运行时长 | 新启动从 GOOD 运行反馈首次确认起；已运行手动切自动从切入当拍起 → 到时撤运行请求 | 启动等待不算运行时长；反馈丢失与保护单独监督 |
| 周期停止时长 | GOOD 停止反馈首次确认 → 到时允许下一次启动 | 停止等待不算停止时长；未知停机不开始安全等待 |
| 启动/停止反馈超时 | 实际启/停动作首次发出 → GOOD 目标反馈 | 重复命令/扫描不刷新超时；启停分开，不能共用隐式计时 |
| 运行反馈丢失窗口 | 已确认运行、仍要求运行时首次观测 GOOD+false | 连续达到已冻结时限（继电器设备默认 5 秒）；GOOD+true 取消窗口；STOP 后转停机监督，坏质量单独处理 |
| 开/关阀行程超时 | 对应方向 DO 首次 true → GOOD 目标到位 | 到位撤方向输出；重新扫描保持 DO 不刷新；相反方向另起监督 |
| 阀门双向反转间隔 | 最终开、关输出首次同时断开 → 连续全断 `>=2000 ms` | 任一方向重新输出则本次全断结束；手动早到命令丢弃，自动到时复核原条件；不计入行程超时 |
| 排泥开放时长 | GOOD 开到位 → 到时发关阀请求 | 不含开行程，关行程另算；仅双到位无运行累计 |
| 启动到启动间隔 | 前一实际动作阀首次开 DO → 间隔满，且前阀 GOOD 关到位 | 不再从关位起重等；跳过未动作阀不重置前阀起点 |
| 关位到下一开阀间隔 | 前阀 GOOD 关到位 → 间隔满 | 仅用于原文明定“关到位后等待”；与上一行互为变体 |
| 整轮间隔/静置 | 本轮最后实际阀 GOOD 关到位（或明确的最后间隔结束）→ 满轮次时间 | 首轮是否先等待、末阀额外等待、跨轮取较晚许可或相加分别写明 |
| 清料/延停 | 冻结事件，首选全部相关上游 GOOD 停止 → 满延时停下游 | 新需求取消旧延停；安全异常按冻结处置，不无限等待上游停机 |
| 普通阈值确认 | 条件首次满足 → 连续 30 秒满足 | 退出、坏质量、owner/相关参数变化重计；保护停机不等待 |
| 外部数据有效窗口 | 本字段最近一次成功合法写入，包括同值写入 | 首包未到不可用；每路独立；默认 age≤30秒有效、>30秒失效，明确接口定义优先 |
| 本机故障复位 | one-shot，按本机根因和可清列表处理 | 按 reset-recovery-contract.md 白名单恢复本机 READY；不改模式、参数、累计或共享延停 |
| 累计运行时间清零 | runtime 本机 clear one-shot → 内部持久化事务完成 | 不改变启停/阀动作/故障；PND 仅内部，ACK 不等于完成 |

周期计时与声明式运行累计是两个用途：运行累计按 GOOD 真实 RUN，包括手动/就地运行；周期计时
只推进本机自动阶段。运行阶段期间短暂丢反馈是否暂停周期，要在选定变体写明，不偷偷拿累计替代计时。

## 阀门双向反转保护

后续需求或点位含独立开、关两个方向输出的阀门、闸门时，逐台直接沿用以下已定规则，包含手动、
自动顺控及退出自动后的受控反向；不因用户简短需求未重复写出而省略，也不重复索要采纳。
`2000 ms` 是用户确定的软件最小全断时间，不是 IEC 标准时间；现场证据要求更长时取更长值。
只有单 DO、模拟调节或采集阀位的设备先按实际接口判定适用性，不虚构第二方向或自动业务。

- **手动**：开阀过程中不得直接关阀，关阀过程中同样不得直接开阀。必须先单独执行本阀 STOP，
  等开、关输出均断开满 `2000 ms`，再重新发出反向 one-shot 命令。未停止或等待不足的反向命令
  当次无效并消费、清除对应待执行请求；等待到时且没有新命令时仍不得动作。不能先缓存反向目标
  再自动停止、倒计时执行，也不能用故障复位或模式切换代替独立 STOP。
- STOP 与方向命令同扫描时 STOP 优先，方向命令丢弃，不算“停止后重新发令”。非法反向后的
  原方向处置、冲突报警及必要复位按当前有效项目规则；被拒命令造成的撤输出不等于收到独立 STOP。
  新项目须有本阀独立停止命令；修改已发布项目时复用原入口并保留北向兼容。
- **自动**：原工艺需要换向时先撤当前方向，保持两路全断至少 `2000 ms`，期间任何方向不得输出；
  到时后重新核对当前模式、原顺控步骤、需求、许可、质量、限位与保护，仅在原控制条件仍允许时
  输出反向。自动可保留工艺目标，但不得把被拒的手动命令带入自动；STOP/故障/许可失效等按原策略
  即时中止或禁止动作，不等待这 2 秒。纯手动工程不为此新增自动流程。
- **计时与状态**：以最终输出首次形成双断的扫描为起点，不以收到命令、期望方向改变或前一拍时间
  代替。连续空扫描、重复 STOP、复位、模式切换和控制器停/启不刷新或清空已建立的起点与历史方向，
  不得提前宣称等待完成；任一方向再次输出后，下一次双断重新起算。逐阀独立保存到 `context->state`
  或声明式功能块，用无符号时间差处理回绕。不得用阻塞延时、共享计时器或“一次全断扫描”替代。
- **行程监督**：2 秒等待不计开、关到位超时；对应方向最终 DO 首次有效才开始该方向的行程监督，
  自动实际动作时间也从该时刻记录。等待不能被当成行程已启动或已完成，重复扫描不重置行程期限。
  同方向重新启动、无历史方向的冷启动首次动作沿用本项目启动规则，不凭本条额外增加反向等待。

需求正文逐阀记明开/关/停入口、手自动分支、全断起点与来源、拒令后处置及保护状态生命周期。
生成时在唯一最终输出 owner 统一仲裁，所有提前返回/保护/停止路径均纳入全断状态记录。
需求、测试和实现必须追溯以下反例，复用 `NEGATIVE_SWITCH_WINDOW`、`COMMAND_CONFLICT`、
`STOP_SAFE`、`TIME_BOUNDARY`、`TICK_WRAP` 场景；不以标签齐全代替真实扫描断言。

| 验收输入（开→关与关→开对称） | 必须观察的结果 |
| --- | --- |
| 动作中未先 STOP 直接反向，过 2 秒再重复反向 | 不输出反向；未收到独立 STOP 不得解除手动反向门禁 |
| 独立 STOP 后全断 1999 / 2000 / 2001 ms 分别新发命令 | 1999 ms 拒绝；达到 2000 ms 后，仅新命令且原许可满足才允许反向 |
| 早到命令或 STOP+反向同拍，之后只推进时间至超过 2 秒 | 双输出保持断开，证明命令未排队；随后新发合法命令才可动作 |
| 自动需要反向，全断 1999 ms / 满 2000 ms | 前者两路全断；后者复核当前原有条件后才可输出，不需人工再发自动命令 |
| 自动等待中需求/步骤改变、退出自动、STOP、故障或质量/许可失效 | 不盲目执行旧反向目标；按原工艺及恢复策略处理 |
| 重复 STOP、复位、模式/控制器停启、tick 回绕；任一方向重新输出 | 不绕过等待，连续全断起点不刷新；重新输出后下次全断重计 |
| 多阀交错操作，行程超时小于 2 秒的等价测试配置 | 各阀状态不串扰；等待不误报行程超时，实际方向输出后才监督 |

在目标 KZ3 仓库适配时，可按需查看 `application/valve_reverse_guard.h` 的最终输出门控和
`tests/valve_reverse_regression.h` 的逐阀双向拒令反例；独立包提供
[保护器源码快照](../assets/control-templates/valve_reverse_guard.h) 与
[集成参考](cases/reversing-valve.md)。这些是实现参考，不是物理反馈证明。
不得复制历史工程的端子、地址、故障定义或旧规则覆盖本条要求；仅诊断旧工程时报告差异，不自动改现场源。

主机检查只能证明两路最终软件输出请求的全断窗口，不能证明接触器释放、电机零速或跨 RTU 模块的
端子已经同时断电；实板/HIL 须量测真实双向输出断开间隔并核对硬件互锁、释放及停稳条件。

## 必须写实的周期策略

每个使用时间的业务，用正文的一行记录 `owner / 初值与单位范围 / 起点 / 到时等号 / 取消条件
/ 参数生效点 / 首轮 / 恢复`；共享同一个设定值不代表可以共享有状态计时实例。

- 独立运行/停止周期的默认首阶段为 FIRST_RUN：本机从手动切入自动，是新的本机周期使能；许可、
  保护及时间参数有效、且不存在尚未完成的停机监督时，已停止设备在投入扫描即建立本机自动启动请求，
  不先等待停止时长，也不额外等待普通过程阈值的 30 秒确认期。确认 GOOD 运行反馈后计满运行时长，再停机，
  确认 GOOD 停止后计满停止时长，再运行。需求直接写明此已定默认，不再次询问“先运行还是先停止”。
- 本机 GOOD 运行反馈已确认运行时，手动切自动不做额外启停处理：保持已有合法输出，不发启动或停止
  命令、不重发启动脉冲、不先断 DO、不重新进入启动等待；直接进入运行计时，从切入当拍开始计满设定
  运行时长，不计入此前手动已运行时间，不清累计运行时间或故障。内部自动请求按此次合法移交建立，
  不复制旧手动请求；正常许可与保护仍生效。启动尚未确认不能冒充已运行，模式变化也不能刷新原启动超时。
- FIRST_RUN 只决定独立周期的首阶段，不绕过 STOP、故障、质量、许可或参数校验。上电保留 AUTO=true、
  断流/故障恢复、复位或从 0 补齐参数都不是新的手动切自动，不因此自启；重新投入遵守本机恢复契约。
  原文或有效项目契约明确先停止时保留 FIRST_STOP 并说明差异；定时阀组整轮首选 FIRST_WAIT、液位/PID
  等按各自有效需求启动，不能把 FIRST_RUN 机械套成“所有自动一选中就启动”。
- 独立启停周期正常参数首选 PAIR_NEXT_CYCLE：一次捕获运行＋停止一对时长，本次完整周期结束才
  再捕获，不在运行结束时只替换停止时长。切换/故障中断旧周期，新投入从首阶段重建。
- 在线 0 首选立即禁用本机自动并要求重新投入；明确要求 0 也下个完整周期生效时可用
  ZERO_NEXT_CYCLE，必须提示“写 0 不是立即停机，请用 STP/退出 AUTO”。入场任一 0 均禁止自动。
  协议拒绝的非法值不能成为已生效参数；代码遇到越界/NaN 等仍要安全禁用，不冒充合法快照。
- 顺控时间首选 SESSION_SNAPSHOT：合法投入时捕获整组参数；HMI 调整需退出自动，重新投入才生效。
  底层协议若无此写入门禁，诚实说明权限限制，代码仍只用有效快照，不能声称任意协议都拒写。
- 周期或清料延时可按明确要求使用 LIVE_KEEP_ELAPSED：下拍采用新时长但不清已用时，缩短到已过时间
  就转阶段/停机；
  与 PAIR_NEXT_CYCLE / SESSION_SNAPSHOT 不能混写成统一“下阶段生效”。没有需求不增加四种可选 HMI 参数。
- 远程 GOOD+false 首选当拍禁止新启动且撤本机输出；明确允许正常值短失宽限时，仅既已合法运行者
  可限时保持，不允许新启动。宽限从首次 false 连续计，恢复取消；坏质量/硬故障/STOP 不享宽限。
  未远程或宽限到期都只是控制许可失效，不置设备故障或总故障、不锁存、不要求故障复位；动作监督
  按 [设备归属契约](device-ownership-contract.md) 移交，不能把撤远程输出后的就地运行报为停机失败。
  10秒、30秒等均为项目变体，不当成统一 PLC 标准。无上位机在线/租约输入时不能虚构掉线检测，
  默认已投入本地自动继续、本机保护有效，重连不重放旧命令。

## 边界与实现验收

- 用当前平台支持的无符号时间差，不用 `now >= start + duration`；乘法前校验单位换算和上限。
  默认秒/分钟上限使毫秒时长 `< 2^31`；明确要求完整 u32 分钟范围时采用已审查分段计数，不能直接乘毫秒。
- 长扫描间隔只执行有证据支持的当前合法转移，不补发已错过的启停/开关脉冲；每步需真实反馈才能推进。
- 反馈时限推荐包含等号：T 当拍有 GOOD 目标反馈可成功，T 当拍无反馈超时；首次收到反馈已晚于 T
  仍报超时，不因先检测到位吞掉历史超时。旧代码只“先到位再超时”不等于证明这一边界，需单独测。
  若有效原契约另定时限/等号，保留并标明差异，不在技能维护任务中改现场项目。
- 每个监督测 T−1/T/T+1 的“有/无反馈”、跨过 T 后首次晚到、重复命令、质量失效、tick 回绕。
  持续 false 窗口从第一拍观察丢失起，不从上一拍 true 提前算；反复短失不能累加为连续丢失。
  缺省继电器设备分别测启动/丢失 `4999/5000/5001 ms`、停止 `29999/30000/30001 ms`；阀各方向
  测 `119999/120000/120001 ms`。使用明确覆盖值时改测其 T，不能将新默认强加给旧冻结项目。
- 复位快照：测试本机/他机请求、DO/AO、阶段、时间戳、重投许可、模式、参数和 runtime；按恢复白名单分别验证允许变化与必须保持；本机故障态、监督计时和重投许可可恢复，不能影响他机/共享状态。
- 独立周期在 CYCLE_TIME_BOUNDARY/模式移交测试中覆盖：停止设备合法切 AUTO 当拍发启动请求，
  启动等待不占运行时长；已运行设备切 AUTO 无额外启停/脉冲、不进入启动等待，切入当拍直接开始
  运行计时且累计不清零；运行到时后先确认停止，
  再计满停止时长才重启。另测两完整周期、两机不同值、参数缩短/增长、在线 0、未配置补齐、
  STOP/复位同拍、许可无效、故障恢复及上电保留选择不误启；有 FIRST_STOP 明文例外则测其等待行为。
  阀顺控覆盖开/关行程、到位后停留、阀间和跨轮的不同起点；延停覆盖新需求、异常与手动。

这些是语义与真实扫描测试要求，静态场景声明只能保证测试计划完整，不证明上述行为或 HIL 稳定性。
