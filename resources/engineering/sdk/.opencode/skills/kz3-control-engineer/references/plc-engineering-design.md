# PLC 工程设计与点位差异处理（PLC_ENGINEERING_V2）

技能修订：2026-10-16。新生成项目必须采用本设计流程和 `execution-evidence.md`；既有项目按原契约检查，不自动迁移。

## 先形成完整设计，再写控制代码

智能体负责把简短需求落实为完整工程设计，不要求用户自行设计状态机。保留用户明确的工艺目标，
为未写的软件边界提出可实施的首选方案。用户已授权完整设计实现时，常规软件细化直接记录并采用；
涉及新增工艺联锁、物理安全事实或改变既定工艺的分歧才集中裁决。不能用模板默认值替代现场事实。

每次输入先记录“本次生效需求”，按最新明确修订覆盖旧描述，保留被替代条款及原因。
例如用户已明确“液位差自动与定时自动互斥”，就设计逐台 MANUAL / LEVEL / TIMER 枚举选择，
不能继续生成液位差优先、OR 合成或失效自动切换至定时。未选模式不能推进需求或暗中启停设备。

原始输入另存不可混写的来源快照，设计表逐条标记保留/适配/待决及验收场景。删除原功能必须指向
用户具体修订原文，不能只在生成的 README 自称“新需求取消”。控制语境的“新需求到来/取消延停”
通常是新的运行或来料需求重新成立、取消正在进行的延停倒计时；不是用户删除延停功能。
同样，“停止计时”区分暂停和清零，“恢复”区分信号恢复、设备可用和自动启动。先用条件→动作→
恢复的完整句确认上下文；无法确定且会改变工艺时才提出最小裁决，不能靠缩短实现选择解释。

在 README 形成以下相互对应的设计表；不适用项说明原因，不能用“遵循模板”代替设计：

1. 原始点 → 模块/通道 → 类型/单位/quality → 业务角色 → 证据。板载 mA 与模块 µA 先归一单位；
   两只绝对液位计算差值须同基准、同单位、均有效且满足采样时差；差压计与差值计算不是同一接线。
2. 逐设备能力表：保持/脉冲/双向输出、真实 RUN/到位/故障/远程反馈、支持模式、缺失能力与禁用范围。
3. owner/优先级表：硬保护、设备故障、许可、停止、复位、模式移交、手动、自动需求、最终输出。
   每个输出只有一个最终 owner；普通远程 false 是控制许可不成立，不自动变成故障。
4. 完整状态转移表：现态、事件、输入质量与前提、下一态、输出、计时处理、拒绝/异常及恢复。
   覆盖首次投入、正常两轮、STOP、故障、复位、参数变化、控制器重启与非法状态。
5. 逐设备恢复白名单，使用 `reset-recovery-contract.md`。可重新投入不等于恢复旧启动命令。
6. 参数表：类型、单位、范围、成组约束、调试占位、保存方式、在线生效时点。先整组校验再动作；
   分字段 Modbus 写入过程中间态必须禁用有关自动控制，不能假设整组写入原子提交。
7. 北向使用表：HMI 操作/状态/故障/禁用原因/测量质量/设定/维护用途，以及完整地址、类型、宽度。
8. 每条转移与禁止动作 → 独立测试场景 → 实际执行证据；代码与测试不能只复述同一个模板。

## 同一扫描的一致性

所有设备使用本扫描输入快照。先解析质量、命令和模式，再完成单体监督及工艺仲裁，最终统一写输出。
如果下游监督在本扫描才产生超时故障，上游最终自动输出仍须在本扫描按已定联锁收敛，不能继续使用
监督前的“下游可用”。可先计算全部设备候选状态/故障再仲裁，或在最终提交前做一次有界保护复核；
禁止递归重算、无界反复扫描或通过先写危险输出再撤销掩盖顺序问题。手动不在已定联锁范围时保持独立。

每种反馈监督明确期限等号规则；首次反馈在期限之后才到达，不能先接受反馈再跳过超时判断。
测试 T-1/T/T+1、反馈在第一次晚到扫描与超时同时出现、下游新故障与上游新需求同拍。
停止、故障复位和模式重投同时出现时，按优先级消费命令并阻止新的输出启动；健康持续运行复位仍须幂等。
默认故障后的 AUTO 重投是退出并重新选择，不把旧 AUTO 下的手动 START 偷换为重新投入；
若项目需要 START 兼作自动重投，须明确写入模式/命令表并独立验收。

## 点位有差异时先输出差异设计

逐项标记 `SUPPORTED / ADAPTED / DISABLED / BLOCKED`，列出：原能力、新点位、实现方式、
对控制/诊断/北向的影响、待补硬件及验收。只有 BLOCKED 对应的功能受阻，继续完成其余已授权工作。

- 少一台设备：缩减实例与候选池；不得残留不存在的 DI、累计器、故障或 HMI 命令。
- 增加设备：检查 DI/DO/AI、Profile、RTU 负载、变量/北向/存储容量，再扩展实例；不是改一个数量常量。
- 缺 RUN：不能生成“真实运行”、运行累计或反馈成功断言；可设计明确标识的开环命令控制，
  仅在工艺允许且接触器/保护链有证据时启用；依赖真实停稳的联锁保持禁用或补反馈。
- 缺故障 DI：标明硬件故障不可直接观测，仍保留已有 RUN 能支持的超时诊断；不虚构故障点。
- 缺液位差：可用满足条件的两路绝对液位推导；条件不足则禁用液位差模式，保留独立可实施模式。
- 缺外部泵状态：不能把 INIT、过期值或参数常量当实时运行；只禁止依赖该输入的模式。
- 双脉冲启停替代单 DO：需互斥、脉宽、取消/再触发与控制器 STOP 行为设计，不能套保持输出。

不得因为不能确认全部现场参数就什么也不产出。可交付带配置就绪门禁的代码：未知值显式占位，
有关模式实际禁止投入，HMI 显示原因；不能用猜测量程、站号或反馈把该门禁置为就绪。
离线演练可由明确的实验夹具补齐值，标记 `LAB_ONLY`，冻结的是实验软件设计，不是现场事实。

## 样例组合必须明确的边界

格栅/压榨机案例中分别决定：泵运行许可影响哪些模式；正常无泵暂停还是清零；坏质量是否需要重投；
任意一个 GOOD+运行是否足以许可；手动格栅是否联动压榨机；压榨机是否须自动就绪；延停从真实全部停机
还是撤销命令开始；再次来料取消延停；下游故障影响哪些上游。原需求没有规定的跨设备停机不能隐含添加。
本轮示例采用互斥模式；其他项目仍以自己的生效需求为准，不把该选择写成全行业唯一正确方案。
当规则是“任意可信运行允许”时，一路过期不能取消另一持续可信运行源已提供的许可；同时检测唯一
许可源在两扫描之间短断流又恢复的情况。按来源连续性判断，不把任意源中断计数简单 OR 成全组禁止。

## 模板与硬件适配

先核对认证模板的不变量与当前设计是否一致，再决定薄适配或 CUSTOM_REVIEW_REQUIRED。
模板允许故障态转 READY、释放本机重投锁不构成错误；须满足恢复契约和负向测试。
禁止把普通 REM 许可送入会锁存保护故障的入口。厂家原则参考 `vendor-control-patterns.md`，不移植厂家安全认证。

代码规模是可维护性代理值，不是 CPU/内存测量。文件上限调整为有效行 2000、决策点 400；
单函数仍为 400 行/90 决策、嵌套 8、输出写点 2，超过时先按设备/测量/周期/监督分解。
不能为通过门禁压行或提高所有上限。当前 KZ3 工程硬限制由生成器和真实结构检查：
LogicContext 4096 B、北向 256、绑定 384、runtime 16、保持参数 120 B；以目标版本源码为准。
ARM 对象大小、单函数栈帧只提供预算证据，不代表全固件链接、最坏调用栈或实板 10 ms 周期已通过。
上线分层：软件设计/主机 → 目标构建与资源 → HIL 时序/失联/重启/保护 → 现场验收；
可放宽没有硬件依据的文件级规模门禁，不能放宽硬容量、输出安全、反馈/质量或实际周期约束。
