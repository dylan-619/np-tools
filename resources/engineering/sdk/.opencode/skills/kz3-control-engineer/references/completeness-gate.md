# 控制需求完整性门禁

以下项目全部有明确结论，需求才可标记为 `FROZEN`。

README 同时必须符合 [机器可读需求契约](requirements-contract.md)。正文是事实来源，契约是自动门禁摘要；
两者冲突时保持 `DRAFT/BLOCKED`，不能以契约布尔值覆盖正文未决项。

## 软件冻结与现场放行分开

`FROZEN` 表示软件行为及接口已唯一确定，不表示硬件已验收。分三类管理剩余事项：

- 设计阻塞：控制者、关键动作/异常取舍、物理绑定、安全态或必需安全时限未明确，保持 DRAFT/BLOCKED；
- 调试项：已采纳“占位未解除即禁止相关功能”的明确行为，可以进入 FROZEN；在正文单列参数、占位识别、
  禁用范围、提示、填写来源、解除操作及验证。未知液位量程可用 float 0.0，不能当已知量程参与运算；
- 硬件验收项：仅缺 HIL 条件、物理性能/存储寿命实测时，不阻止满足设计门禁的软件生成；阻止相应现场放行。

机器契约 `open_items` 保存设计阻塞，冻结时必须为空；调试与 HIL 项保留在正文和交付记录，不得删除或
伪装成已完成。尚未确定的 PID 算法/方向不能直接生成启用的闭环；只有明确冻结禁用范围、安全输出及
后续受控配置/再验证步骤时，才可交付相关功能禁用的软件版本，不得称为全部工艺已投用。

## 项目与范围

- 稳定 ASCII `project.id`、人读名称、版本和目标板型；
- 工艺目标、明确非目标、首次交付范围；
- 每项需求的来源与可追溯标识：用户原话、点位/原理图/手册路径及版本，或已确认的设计决策；
- 上电默认状态、控制器 RUNNING/STOP/RESET/FAULT_SAFE 的行为；
- 是否允许故障解除、通信恢复或重新上电后自动恢复输出。
- 已匹配的经典场景、主控制模式和认证模板/CUSTOM_REVIEW_REQUIRED 结论；
- 智能体提出的首选方案、用户采纳/改写结果，以及仍需证据的阻塞项。

## 控制所有权

- 多设备已按 [PLC 设备单体与共享工艺归属契约](device-ownership-contract.md) 完成设备 owner 表及共享
  工艺/安全范围表；所有受控设备、命令、模式、输出、反馈、专属参数/计时、总故障、复位与必要北向点
  都能一一追溯，公共测量/阈值/PID/仲裁不无故复制为逐台点；不适用项写明理由；
- 自动/手动、就地/远程等模式及唯一 owner；
- 远程有效但未成立只禁止控制，不列为设备故障或总故障来源；拒绝/移交动作不间接触发超时故障，
  不要求为恢复远程做故障复位，坏质量/真实故障分开；按设备归属契约核对正文、点表和验收断言；
- 每台受控设备的独立自动选择、北向字段和当前 owner；组级自动使能若有，仅为附加许可。自动候选池
  仅包含已选自动且满足本机许可/质量/故障/能力的设备；手动运行设备计入真实容量但不可被自动启停；
  候选不足、联动依赖未选自动和逐台退出/重入自动的降级、诊断与防误启策略均须写明；
- 多台设备的手动命令逐台独立，手动请求与自动请求使用不同状态；除冻结的手动联动或共用安全保护外，
  操作一台不得改变其他设备请求/输出，自动调度状态不得进入手动分支；
- 模式切换期间输出与从手动返回自动的策略；
- 自动间歇启停/定时轮换时，逐台列可写运行时长与停止时长、独立 bind/计时实例、单位/范围/初值来源、
  计时起点、零值/非法值禁用、故障/模式切换后重入及在线修改影响范围；若共用时长为明文要求，
  单独记录例外，不以一对全局参数冒充逐台设置；
- 急停/硬保护、故障、停止、许可、启动和正常调节的明确优先级；
- 同一扫描冲突命令的胜出规则。

## I/O 与外部契约

每个输入至少具有：业务名、类型、物理 bind、正常语义、质量要求、坏质量策略、证据来源。

每个输出至少具有：业务名、类型、物理 bind、安全值、允许条件、反馈点或“无物理反馈”的明确声明、
证据来源。

对未改动的 A11 标准板固件，板载 DI/DO 的软件极性与 DO 安全目标可直接以当前板型定义和底层映射
作为来源：DI 低有效并归一为逻辑 `true=业务状态成立`，DO 高有效且 `false` 为软件安全目标。
这部分不作为待用户逐点确认的设计阻塞；触点、断线、继电器和设备最终动作另列 HIL/现场验收。
从站/其他板型不继承 A11 默认，配置冲突或安全行为确实依赖未知接线时保留具体阻塞项。

模拟量还需要单位、工程量程、原始码/缩放归属、断线或越界行为。RTU 还需要已证实的 Profile、端口、
站号、轮询/失效策略和输出确认语义。北向字段需要稳定名称、类型、访问权限和地址分配约束；已有地址
冻结保持，新字段按既定布局由生成器确定性校核，交付前补齐实际地址/宽度，不能手工猜地址。
已接线并在本项目配置工程量程的 AI 仪表，逐路明确换算结果、工程单位、只读北向字段及无效显示语义；
仅有原始电流或工程量程参数而没有可供 HMI 直接显示的换算值，不满足需求完整性。

用户提供现有点位文件时，还必须记录业务角色如何从 `name + description + type + direction + bind` 得出。
描述与类型/方向冲突、一个角色对应多个候选、或运行反馈其实只是输出回读时，不能通过门禁。

输出请求、模块/协议回读、接触器辅助触点或设备真实运行反馈必须逐项标明，禁止用同一个“运行”字段
混写。缺少真实反馈时要明确记录“无物理反馈”和因此无法证明的现场行为。

## 变量与状态

- parameter：类型、默认、最小/最大、单位、何时生效；缺省仅 RAM，需掉电保持时显式确认
  `persistent: true`、恢复策略和实板掉电/寿命验证边界；
- command：one-shot 语义、允许条件、冲突优先级；每台受控设备包含独立故障复位，并明确可清本机软件
  锁存、不可清客观故障、复位后自动恢复和不误启行为；
- state：owner、初始值、置位/清除条件、可观测意义；
- 每台受控设备列出硬件故障反馈（没有则明记无反馈）、设备级软件故障及独立总故障；总故障为已定义
  可见故障分项（含硬接历史锁存）的逻辑或。不得用原始故障 DI 或控制器级故障代替设备总故障；
- 凡有启动/停止或开阀/关阀动作，逐台列出真实成功反馈及相应启停/开关超时、置位/复位、坏质量和
  安全处置；只有独立真实运行反馈、本机已确认运行且仍要求运行，才加入按冻结时限（继电器设备
  缺省 `5000 ms`）的滚动运行反馈
  丢失；只有真实故障 DI 才加入硬接故障。只有开、关到位反馈的阀门只做开阀、关阀超时，不默认
  增加到位反馈丢失、运行反馈丢失或运行累计。必需成功反馈或明文要求的故障反馈缺点位时保持
  DRAFT；不得以 DO 目标、通信错误或笼统故障伪造物理反馈；
- 功能块：用途、独占实例、时间或工程单位；
- runtime：采用 `T05_RUNTIME_COUNTER_USAGE`，冻结真实反馈/命令时长口径、trigger 与质量、稳定名称和声明
  顺序、清零协议/权限、掉电损失接受边界、日最大启停次数和 schema 影响；EEPROM 寿命证据缺失列为
  待产品放行，不冒充软件设计已验证寿命；启动次数、
  故障时长、班次/月报等未认证统计标记 `CUSTOM_REVIEW_REQUIRED`；
- 逐台核对所有真实运行反馈均有唯一的声明式 runtime、只读北向累计秒数和本机 one-shot 清零命令；
  `clear_pending` 保留内部完成状态，不新增北向点位；每个其他已声明 runtime 也必须具备清零接口。
  仅采集项目同样适用。无反馈时不冒充真实运行累计；超过 16 个 runtime 或已投产槽位身份无法兼容
  时保持 DRAFT，不通过省略某台、重命名或重排绕过；
- PID：方向、测量/给定/输出、限幅、采样周期、手自动、坏质量、整定值来源与 HIL 方案；每回路 KP/KI
  application parameter、北向可写字段、runtime gains 实际消费、范围/单位/持久化及增益改变后的退出闭环和重新投入。

所有数值规则必须写出单位、有效范围、越界策略和等号归属。定时、液位、压力、加减泵、反馈超时等
规则至少明确阈值前一拍、等于阈值、后一拍；不能只写“到时”或“高于一定值”。

每个 parameter/command/state 都要记录“来自用户原话、点位描述还是智能体工程建议”，智能体必须先给出
首选分类和理由；用户确认业务用途或已有授权可覆盖的细化，不逐字段重复签核。长期可调设置与一次性动作不能因为北向实现方便而混为同一字段。

## 北向与地址兼容

- 新项目具有面向 HMI 页面/用户动作的显式北向白名单，并使用 `HMI_SHORT_V1` 短名和中文说明；
- 每台受控设备的只读 `<设备>_F_L` 总故障在白名单中；适用的启停/开关超时、真实运行反馈丢失、
  已接线硬接故障按故障定位用途逐台列只读分项，不以精简点位为由隐藏原因或删除总故障；
- 每台有真实运行反馈的设备都有只读 `<设备>_RT_S`；只有开、关到位反馈的阀门不生成该字段；
- 每个已声明 runtime 都有本机 `*_RT_CLR -> runtime.<name>.clear`，内部使用
  `runtime.<name>.clear_pending` 判断完成，但不生成 `*_RT_PND` 北向点位；按 T05 发布存储诊断，
  清零与故障复位分开；
- 中间状态、临时请求、上一拍、内部时序、功能块内部量和无用户动作的诊断已列入排除项；
- 修改已有项目时，每个原有字段的名称、类型、访问权限、地址和宽度均完成兼容性对比；
- 新字段追加到不冲突地址，不对旧地址重排或压缩；
- 删除、改名、改类型、改权限或改地址已经明确标为兼容性变更并取得确认。

## 行为与验收

- 正常启动、运行、停止；
- 输入 INIT/STALE/OFFLINE/BAD；
- 故障、急停、许可丢失、反馈不一致和超时；
- 逐台分别验证适用的启动/开阀超时、停止/关阀超时；有独立真实运行反馈与持续运行目标时验证
  首次确认后的运行反馈丢失（继电器设备未指定时 `5000 ms`），有实际故障 DI 时验证硬接故障；
  校验超时前/到时、时钟回绕、反馈恢复、质量失效、停止中不误报运行丢失，以及安全输出和恢复不误启；
- 逐设备验证硬件故障单独出现、软件故障单独出现、两者同时出现及复位后硬件故障仍存在时总故障保持；
- 逐设备故障复位只清本机软件锁存；复位一台时另一台的软件故障/总故障保持，同拍复位多台各自处理；
  不掩盖仍存在的客观故障，且不改参数、不清 runtime、不建立启动请求；
- 逐台 runtime 清零不改变运行输出、模式、请求或故障；写入 ACK 后核对本机 `clear_pending` 生命周期、
  新累计纪元、他机不清零，以及存储失败/恢复；EEPROM 掉电和写寿命另列 HIL/产品放行；
- 阈值前一拍、到时、后一拍及 32 位 tick 回绕；
- 平台 STOP、controller_reset、FAULT_SAFE 的实际生命周期与各类状态保留/清理结果；不能笼统承诺所有值清零，
  runtime/持久化参数由其 owner 管理；项目 reset_faults 不改步骤、计时或 PID；
- 参数边界、命令冲突和模式切换；
- 多设备手动逐台启停无串扰，以及自动需求、候选、阶段或计时变化时手动输出保持隔离；
- 多设备自动逐台选择、混合手自动、候选不足/替补、手动运行计入容量、联动下游未选自动、单台模式
  切换首拍与恢复；自动不得启停未选自动的设备，也不得改变其他设备选择/请求；
- 定时自动项目逐台设置不同运行/停止时长并跑完整周期，测试边界前/到时/后、非法/未填、改单台参数、
  故障/模式切换中断与恢复；其他设备参数、阶段和输出不得被串改；
- 每个 Then 都能在 `logic_project_test.c` 或 HIL 步骤中观察；
- 每个场景有稳定场景 ID，需求契约的 `required_scenarios` 与测试中的 `PLC_TEST:` 标签一一对应；
- 清楚区分主机可验证项与待实板/待现场项。
