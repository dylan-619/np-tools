# 点位表＋简短需求到控制代码

## 目标与执行优先级

智能体承担 PLC 控制逻辑的工程细化，不是问卷收集器。用户给出点位表和简短工艺要求后，主动完成
角色映射、控制方式选择、正常/异常/恢复状态机、完整配置、代码和可执行测试。保留原工艺，不要求
用户先写出程序级规格。仅分析/完善技能不授权生成现场项目；已授权实际项目实现时，门禁通过后连续交付。

本文件统一入口的默认继承、提问和资料加载策略；其他文件中“整组确认/是否采纳”只适用于新增且
实质改变工艺的决策，不要求重新确认这里的已定规则。PLC 指可编程逻辑控制器及其工程控制规则。

采用顺序：当前明确需求 > 当前有效项目契约 > 已确认的平台约定 > 与点位能力匹配的控制建议。
旧项目的数值、联锁和硬件事实不能因“案例相似”覆盖当前输入。记录来源，不伪造用户确认。

## 首轮直接完成

1. 解析模块、通道、设备及真实反馈，区分备用、物理 I/O、参数和外部写入；不按案例名称猜设备。
2. 按下面控制模式选主模式；命中时从 [标准场景匹配](field-control-patterns.md) 只读对应小节，组合
   必要的反馈监督，主动列出完整控制结果，不把状态机交给用户设计。
3. 已定共性直接写入“沿用规则”；新工艺选择给推荐、理由与影响，集中列出真正待裁决的少量事项。
   没有实质分歧时不凑确认问题。工程量程等可安全占位的调试项与设计阻塞分开。
4. 形成需求及机器契约，执行冻结门禁；实现授权仍有效则继续 YAML、C、项目测试、隔离验证和 HIL 计划。
   不把“需求写完”当作完整实现任务完成，也不以减少提问为由越过真实安全缺口。

## 沿用规则：说明采用，不重复索要批准

- A11 为控制器本体；A12/A13/A14/A15 对应从站地址 1/2/3/4，后续按 A(n) → n−11。
  这是本项目族的模块标号约定，不是型号或通用 PLC 标准。型号/Profile 由硬件确定，未明说默认
  `rs485_1`；真正的 `AI12` 是通道名，不能不看表结构就当 A12。
- 同类标准模块的串口配置默认 `9600`、8N1、响应超时 `100 ms`、重试 `1`、离线退避 `5000 ms`；
  默认轮询 `500 ms`、失效 `1500 ms`。明确配置或 Profile 限制优先。写配置不会给物理从站改地址；
  实际地址、串口一致性在调试检查，资料冲突才提出问题，不逐站重复问默认值。
  多从站/大点表要检查总线周期预算，不能照抄 500/1500 ms 造成误判离线；不满足时由智能体计算建议值。
- 未更换标准板和固件时沿用已验证 I/O 定义：DI 已归一为业务逻辑值；继电器式 DO 使用既定软件极性。
  不再次反转、不逐点询问；从站按实际 Profile，未知安全接线不能冒充已知。
- 远程反馈是控制许可：`GOOD + REM=false` 只禁止本控制器控制，不算设备故障、不锁存、不计入总故障，
  不要求为恢复远程做故障复位；动作监督、坏质量及旧接口区别按设备归属契约处理。
- 每台独立手动，手自动请求隔离；自动调度不能改手动设备。需要自动的设备逐台 AUTO，自动候选
  只包含已选自动且可用者。只有手动需求时不凭空添加自动算法或空 AUTO 字段。
- 开/关双方向输出的阀门、闸门逐台执行 [双向反转保护](control-timing-contract.md#阀门双向反转保护)：
  手动开转关、关转开都先独立STOP，双向全断满 `2000 ms` 后重新下令；未停或早到反向命令作废，
  不排队。自动换向先全断至少 `2000 ms` 再复核原工艺条件。直接写入沿用规则，不作为新增建议待确认。
- 独立运行/停止定时周期默认 FIRST_RUN：已停止设备手动切自动且条件有效时直接启动，真实运行确认后
  计运行时长，再停机并从真实停止确认计停止时长。已运行设备不做额外启停处理，直接从切入开始计时；
  不再询问首阶段。上电保留模式/故障恢复不视为新投入，明文先停止等例外按计时契约保留。
- 每台独立故障复位、总故障；复位按恢复白名单清本机故障并恢复可用，不直接写输出、不恢复旧启动、不改模式或运行累计。
  客观故障仍在则总故障保持；恢复策略由正常控制路径处理，复位不等于启动。
- 未指定反馈时限时，直接继电器控制的泵/机器启动 5 秒、停止 30 秒、运行反馈丢失滚动窗口 5 秒；
  阀门开到位、关到位各 120 秒。按设备归属契约逐项核对适用反馈，直接写入沿用规则，不重复确认。
  明确值和有效冻结契约优先，不回写旧现场项目；这些默认不是 PLC 标准认证时间。
- 普通过程阈值连续满足 30 秒才改变需求；中断、坏质量、模式或相关参数改变重计。保护停机不等这 30 秒。
- 真实运行反馈才派生累计运行秒数及独立清零命令；内部清零 PND 不北向发布。仅阀位反馈不派生运行累计。
- AI 使用工程量程则北向发布换算工程值及有效性。北向只保留必要操作、设定、监控、报警和维护字段，
  沿用统一短名；一条 YAML 点位记录一行，不发布内部阶段/请求/临时计时。
- KZ3 实际执行 PID 时，每回路 KP、KI 都作为独立可写参数北向开放；改单必须退出该回路并重新投入。
  厂家成套柜自行 PID 时只保留其真实接口，不生成第二套本机 KP/KI。
- 工程量程及液位阈值可用 float 0.0 调试占位，相关自动保持禁用直至参数有效；非安全级外部输入
  默认失效窗口 30 秒，必须同时定义首次数据、断流和恢复。占位不代表已具备现场投用条件。

## 控制模式：按命中选择，不全部装入项目

| 输入特征 | 智能体补全的控制骨架 | 不得擅自加入 |
| --- | --- | --- |
| 仅远程手动启停 | 每台独立启停请求 → 本机许可/保护 → 输出；同拍停优先；公共反馈监督 | 自动轮换、跨设备联停、空自动模式 |
| 运行时间/停止时间交替 | 每台合法切 AUTO：已停先启动并等运行反馈，已运行不做启停处理直接计时 → 运行到时停止 → 等停止反馈 → 停止计时 → 再启动；逐台时长参数 | 默认先等停止时间、已运行重复启动、共用一对全组时长、用 DO 代替运行反馈 |
| 单液位一用一备 | 高阈值确认后需求 1，低阈值确认后需求 0，中间保持；可用自动候选中择一；故障剔除并按许可替补 | 默认两泵同时跑、无依据的定时强制换泵 |
| 多液位分段加减泵 | 液位状态机只算需求台数；调度器只分配可用自动设备；已启动反馈确认后才开始后续加泵等待 | 缺失减泵规则、把手动设备纳入自动启停 |
| 污泥回流/多泵均衡 | 先辨明液位分段、定时还是固定台数，再组合对应模式；要求均衡时最短累计优先启动、最长优先停止，同值按编号 | 仅凭“回流泵”添加 PID、配阀、定时轮换 |
| 开关阀＋双到位 | 方向互斥＋双向2秒反转保护 → 行程监督 → 到位完成；手动独立STOP后新命令，自动先停后等；双到位矛盾另报异常 | 手动反向排队、只全断一拍、把阀位当运行反馈或累计 |

定时、反馈监督或延停命中时读 [控制计时与清除契约](control-timing-contract.md)。独立周期合法新 AUTO
投入后，已停者启动并从 GOOD 运行反馈计时，已运行者不做额外启停处理、从切入直接计时；停止时长
从 GOOD 停止反馈起算。正常时长变化首选下一完整
运行＋停止周期成对生效，不重置当前计时。首次阶段、在线 0、模式移交、顺控会话快照与清料实时改值
是不同策略，按原文/已采纳变体记录，不能混为“取消旧周期”。未给时长用禁用占位，不把别的项目
15 分钟写成现场事实；停止未确认不得直接倒计时再启动。

一用一备缺少指定主泵时建议累计最短者为本轮主泵，启动后不因累计排名变化频繁切换；故障替补还需
检查旧设备未确认停止时的并行许可。排水/补水方向、最大同时运行数或支路隔离不清且会改变工艺时，
给具体推荐供一次裁决，不能仅凭“液位控制”猜方向。

泵阀顺控只有点位与工艺要求支持时才组合：阀到位后起泵、停泵反馈后关阀；故障替补是否必须等待
原支路关闭取决于实际隔离要求，不能把某个项目的等待条件推广到所有并联泵。
单 DO 保持、双 DO 脉冲和阀行程保持是拓扑建议，不证明执行器电气行为；已有确认直接沿用，冲突或
关键驱动证据缺失时保持对应输出禁用并给出明确待验证项。

## 公共反馈监督与验证

以下是控制分层伪代码，不是可直接复制的 KZ3 API；生成前必须对接当前平台接口和适用实现模板。

```text
每扫描：
  采样输入及质量，计算各设备客观故障与许可
  消费逐台命令；复位只处理本机软件故障位
  对每台设备选择唯一请求来源：手动请求 或 该设备自动请求
  单液位：连续确认高/低条件 -> 需求 1/0；滞回区保持
  多液位：按冻结的逐级升降表 -> 需求台数
  调度：保留已分配健康设备，只对自动候选增减请求
        排除故障、未选自动、许可/质量不满足者
        均衡模式只在分配时按累计排序，不每扫描重排运行者
        扣除已明确计入容量的手动/就地运行；未知运行占用按冻结策略处理
  独立周期：已停设备合法新 AUTO 投入 -> 首先启动等待 -> 运行已确认 -> 运行计时
            -> 停止等待 -> 停止已确认 -> 停止计时 -> 再启动；各设备各自计时
            已运行者切 AUTO 不做额外启停处理，保持合法输出，从切入直接开始运行计时
  启停监督：启动/停止等待各有超时；已运行后另监视持续反馈丢失
  阀监督：开关互斥，分别等待真实到位并监督超时
  汇总本机总故障；执行本机/明确共用保护；每路输出唯一最终提交
```

各模式为按需求选择的分支，不是每个项目都执行的全功能循环。软件复位本身不跳状态；
故障后的状态迁移与重新投入由正常控制路径执行。计时使用平台安全的时间差方式并测试回绕。

有本机控制和实际运行反馈：启动后在启动限时内收到 GOOD 运行；停止后在停止限时内收到 GOOD 停止，
分别检查到时前/到时的启动与停止故障。已确认运行且持续要求运行时，反馈连续丢失达到本机冻结时限
（继电器设备缺省 5 秒）报丢失故障；
启动等待、正常停止不进入该判据。坏质量不是有效停止或有效到位，不得用缺省 0 绕过监督。
实际硬接故障 DI 才纳入硬件故障；无反馈能力必须说明限制，不虚造输入。启动/停止/阀行程限时沿用
明确值；未指定时采用上述已定共性默认，不把旧案例的其他时限冒充当前需求或设备事实。

按适用能力测试：独立手动、多台混合模式、候选不足、阈值抖动、精确计时边界、反馈异常、故障复位隔离、
断电/通信恢复不误启、参数非法及在线变更；有运行累计再测保持/清零。阀门仅双到位不加运行丢失测试。
检查必须调用实际逻辑并断言输出，不能用场景标签代替验证。主机通过与 HIL/现场验收分别报告。

## 按阶段取资料

首次解析读本文件、实际点位和需求；复杂工艺才从行业目录加载命中的卡，不通读全部行业案例。
需求落盘再读需求工作流、机器契约和模板；北向字段查词典，多设备归属查 ownership，外部输入才读
external-input。冻结前完整性与安全审查不能省略，但不适用项用简短理由，不生成空业务/空点位来凑表。
生成阶段才读取生成契约、真实 API/认证模板；验证阶段才读取验证规则。相同版本文件不重复读，
开发指南按当前问题定位段落，不要求每轮完整加载多个大章节。存在冲突时定位具体条款，不递归读全库。
