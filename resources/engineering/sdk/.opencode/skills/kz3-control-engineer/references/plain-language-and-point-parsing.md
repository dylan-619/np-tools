# 白话沟通与点位解析

## 先听业务，再整理工程字段

用户不需要先准备专业需求书。允许从一句话开始，例如：

```text
两台泵平时只开一台，运行满 4 小时就换另一台，一直交替。
```

先回复对 PLC 原工艺的简短理解，读取点位，列出已经明确的规则。匹配经典/行业案例找出原文省略的
条件，仅对缺口给首选补充；不能因为文字简短就认定用户没有方案。不重复询问已明确的规则，不要求
用户设计状态机。水处理输入按 [PLC 边界匹配](plc-boundary-matching.md) 执行。

对用户说“运行反馈质量不好时是否停机”，不要先问“BAD quality policy”；说“这个时间以后能不能远程改”，
不要先要求填写 parameter schema。专业术语可以保存在工程文档中，但面向用户的摘要优先用白话。

已定共性直接说明采用，不将它们反复变成问题：

```text
沿用停止优先：启停同拍时停止。
沿用逐台故障复位：清本机故障并按恢复白名单恢复可用，不直接写输出、不恢复旧启动、不改模式或他机。
```

只有新增实质工艺选择才用“建议＋理由＋确认”；依据见 [点位表到控制代码](table-to-control.md)。

避免使用“启停冲突怎么办”“坏质量策略是什么”“你想要哪种状态机”这类把 PLC 设计责任原样交给用户的
开放问题。先检查当前固件的板型定义与映射；已由未变的标准板固件确定的 DI/DO 逻辑极性直接沿用，
不要再询问用户。只有端子/接线与当前基线冲突，或真实反馈来源、硬保护等确会改变安全行为的事实
无法推导时，才说明需要哪份现场证据。

## 点位角色识别顺序

对 `project_io.yaml`、点表或用户提供的配置，按以下顺序处理：

1. 读取完整字段，不只搜索名称；至少收集 `name`、`description`、`type`、`direction`、`bind`、安全值、
   单位和质量要求。
2. 使用 `name + description` 提取设备编号与业务动作，例如 `pump_01_start`、`1#泵启停控制`。
3. 用 `direction` 和 `type` 检查候选是否合理：启停控制通常是 BOOL 输出，运行/故障反馈通常是 BOOL
   输入，频率反馈通常是带 Hz 语义的数值输入。
4. 用 `bind`、安全值、单位和量程确认现有配置事实，但不从地址编号推断现场用途。
5. 输出角色映射和证据。冲突、缺失或一对多候选单独列出，让用户确认。

常见描述线索仅用于提出候选：

| 角色 | 中文线索 | 英文/标识符线索 |
| --- | --- | --- |
| 启停控制 | 启停、启动、接触器控制、运行命令 | start, run_cmd, enable, request |
| 运行反馈 | 运行反馈、接触器反馈、已运行 | run_feedback, running, feedback |
| 故障 | 故障、跳闸、保护 | fault, trip, alarm |
| 频率反馈 | 频率、实际频率、输出频率、赫兹 | frequency, freq, hz |
| 许可 | 允许、联锁满足、就绪 | allow, permissive, ready |

不能仅靠关键词覆盖结构事实。例如一个 `direction: input` 的字段即使名称包含 `start`，也不能直接当成
物理启动输出；描述写“运行”但实际是输出请求时，也不能把它说成设备真实运行反馈。

## 参数、命令和状态怎么从描述里提出

- “时间、阈值、上限、下限、比例、首选、设定值，以后需要调整”：列为 parameter 候选；
- “启动一次、停止一次、立即切换、确认、复位、清零”：列为 one-shot command 候选；
- “其他采集器/业务机/上级周期发送的当前值、断流后要失效”：列为 external input 候选，按
  [外部实时输入契约](external-input-contract.md) 补齐生产者、周期、类型/范围、时效及恢复；
- “当前泵、正在切换、剩余时间、禁止原因、实际阶段”：列为只读 state 候选；
- “自动运行开关、远程允许”可能是保持目标，也可能是命令组合。先建议“不掉电自动恢复、断线禁止输出、
  恢复后重新使能”的不误启方案；连续工艺需要自动恢复时，再把替代方案和风险交给用户确认。

提案要包含白话用途，而不是只给机器字段名。用户确认后再冻结名称、类型、默认值、范围、权限和地址。

## 北向白名单与排除

新项目按 [北向 HMI 点表契约](northbound-contract.md) 建立显式白名单。先从需求和点位推导 HMI 页面与
用户动作并提出白名单，只将操作命令、可调设定、关键测量、设备状态、工艺摘要和必要维护诊断列为候选；
只有候选会改变外部接口且无法推导时才请用户确认。状态机阶段、临时请求、上一拍值、内部时序、功能块
内部量和无用户动作的调试字段默认排除，不因在 YAML 中声明就自动暴露。

修改已有项目时：

- 保留已有字段名称、地址和顺序；
- 新字段使用不冲突的后续地址，并遵守类型占用宽度；
- 暂停报送优先采用明确的兼容策略，不能顺手压缩地址；
- 删除、改名、改址或重排均标记为北向兼容性变更。

新项目使用 `HMI_SHORT_V1` 共享词典和确定性规则分配地址。需求解析阶段就建立“中文业务语义 → 统一短名 → bind”，
生成和交付只能复用，不得临时换同义缩写。生成后把北向白名单、缩写词典和地址表交给用户确认。
