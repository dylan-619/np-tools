# STM32-Logic 项目验证工作流

按设备归属契约审查 `DEVICE_FAULT_COHERENCE` 三个专项场景：硬接历史保留、北向分项/总故障一致、
复位同拍按恢复白名单处理且无越权控制副作用。实际从生成点表读北向字段，不能仅断言内部锁存；旧接口差异只报告待迁移。

默认对项目源做隔离验证，不修改 `active_project`、活动副本、生成物或 lock 文件。

## 执行

完整交付同时读取 [端到端交付契约](end-to-end-delivery.md)，核对配置完整性、安全/稳定性报告与 HIL
计划。旧项目只读诊断则报告缺口，不未经授权补文件；脚本成功不能代替这些内容的语义审查。

若只检查独立需求文件，运行 `verify_project.py --requirements-file <文件> --require-engineering-review`，
冻结追加 `--require-frozen`，报告 document-only；无需定位工程。以下编译流程仅适用于项目验证。
语义审查先对照 PLC 原始需求保留表和边界差异表，发现代码按模板改写原工艺时报告偏离。
命中的 [标准场景](field-control-patterns.md) 逐项对照需求、配置、实际读写和断言；时间相关逐项按
[计时契约](control-timing-contract.md) 检查。首轮、完整周期快照、在线0和清料改值不能用同一句
“下阶段生效”代替；时限后首次晚到反馈不能吞掉超时，运行丢失不能从上一拍正常反馈提前起算。
多设备必须按 [PLC 设备单体与共享工艺归属契约](device-ownership-contract.md) 审查完整 owner 表：
点位识别出的每台受控设备都有唯一命令、输出、反馈、模式、故障与复位归属；只给实际使用周期的
设备配置独立时长，公共测量/阈值/PID/调度不得无故复制。逐台与共享行都要追溯到实际配置、
代码、北向白名单和测试；脚本无法证明未声明的设备或共享边界，应人工对原始点表核对。
项目存在 KZ3 PID 时，按 [PID 上位机整定契约](pid-online-tuning-contract.md) 逐回路核对 KP/KI：
必须存在独立 parameter、北向 `float/read_write` 字段及实际 runtime gains 赋值；测试需证明非法值拒绝、
单项/两项写入期间不继续闭环、增益变化要求重新投入、其他回路隔离及持久化恢复。只有字段名或标签不算通过。
对原点表和 `points.inputs` 再逐项查找设备真实运行反馈，不按设备名称排除；每个反馈必须唯一绑定 T05
`runtime_counters`（显式 active_value、GOOD 质量）并有只读 `*_RT_S`。只采集项目也检查。
严格脚本按命名/描述拦截常见遗漏，但不能把模糊点位自动当作真实反馈；描述不清时人工核对并
保持需求待决。测试包含两台同时运行、单台反馈坏质量/恢复、STOP/Reset 与累计隔离；
持久化和写寿命分别保留实板证据。
对每个 runtime 再核对本机北向 `*_RT_CLR` 和 T05 存储诊断；`clear_pending` 仅作为内部状态，
不要求 `*_RT_PND` 北向点位。真实扫描验证写入 ACK、
pending 置位/清除、新累计纪元、运行中清零及他机不受影响。故障复位不能清累计，清零不能改
控制输出或故障；旧项目未开放 clear 时列出待迁移缺口，不把 host 通过当作此项通过。
严格脚本会拒绝缺失/重复/只读/串绑的累计清零入口和北向 `runtime.*.clear_pending`；旧发布接口有
pending 时只记录不符合新最小点位规范，先做兼容迁移评估，不在诊断中删除已用地址。
对每台受控启停设备或开关阀，按 [单体反馈故障契约](device-ownership-contract.md) 分别查适用的
启动/开阀、停止/关阀超时，逐项核对冻结值及单体契约默认表；有独立真实运行反馈且持续要求运行时
才查已确认运行后的滚动窗口（继电器设备未指定时 5 秒）
反馈丢失，有实际故障 DI 时才查硬接故障。只有开、关到位反馈的阀门只核对开、关超时，
不要求运行反馈丢失或运行累计。至少测试适用项的超时前/到时、反馈晚到、坏质量、故障保持、
复位和安全输出；不虚构输入。已有设备内建故障要核对方向与完整语义。
同时读取 [北向 HMI 点表契约](northbound-contract.md)，逐点核对消费者、用途、必要性和重复语义；
无用途的新字段不应发布，必要报警/质量/完成判据不能为减点裁掉。结构脚本不能代替最小化语义审查。
逐路核对已接线且配置工程量程的 AI：实际逻辑换算结果应有同单位、只读的北向工程值，HMI 可直接显示；
无效采样或未完成标定时不能呈现伪有效的 0，原始电流/码无需重复发布。仅有量程参数或内部工程值不算通过。
另逐点核对需求表、README、`project_io.yaml` 和临时生成点表的短名/bind 映射完全一致；
同一业务语义使用不同缩写、同名异义或未登记临时缩写均不得交付。
新生成项目还要检查 `project_io.yaml` 的点位及扁平变量清单是否“一条记录一行”，遵守
[生成契约](generation-contract.md) 的范围和 YAML 引用规则；解析成功、字段/地址/权限/顺序及生成点表
一致性是前提。旧项目仅诊断时把多行排版记为风格差异，不擅自批量改写，也不把排版差异当作控制
逻辑或 HIL 失败。
采用本点表编号体系时，复核 A11 为本机、A12 为从站 1、A13 为从站 2，通道保持各自归属；
硬件型号/Profile 单独核对，不得由 A12/A13 固定推断模块型号，也不能配置成从站 12/13。
未指定从站串口时核对默认 `rs485_1`；已明确其他端口时核对原要求，不用默认覆盖。串口参数仍单独审查。
这是来源到配置的语义复核；只有 YAML 而没有原点表标识时，不声称脚本已自动验证此映射。
项目声明 external input 时读取 [外部实时输入契约](external-input-contract.md)，确认需求、YAML、逻辑和
`EXTERNAL_INPUT_LIFECYCLE` 测试一致；严格门禁允许直接读取 `context->input.external`，但仍禁止直接
读取 `context->input.board/rtu` 或在项目逻辑调用 DataManager/网络写入口。

新生成项目按 [安全与可靠性审查](safety-reliability-review.md) 完成边界与实际断言的对应审查，命令使用
`--strict-quality --require-engineering-review --require-execution-evidence`。旧项目诊断省略执行证据标志，也可去掉工程评审标志，但不得声明完成新门禁。

对未变的 A11 标准板固件，核对项目使用 `IO_IN` 已归一化的逻辑值，断言 `GOOD + true` 对应点位描述的
状态；DO 的 `false` 与板型软件安全目标一致。不得因 `board_io_hil: pending` 把相同 DI/DO 软件极性
逐路退回用户确认；实板仍核验端子、触点、断线和负载最终动作。RTU 扩展模块单独核对 Profile。

1. 读取适用 `AGENTS.md`、项目 `README.md`、冻结需求与 [验证矩阵](verification-matrix.md)。先检查用户
   工作树，记录但不处理无关修改。
2. 从仓库根目录对单个项目运行：

   ```sh
   python3 .opencode/skills/kz3-control-engineer/scripts/verify_project.py \
     application/projects/<项目目录> --strict-quality --require-engineering-review --require-execution-evidence
   ```

   脚本会在系统临时目录复制 I/O 定义、确定性生成点表、扫描常见越界接口，以
   `-std=c11 -Wall -Wextra -Werror` 编译真实 LogicManager/DataManager 路径并执行项目测试；严格模式还会
   核对冻结需求契约、`PLC_TEST` 场景可追溯性、`PLC_STYLE_V1` 文件级/函数级静态指标、递归禁用和
   `HMI_SHORT_V1` 北向契约。
   北向契约同时检查节点说明：BOOL 物理输出必须写明“DO输出”，复位必须写“故障复位”，`*_F_L`
   必须写“总故障”，并拒绝“软件目标/软件请求/软件解读/软件监督/软件故障/故障锁存”等实现术语。
3. 审查临时生成的诊断和项目 README 中的 Given/When/Then 覆盖。`RESET_FAULTS` 必须按恢复白名单验证清故障、恢复本机可用、旧启动不恢复及健康运行幂等；本机阶段、监督计时、重启许可可按设计恢复，不改模式、参数和 runtime。
   逐台检查只读 `*_F_L` 是否绑定该设备总故障，计算包含全部可见故障分项（含硬接历史锁存）；
   实时 `*_FLT` 不能替代硬接记录 `*_F_DEV` 或总故障，也不参加报警分项 OR。核对硬件/软件单独、同时发生及复位后硬件仍在的真实扫描断言，
   多设备还要确认故障归属不串扰。
   未远程单独按设备归属契约审查：首拍、持续未远程、运行中转就地及无许可命令只禁止本控制器控制，
   不置设备故障/总故障、不要求复位，不因被中止监督间接报启停/行程超时。真实故障和 REM 坏质量另测；
   这属于真实扫描语义检查，脚本的结构通过不能代替。旧项目相反行为列迁移差异，不未经授权改现场代码。
   多设备手动项目必须声明 `MANUAL_MULTI_DEVICE`；逐台核对手动命令只改变目标设备，并在自动需求跨阈值、
   候选重选、阶段/计时变化和自动联停发生时，证明 `MANUAL_INDEPENDENCE`、`MODE_ISOLATION` 仍成立。
   多设备自动项目必须声明 `PER_DEVICE_AUTO`；逐台核对模式选择的北向 bind 与代码 owner，使用真实
   扫描证明 `AUTO_SELECTION`、`AUTO_POOL_ELIGIBILITY`、`AUTO_MODE_ISOLATION`：未选自动设备不进候选、
   手动运行计入容量但不受自动启停、候选不足与下游不在自动时按冻结策略处理、切换一台不串扰其他台。
   自动周期或定时轮换项目声明 `TIMED_AUTO_CYCLE`；逐台对照需求表、`project_io.yaml` 参数及北向
   `*_RUN_M/*_STP_M`、代码读值与独立计时实例。不同设定、非法值、到时边界、改单台参数和切换/故障
   后恢复必须有真实扫描断言；脚本场景标签通过不等于这些行为已验证。
   独立周期未另定时核对 FIRST_RUN：已停设备合法切 AUTO 当拍发启动请求；已运行设备不做额外启停
   处理，不重发启动命令/脉冲、不进入启动等待，从切入当拍直接开始运行计时且累计不清零。
   反馈等待不占工艺时长。测试禁止保留 AUTO、故障恢复或补齐参数自行启动；
   明文 FIRST_STOP 例外按原契约测，不能因新默认直接修改已冻结现场项目。
   阀轮次顺控声明 `VALVE_TIMED_SEQUENCE`，验证 `VALVE_TIME_ORIGINS`、`VALVE_SEQUENCE_ABORT`、
   `VALVE_SEQUENCE_SELECTION`；自动延停声明 `POSTRUN_LINKAGE`，验证 `POSTRUN_TIME_ORIGIN`、
   `POSTRUN_RETRIGGER`、`POSTRUN_SAFETY_ABORT`。各标签对应真实输出/反馈/时间断言，不只正常走完一轮。
   多设备项目声明 `PER_DEVICE_FAULT_RESET`，逐台核对北向 `*_RST`、独立 command bind 与本机清除
   列表；对两台同时故障分别执行 A 单复位、B 单复位、双复位同拍，断言未选设备故障和总故障不变，
   客观故障仍在时本机总故障保持，复位不直接写输出、不改模式、不恢复旧启动，允许白名单内本机恢复。
   README 声明认证模板 ID 时，读取
   `application/case_center/standard_templates/catalog.yaml` 并对照其 invariants 逐项核验负向断言；声明
   `CUSTOM_REVIEW_REQUIRED` 时必须存在状态转移表、非法状态收敛和人工审查项。脚本通过不等于业务需求
   完整，测试与代码同源错误仍需人工对照冻结需求。
4. 只有项目已明确激活时，才执行 `python3 tools/project_configure.py --check`、定向 CTest 和静态检查。
   只有用户明确要求切换时才修改 `active_project` 并运行非 `--check` 配置命令。
5. 用户要求发布级验证时，再按仓库规则运行完整主机测试与批准工具链 Debug/Release；缺少工具链就明确
   未执行，不使用 PATH 中未知 GCC 代替。
6. 核对源 YAML 与实际生成的完整点表、逻辑读写及北向白名单一致；审查最坏时延预算、长序列不变量、
   通信/掉电恢复等适用稳定性项。自动脚本未覆盖的项单列结果，不能随总退出码标为通过。
7. 完整新项目按交付模板完成 HIL 计划和证据入口。有硬件动作授权与前提条件才实测，并按版本记录
   失败、修复及受影响回归；无条件则交付软件与计划，报告 HIL_PREPARED/待实板或具体阻塞。

## 报告

验证器不接受 `--requirements-only` 与 `--strict-quality` 混用，避免只查文档却被当作代码已验证。
项目测试默认墙钟超时 120 秒，可按明确测试预算用 `--test-timeout-s` 调整；超时属于验证失败，不无限等待，
也不盲目增大时限掩盖死循环。生成/编译子命令同样有 120 秒上限；脚本输出须归档到稳定交付位置。

逐项列出命令、退出状态和验证层级，并给出有效逻辑行、决策点代理值、最大嵌套、单函数最大行数/
决策点/参数数、递归检查、逐输出写点、测试断言/场景数和北向字段检查结果。只有
`--strict-quality` 全部通过才标记 `KZ3 PLC_STYLE_V1: PASS (host-only)`。IEC/PLCopen
按 [标准符合性声明](standards-compliance.md) 报告工程对齐而不是认证。GPIO/RS485、
电气极性、模拟量量程、执行机构动作、PID 稳定性、掉电与长稳均保持“待实板/待现场”，除非本次真实
执行并留下验证记录。
