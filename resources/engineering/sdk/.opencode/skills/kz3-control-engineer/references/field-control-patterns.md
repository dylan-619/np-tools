# 标准场景匹配与控制建议

用于“点位表＋简短场景说明”的需求细化，不要求部署者拥有任何历史工程。以下是已实现结构的归纳，
不是现场参数库、认证 C 模板或新工艺设计授权。点位能力与本次原文必须同时命中；厂名、柜名、设备
数量或相似文件名不能代替证据。原要求、既有有效决策和已发布接口优先，案例差异不静默覆盖。

## 快速路由

只读命中的小节；复杂水处理再加载对应行业卡。共性复位、累计、质量与北向约束见
[设备归属契约](device-ownership-contract.md)，所有时间含义见 [计时契约](control-timing-contract.md)。

| ID | 表单＋场景命中依据 | 控制组合 | 追加检查特征 |
| --- | --- | --- | --- |
| F01_MANUAL | 启停 DO / 开关 DO＋反馈；原文仅远程手动 | 逐台手动＋本机反馈监督 | 多设备 MANUAL_MULTI_DEVICE、PER_DEVICE_FAULT_RESET |
| F02_INDEPENDENT_CYCLE | 每机运行反馈＋启停 DO；运行/停止时间交替 | 独立周期＋逐机 AUTO＋本机监督 | TIMED_AUTO_CYCLE；多设备再加 PER_DEVICE_AUTO |
| F03_LEVEL_DUTY_STANDBY | 公共液位＋两泵反馈/DO；一用一备 | 滞回需求 0/1＋可用池择一＋停稳替补 | PER_DEVICE_AUTO；要求互斥时测 NEGATIVE_SWITCH_WINDOW |
| F04_STAGED_GROUP | 公共液位＋多泵；分级加减/均衡 | 需求级数＋自动池调度＋容量监督 | STAGED_GROUP、PER_DEVICE_AUTO |
| F05_PUMP_VALVE | 配对泵阀点齐全；明确先开阀后启泵 | 支路顺控＋泵监督＋阀行程监督 | PER_DEVICE_AUTO、VALVE_PUMP_SEQUENCE 场景 |
| F06_MANUAL_VALVE | 开/关 DO＋开/关到位；手动开关 | 逐阀方向互锁＋到位撤输出 | 多设备 MANUAL_MULTI_DEVICE；不生成空自动 |
| F07_VALVE_ROUND | 多阀双向输出/到位；按顺序排泥、轮次间歇 | 自动候选快照＋单阀动作＋整轮等待 | VALVE_TIMED_SEQUENCE、PER_DEVICE_AUTO |
| F08_SCREEN_POSTRUN | 液位差/定时格栅＋共享压榨机/输送机 | 上游需求仲裁＋下游自动联动延停 | POSTRUN_LINKAGE；上游独立周期另加 TIMED_AUTO_CYCLE |
| F09_EXTERNAL_LINKAGE | 上级写入当前设备状态；本柜风机/分离器顺控 | 独立外部数据租约＋顺启顺停＋主备 | EXTERNAL_INPUT_LIFECYCLE 场景；有清料再加 POSTRUN_LINKAGE |
| F10_MIXED_PID | 固定变频主泵 AI/AO＋工频辅泵；明确 PID/分级 | 异构池＋液位需求＋单回路连续调节 | PID_LOOP、HETEROGENEOUS_GROUP、STAGED_GROUP |
| F11_COLLECTION | 有反馈/仪表但无本柜控制输出或控制要求 | 采集、有效性、工程值、已有报警；真实 RUN 累计 | 有 runtime 测 RUNTIME_PERSISTENCE；不造启停故障或命令 |

F01/F05/F06/F07 及其他组合中，只要实际控制开/关两个方向的阀门、闸门，就必须套用
[双向反转保护](control-timing-contract.md#阀门双向反转保护)，并声明其负向窗口与时间边界场景。

所有受控设备按实际能力具备本机总故障和故障复位；有真实运行反馈就累计并配本机清零。
所有场景中未切远程只禁止控制，不是设备故障/总故障来源；旧案例的远程许可故障锁存不得继承，
按设备归属契约处理 owner 移交和动作监督，不能变相生成超时故障。
F02 的“独立周期”不是互斥轮换：原文未要求先后/互斥时允许多台同时处于运行阶段，不添加轮换调度。
这里只登记需求/测试结构；实际 C 复用查目标工程认证目录。组合顺控、特殊许可宽限、完整 u32 分钟
计时或特殊模式移交超出模板适用范围时按 CUSTOM_REVIEW_REQUIRED 审查，不借历史项目通过冒称认证。

## F01 / F02：单机或多机独立启停、间歇运行

典型输入：“三台回流泵，远程手动；自动各运行、停止一段时间，可调整。”

- 由点位识别台数，每机独立 STA/STP/AUTO/RST、运行/停止参数、反馈等待及软件故障，不从柜名补设备。
- 默认 FIRST_RUN，已停设备：`合法手动切 AUTO → 立即启动请求 → GOOD 运行确认 → 运行计时 → 停止请求
  → GOOD 停止确认 → 停止计时 → 再启动`。直接说明“切自动先运行，再停止循环”，不反复索要首阶段
  确认。已运行设备不做额外启停处理，保持合法输出，直接从切入开始运行计时，不重发启动命令/脉冲
  或进入启动等待，不清运行累计；详细准入和起点按计时契约。
  保留的 AUTO=true、故障恢复或参数从 0 补齐不当新投入；原文明定先等停止时间时保留 FIRST_STOP。
- 正常在线改非零时长首选一对参数在下个完整运行＋停止周期边界一起生效，当前计时不重置；在线 0 的
  即时禁用/下一周期禁用必须写清。首次未配置 0 禁止自动；保护和 STOP 永远不等待周期结束。
- 自动退出通常撤本机请求且旧手动请求不复用；明确连续工艺时可采用保持当前 DO 后交给手动的变体，
  但只能转交本机当前合法输出，不能复制旧自动调度或改变别台。不把某柜无扰规则推广为通用事实。
- 验证两台不同周期连续两轮，改 A 参数/复位/退出 AUTO 不改 B；启动等待不占运行时长，停止等待不占
  停止时长。已在运行时投入 AUTO 的计时起点、参数补齐、重启旧选择和长扫描跳变均要覆盖。

## F03 / F04 / F05：液位需求、主备与支路顺控

- 液位角色先分控制、监测与保护；排水/补水方向必须从原文确定。0 工程量程/阈值可作调试占位，
  相关自动禁用，但不阻塞独立手动或其他已具备条件的业务。发布换算工程值与有效性供 HMI 直接显示。
- 普通高/低/分级条件连续成立 30 秒后才更新需求；滞回带保持。明定保护当拍生效，不混为普通阈值。
- 一用一备：缺少指定主泵且要求均衡时，择累计最短的合格 AUTO 泵，同值按编号；选中后保持，
  不每扫描按累计重新排名切泵。未要求均衡时不凭空添加定时强制轮换。
- 多液位：写全每级升、降条件和等号，不能只写加泵。分配时最短累计优先启、减量最长优先停；故障、
  未选 AUTO、能力不匹配者不入池。手动/就地运行及未知停机仍按冻结容量占用，不被自动启停。
- 配泵阀仅在原文有顺控要求时组合：`阀 AUTO 且健康 → 开到位 → 泵 AUTO 且健康 → 启泵
  → 泵停稳 → 关阀到位`。单边 AUTO 不授予整支路控制权；手动默认泵阀分别控制。
- 互斥替补保留旧支路身份，停泵可信确认且所需隔离完成前不启备用；并联组按容量与原文判断，不
  无依据强加全关窗口。传感器/公共禁止失效不是一台泵坏了，不能借“故障自投”继续盲目启备用。
- 低位正常停机、当前泵故障、反馈粘连、阀未到位、手动占容量、候选不足分别测，不只测成功替补。

## F06 / F07：阀门操作与顺序排泥

- 开关 DO 在行程期间保持，目标 GOOD 到位即撤销；已到目标不通电。双限位同时有效为异常，均 false
  是可能的中间位置，不冒充关到位。同阀开关绝不并真；开转关、关转开均须连续全断至少 `2000 ms`。
  手动先独立STOP、等满后重新下令，早到命令丢弃；自动先全断等待，再按原条件反向。起点、拒令和
  行程监督按计时契约；一拍全断不能替代 2 秒，物理释放/停稳效果仍待实板证据。
- 手动各阀独立，不能继承自动单阀排泥限制。真实共享安全/容量互锁另行冻结；若手动申请会冲突自动
  会话，按明定移交处理，而非把自动算法混入手动或擅自关闭另一台手动阀。
- 顺控骨架：`准入/等轮次 → 选已 AUTO 的可用阀 → 开阀 → GOOD 开到位 → 排泥计时
  → 关阀 → GOOD 关到位 → 阀间许可 → 下一阀 → 整轮间隔`。排泥时间从开到位起，不从开阀 DO 起。
- 相邻“启动间隔”首选启动到启动最小间隔，下一阀还须前阀可信关闭；若原文“关到位后等 N 秒”，
  用 CLOSE_TO_NEXT_OPEN，不能二者相加。末阀之后是等间隔再静置还是两个许可取较晚，原文优先。
- 首轮定时场景首选等完整整轮间隔；液位触发场景等有效需求。需求只触发一轮还是持续许可应明确；
  推荐普通触发锁存本轮、公共保护持续监督，普通需求消失不擅自半途停止，保护分支单独收敛。
- 顺控快照在合法投入时捕获时间参数，本轮候选中取消 AUTO 立即剔除、新加入下一轮参加；行动中退出
  AUTO 推荐健康条件下关到位再移交，异常不能盲目关阀，控制器 STOP 始终撤 DO 而非假称物理关闭。
- 未开始且确认关闭的故障/不可用阀可跳过，不耗本阀排泥时长；已开始故障、关位未知、他阀不再确认
  关闭时停轮报警，不开下一阀。每阀分别开超时/关超时/硬接故障/总故障/独立复位，仅双到位不计运行累计。
- 独立电机周期逐台时长规则不机械套到单序列阀组。排泥时长/阀间隔/行程时限可按明文全组共用，
  但各阀计时起点、故障、AUTO 和 RST 仍独立；只有“一段开位停留”不生成无用途的运行/停止参数对。
- 必测两轮、非连续候选编号、途中取消/加入、提前/迟到限位、跨轮等待、跳过阀、模式移交及复位快照。

## F08 / F09：联动与清料延停

- 同步启动与下游先确认后启动上游是两种模式；原文同步就保留，不能借标准顺控擅自增加串行等待。
- 液位差优先与定时辅助要定义交接：高差接管后重算周期，还是两需求 OR；推荐不允许定时到期打断
  正在成立的高差需求，低差后是否仍跑定时按原文/一次建议决定。无时钟输入不实现“夜间”条件。
- 清料延停首选从全部实际相关上游 GOOD 停止起算；重来料取消延停、重新建立正常联动。已有原文若
  明定从请求撤销起算，保留并指出真实停机拖延的影响。停止反馈粘连须有限故障结果，不无限延停。
- 清料延停只属自动；手动 STP 立即按本机监督停机，不能自动延停或触发他机联停。下游故障作用范围
  限已确认的自动上游，真硬保护则依其明定范围；本机复位不改共享延停来源、计时或请求；本机恢复按恢复白名单处理。
- 外部状态是每路当前值，不是启动命令。首包、同值刷新、独立年龄、错误写入、断流和恢复都明确；
  无指定周期时非安全级默认 30 秒窗口，已明确 60 秒等值优先，不从其他案例继承。断流只影响依赖
  它的自动业务，不擅自停手动；恢复不能重放旧命令。物理安全信号不以此代替。
- 主备风机替补遵守旧机停稳；主备与共享下游 AUTO 缺席分别报受阻，不强启未授权设备。风机先停、
  分离器清料后停仅在该工艺要求下使用，不能推广到所有设备。

## F10 / F11：异构 PID 与采集边界

F10 另读 [W09](water-process-boundaries/09_mixed_speed_group.md) 与
[PID 整定契约](pid-online-tuning-contract.md)：固定变频主调与工频辅调不可等价替补；明确本机 PID
还是变频器内置 PID，只在本机实际执行闭环时开放真实参与计算的 KP/KI。AO 按范围、安全值与所有权
独立审查；变频主泵不可用时按明确降级，不臆造另一台有变频能力。

F11 不因运行反馈存在就造“启动/停止/运行丢失故障”，因为本机并无动作目标；但真实 RUN 仍必须逐台
累计且有本机清零。仪表独立换算工程值、质量/范围报警，备用点不占北向。纯采集不能因为设备名称是
泵或吸砂机就自动升级为控制项目。

## 推荐到交付

首轮给出“识别的设备/点位、命中模式、采用的已定共性、补全后的正常/异常/恢复行为、少量新增业务
建议、调试占位与禁用范围”。只有会改变工艺的新增选择才请用户集中确认，不能再问默认站号、串口、
标准板逻辑极性、逐台手动/AUTO/RST 等已定规则。用户授权按标准时采用明确标注的首选软件结构。

需求、YAML、C、测试和点表必须同一语义：每条可写点实际被代码消费，每条报警有真实置位/清除路径，
所有引用输入/输出/参数/状态/FB/runtime 都完整配置。接口最小化不是删除必要 AUTO、RST、总故障、
工程值、累计或清零；内部候选、计时起点、快照、pending 不发布。命令消费、参数读回、地址冲突与
数据类型通过真实管理器测试；主机通过后交付 HIL 计划，不声称软件测试已证明现场稳定。
