# KZ3 标准控制模式库

本文档用于让 OpenCode 智能体在生成前选对控制结构。模式提供需求、资源和测试骨架，不提供现场硬件事实。

表单＋简短场景先用自包含的 [标准场景匹配](field-control-patterns.md) 选择控制组合；计时、清料和复位
统一按 [计时契约](control-timing-contract.md)。无需历史项目即可完善需求；目标工程存在时，最多读一个
命中项目核对 API/实现差异，不将旧复位副作用、宽限数值或未验证接线复制为通用规则。

## 选择方法

1. 先识别已有目标和有效约束；没有完整方案时按 [工艺设计与方案选择](engineer-intake.md#工艺设计与方案选择)
   主动提出控制方案，再用 [工程建议与经典场景目录](plc-engineering-recommendations.md) 补齐边界。
   判断输出 owner：单设备锁存、多方向互锁、顺序步骤、数量调度、连续调节或仅北向手动。
2. 再判断主导过程：命令事件、数字量联锁、模拟量滞回、计时、计数、反馈确认或 PID。
3. 选一个主模式；可再组合“反馈超时”、“故障锁存”、“北向命令/参数”等辅助模式。
4. 组合后仍保证每个物理输出只有一个最终 owner，优先级在需求中冻结。

## 通用安全骨架

所有模式生成前都必须冻结：

- 输出的物理 bind、安全值、允许条件和真实反馈来源；
- 急停/硬保护 > 故障 > 停止 > 模式/许可 > 启动 > 正常调节的实际项目优先级；
- 每个参与自动控制的输入在 `INIT/STALE/OFFLINE/BAD` 时的结果；
- 通信恢复、故障解除、控制器 Reset 和重新上电后是否允许自动恢复输出；
- `Logic_Init`、`Logic_Stop`、`Logic_Scan=false` 和未写输出的安全结果。
- 每台设备各有 one-shot 故障复位：只清本机需求列明的软件故障点位/锁存，不清他机；客观故障必须在
  同扫描保持或重新置位。复位按恢复白名单恢复本机可用；健康运行不额外断开或建立输出，不恢复旧启动，不改模式、参数或 runtime。没有可复位软件故障点位时验证本机命令幂等；系统级故障另定复位范围。

新代码不使用可写 `static` 业务状态。跨扫描保持进入 `context->state`，计时/边沿/计数/锁存使用已声明功能块实例。

### 手动与自动隔离

需求出现“手动”且同一控制器管理多台设备时，默认建议每台设备具有独立启动/停止命令和独立手动请求；
用户只需一次确认“手动逐台独立，是否按此执行”。除非 PLC 明确要求手动联动、共享执行器互斥或经确认
的物理安全联锁，操作某台设备不得启动、停止、重选或清除其他设备请求。

手动和自动是两个隔离的请求域：`manual_request[i]` 只由第 i 台手动命令更新；`auto_request[i]` 只由自动
需求、顺控、轮换或 PID 更新。每台受控设备独立选择自动/手动，由 `auto_selected[i]` 选中本设备请求域；
组级自动使能若存在，仅是附加总许可，不能代替逐台自动选择。再统一通过本设备的远程许可、客观故障、
硬保护和已冻结的共用安全联锁产生最终输出。未选中的模式不得写最终输出，也不得借用、清除或重算
当前模式请求。自动阶段、候选、需求台数、轮换选择和联动停机不能进入手动分支。

自动候选池仅含已选择自动、许可和测量质量满足要求、未故障且具备对应能力的设备。未选择自动的设备
即使正在手动运行，也只计入真实运行数量、共享容量和安全约束，不得被自动选为启动、停止、替补或
轮换目标。候选不足不能借用手动设备凑数，应按冻结策略告警、限制需求或安全收敛。联动依赖的下游
设备未选择自动时，不得自动操作该设备；上游如何禁止/降级和诊断须在需求中明确。
缺少明文策略时，先建议阻止依赖该下游的上游自动启动并报告“联动受阻”；即便下游正由手动运行，
也不擅自视为已授权的自动联动条件。PLC 有明确允许条件时再按原方案冻结。

模式切换可以按冻结策略取消未选模式的待确认计时和要求重新使能，但不能把自动停机/联动结果复制到
手动请求，也不能用切换顺带操作无关设备。手动仍服从客观安全保护；工艺联动、顺控、均衡和加减泵
不是通用安全保护，默认只属于自动。确需手动联动时，必须明文列出触发设备、受影响设备、动作和恢复，
作为 PLC 需求特殊要求确认，不能由案例或自动逻辑继承。
逐台退出/进入自动时，目标设备原自动请求、计时和重新使能条件按冻结移交策略处理；不得把旧自动请求
直接带入新模式或改变其他设备选择。故障复位也不得改变逐台自动选择。
策略缺失时首选建议：切回手动不复用旧手动启动请求，重新进入自动须重新使能并重算有效需求；
未获新使能时保持安全输出，不能用保留模式或参数补齐冒充启动授权。独立周期可将新 AUTO 投入作为
本机首周期使能，默认 FIRST_RUN，已运行者不做额外启停处理、直接从切入开始计时，见计时契约；
其他方向或特殊工艺的无扰移交单独冻结其条件和测试。

## `P01_LATCHED_ACTUATOR`

- 必需角色：启动请求、停止请求、运行输出；无真实运行反馈时必须明确记录。
- 常用状态：`requested_on`、`applied_on`、`fault_latched`、`blocked_reason`。
- 常用资源：启动命令边沿、反馈超时 Timer；不用输出本身作为自锁状态。
- 首选建议：同扫描启停冲突由停止胜出；反馈超时锁存并人工复位；复位本身不重启。若连续工艺需要自动
  恢复，则把“按当前条件恢复”作为替代方案和新增风险交给用户确认。
- 必测：命令 one-shot、停止优先、反馈超时边界、坏质量、STOP/Reset、恢复不误启。
- 标准骨架：语义匹配时优先 `T01_SINGLE_PUMP_SUPERVISOR`；远程许可不得直接接入会锁存故障的
  safety_permit，先按设备归属契约核对许可移交能力，必要时 CUSTOM_REVIEW_REQUIRED；旧
  `01_电机启停自锁/logic_example.c` 含历史结构，只作反例/迁移参考。

## `P02_REVERSING_INTERLOCK`

- 必需角色：正向/反向请求与两个独立输出；限位、反馈和硬件互锁现状需明确。
- 常用状态：`requested_direction`、`applied_direction`、`fault_latched`、`blocked_reason`。
- 常用资源：换向死区 Timer、限位/命令 Edge。
- 不变量：两输出永不同时为 true；换向必须经过全关死区；双限位同时有效禁止运动。
- 用于开/关双向阀、闸门时，按 [双向反转保护](control-timing-contract.md#阀门双向反转保护) 直接采用
  至少 `2000 ms` 连续全断；手动独立STOP后新发反向命令，早到不排队；自动先停、等待、复核原条件。
- 必测：同扫描双向命令、死区前/到时/后一拍、限位坏质量、反馈反向、STOP 双输出安全。
- 标准骨架：`T02_MUTUAL_INTERLOCK`；正反限位、热继和急停先归并为带质量的 permit，再进入模板。
  普通远程许可在 owner 层独立门控，不并入会产生故障锁存的 global_permit/方向 permit。
  核对模板反馈语义及目标保持行为：到位限位不等于运行/释放反馈，保留反向目标的模板不能直接用于
  手动拒令不排队；未覆盖部分按 CUSTOM_REVIEW_REQUIRED 适配和验证，不改认证模板来迁就项目。

## `P03_SEQUENCE_INTERLOCK`

- 必需角色：每段运行输出、运行反馈、启动许可；堵料/护罩/急停等保护单独建模。
- 常用状态：顺序阶段、启动失败段、报警锁存。
- 常用资源：每段独占反馈超时 Timer、停机清料 Timer。
- 不变量：下游反馈未确认前不启动上游；停机顺序与启动顺序相反；堵料锁存未复位时不重启。
- 必测：逐步反馈、任一段超时、中途停止、清料时间、堵料与复位、扫描时间跳变。

## `P04_DUTY_STANDBY_ROTATION`

- 必需角色：泵组需求、每泵可用/故障/运行反馈/启动输出。
- 常用状态：`group_requested`、`lead_index`、`active_index`、`switch_phase`、`fault_latched`；切换时必须保留旧泵身份，直到旧反馈确认断开。
- 常用资源：每泵启动确认 Timer、最小启停 Timer、换泵间隔 Timer；运行累计需要声明式 `runtime_counters`。
- 首选建议：有可靠反馈时按确认运行时间或完整工艺周期轮换；先按原文/电气/管路判断互斥或并联。
  无可用设备只报警不强启；不得把所有主备组视为互斥。
- 互斥切换不变量：正常轮换、故障、坏质量和反馈超时等替补路径复用 `STOPPING → 旧反馈 GOOD+false → GAP → STARTING`。
  不得清空旧设备身份绕过窗口；停机反馈持续 true 或质量未知时禁止互斥替补。
- 并联替补按冻结容量与控制权判断；启动中、停机未确认和未知运行继续占用容量，不强制所有健康设备停机。
  异构设备池另读 [W09 组合卡](water-process-boundaries/09_mixed_speed_group.md)，不能等价互换。
- 必测：两个完整轮换周期、已提供的立即换泵命令、主泵反馈超时、备泵替补、两泵不可用、最小启停边界；
  都要覆盖“运行泵故障但旧反馈持续 true”。互斥分支再断言“反馈超时后 GAP 未完成”禁止启动；并联分支
  则断言冻结的容量、重叠许可与时限，不为满足测试凭空增加 GAP 或换泵命令。
- 轮换依据若使用累计时间，只读 `RUNTIME_SECONDS` 的上一拍投影；累计器由 T05 和框架拥有，不得用项目
  state/Counter 复制。必须确认掉电误差是否允许影响主备选择，以及存储 fault 时采用哪台泵。
- 若轮换由每台设备的运行/停止时长驱动，逐台开放独立可调参数和计时实例；累计 `runtime_counters`
  只用于磨损均衡，不代替周期时长。改单台时长不得改其他设备阶段。

## `P05_STAGED_DEMAND`

- 必需角色：带工程单位/质量的连续过程值，每设备可用、反馈和输出。
- 常用参数：每级 `start/stop` 阈值、`threshold_confirm_ms`（默认 `30000 ms`）和最小启停时间；必须校验
  单调顺序和滞回关系。
- 常用状态：`demand_stage`、每个转换独立的待确认级/起始时间、轮换指针、每设备应用状态。
- 不变量：普通工艺启停/加减级条件必须连续成立 30 秒；确认期间保持原需求，条件退出、质量非 GOOD、
  模式改变或相关参数变化（含合法变更）/非法时取消并从 0 重计；急停、故障和保护停机不得延迟。过程值坏质量时不新增危险输出；
  滞回区保持上一需求级；
  已投入高一级后按独立的下降阈值减级；故障设备不参与调度。
- 与运行时间均衡组合时，只在需求级变化或已选设备失去资格时重选；减设备按冻结规则（如停运行时间
  最长者）；旧设备未确认 `GOOD+false` 时继续占容量，互斥组禁止替代，并联组按冻结容量判断。
- 必测：每级阈值前/到时/后一个最小可表示变化、`29999/30000/30001 ms`、确认取消重计、下降滞回、同级不重选、质量失效、
  参数非法、故障替补、旧设备未停稳的负向窗口和无可用设备。

## `P06_STEP_SEQUENCE`

- 必需角色：起停/复位、步骤转移条件、每步输出矩阵。
- 常用状态：当前步、进入时间、转移故障和禁止原因。
- 常用资源：步骤 Timer；每个有状态块实例只服务一个转移。
- 不变量：仅按冻结转移表变化；输出矩阵每扫描一次生成；故障/急停按冻结规则进入安全步。
  本机故障复位按恢复白名单恢复设备可用，不直接恢复共享工艺步骤、进入时间或 PID。需要过程重新开始时，
  使用独立且已批准的命令和转移，不与故障复位混用。
- 必测：全转移表、非法状态收敛、时间边界与 `uint32_t` 回绕、任意步 STOP、平台初始化，
  以及各步骤软件故障复位只改变本机恢复白名单内状态；测试复位当拍与后续自动扫描，防止间接误启。

## `P07_COUNT_AND_SORT`

- 必需角色：产品检测、执行机输出、到位反馈；卡料证据若不存在则不得伪造。
- 常用参数：`batch_target`、执行机超时、输入去抖时间。
- 常用资源：Debounce、Rising Edge、Counter、执行超时 Timer、故障 Latch。
- 首选建议：急停/停机时输出立即安全，批次计数默认保留到人工清零；掉电后默认不承诺保持。若业务要求
  掉电续批，列为 `CUSTOM_REVIEW_REQUIRED` 并让用户确认数据一致性要求。
- 必测：抖动、持续高电平、到数只触发一次、到位超时、目标 0/上限、复位与 STOP。

## `P08_MANUAL_MULTI_DEVICE`

- 必需角色：每设备 `local_allow/fault/feedback/start_output`，及全局远程允许；缺少真实反馈时正式记录。
- 北向命令：每设备 `request_on/request_off` 为 one-shot command；需要保持的请求进入 state。
- 常用状态：每设备独立 `manual_requested_on/applied_on/blocked_reason/fault_latched`；自动请求另用独立字段。
- 首选建议：北向断线时禁止输出且不自动恢复，停止与启动同到时停止优先；是否保留目标供画面显示、以及
  通信恢复后是否需要重新启动，给出“不误启”的首选结果后由用户确认。
- 不变量：手动命令只改变目标设备；自动需求、自动候选/轮换/阶段和自动联动不得改变手动请求或在手动
  模式操作其他设备。只有明文手动联动或共用安全联锁可以跨设备影响，并须单独断言原因。
- 必测：每台设备分别执行启动/停止时，其他设备的请求、输出和反馈监督状态保持；自动需求同时变化、
  自动计时到期、自动候选重选时手动输出不受影响；手动切自动、自动切手动、同拍模式+命令；许可/故障/
  反馈质量和超时锁存。使用 `MANUAL_INDEPENDENCE` 与 `MODE_ISOLATION` 追溯这些反例。

## `P09_PID_LOOP`

- 必需角色：带单位/量程/质量的测量、已声明给定、已配置 AO/速率输出、enable/manual/tracking/hold 语义。
- 必需参数：方向、KP/KI/KD、采样周期、输出限幅、积分/切换策略；`Kd > 0` 时需非零微分滤波时间。
- 上位机接口：每回路 KP、KI 分别建为有范围的 `float` parameter 并北向 `read_write`；调用
  `PID_STEP` 时启用 runtime gains。详细命名、持久化和改单重投规则见
  [PID 上位机整定契约](pid-online-tuning-contract.md)。当前 runtime API 不支持在线 KD，不得伪造可写 KD。
- 常用资源：每回路独占 PID 实例与输出 owner；U16 AO 必须使用已冻结的工程量到原始码转换。
- 不变量：测量坏质量或 API 失败时进入冻结的安全/手动结果；不自行发明整定值；多 PID 不共用隐式全局手自动状态。
- 必测：手自动无扰切换、限幅、方向、坏质量、hold/tracking、时间回绕、输出原始码边界；稳定性仍待 HIL/现场整定。
- 标准骨架：`T03_PID_LOOP_GUARD` 只固定 PID 外围门禁，不提供或猜测整定值；原子 PID 行为仍由 `PID_STEP/PID_RESET` 平台测试保证。

## 北向横切模板

| 业务语义 | YAML 类别 | 常用权限 | 代码规则 |
| --- | --- | --- | --- |
| 轮换时间、阈值、给定、模式保持值 | parameter | R/W | 读 `context->param.*`，验证边界；缺省易失，`persistent: true` 才由参数 store 保持 |
| 启动、停止、立即切换、复位、清零 | command | R/W | 每扫描 one-shot；需保持的结果进入 state |
| 当前步骤、活动设备、禁止原因、故障 | state | R | 由 `logic.c` 唯一拥有和更新 |
| 业务输入和输出请求/回读 | point | R | 上位机不直接成为物理输出 owner |
| 声明式运行累计 | runtime | R，清零命令 R/W | 使用 `T05_RUNTIME_COUNTER_USAGE`；只有 `runtime_counters` 具有专用保持机制 |

新项目按固定分类与声明顺序分配无冲突地址，交付时输出完整地址表。已有项目严禁因为“整理”重排旧地址。
