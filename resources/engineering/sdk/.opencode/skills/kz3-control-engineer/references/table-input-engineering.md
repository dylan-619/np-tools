# 点表与简短工艺说明转需求

## 输入归一化：理解目标，设计方案，核对边界

不默认用户已经制定完整工艺方案。按 [工艺设计与方案选择](engineer-intake.md#工艺设计与方案选择)
由智能体基于点表和简短需求主动设计，再做 [工艺边界匹配](plc-boundary-matching.md)。
“同步启动”“手动独立”等明确约束应保留；若与点位或工艺冲突，说明影响并提出修订供选择，不由案例静默覆盖。

支持用户粘贴 Markdown/HTML 表和表格文本；`<br>` 是段落分隔，不能把同一单元格中的多条要求合并成一条。
对合并单元格或错列行，根据已出现的柜体、模块和通道标签恢复上下文，保留原行号/原文，输出归一化点表。
只有柜体、模块等分组字段可在明确分组内向下继承；不得仅凭表格空白填充量程、地址、有效电平或安全值。
已匹配的标准板/Profile 中明确的软件 I/O 语义可以引用其定义，不算从表格空白猜测。

归一化表最少列：来源行、柜体编号、模块标识/型号、通道、原始描述、业务角色、使用/备用、映射证据。
主键为 `(柜体, 模块, 通道)`；A11.AI1 与 A12.AI1 是不同点。本点表体系采用用户明确的归属约定：

| 标识 | 归属 | 需求/配置解释 |
| --- | --- | --- |
| A11 | 控制器本机 | 本机通道，不生成从站 11 |
| A12 | 从站 1 | 按从站号 1 整理，不解释为站号 12 |
| A13 | 从站 2 | 按从站号 2 整理，不解释为站号 13 |

A11/A12/A13 不代表硬件型号；型号按点表型号栏、设备资料或实际硬件确定，同一标识不能固定绑定某种
NP-IIOTEM 型号或 Profile。该归属约定用于本体系输入，不要求用户逐次确认；其他编号或其他编号体系
按明确资料解析，不自行外推。型号缺失时保留已知归属，只将型号/Profile 等受影响项列为待补。
NP-IIOTEM8AI 等型号用于匹配实际 Profile，但编号与型号均不能证明串口、寄存器、极性或设备实装地址。
配置按上述约定给出；现场实装地址在投用时核对。若显式配置/设备资料与约定冲突，只列出冲突供裁决，
不静默覆盖已发布配置，也不把已明确的从站归属重新当作开放问题。

用户未明确从站串口时，默认接 `RS485_1`，配置键为 `rs485_1`，直接写入需求及配置，不逐次询问。
明确指定其他串口时采用指定值；已有配置/接线证据与默认不同则保留并说明差异，默认不能覆盖明确事实。
该默认只确定端口，不推导波特率、校验位、停止位或寄存器；A11 本机通道不因此变成 RS485 从站。
跨模块归属有歧义时展示候选映射与原行；不把置信度评分当作物理证据。

A11 使用未改动的 KZ3 F427 标准板固件时，读取板型定义和当前映射后直接沿用：板载 DI 低电平有效，
逻辑块读到的 `GOOD + true` 已表示点位描述的状态成立；板载 DO 高有效，`true` 为继电器式开关输出
请求、`false` 为软件安全目标。按点表描述确定每路“远程、运行、故障、到位”的业务含义，不逐路再问
“DI 什么时候有效”，也不在项目逻辑中再次反相。现场触点常开/常闭、断线与最终负载结果放入 HIL/
现场验收；资料与基线冲突、变更固件/板型或安全逻辑依赖未知接线时才提出具体差异。A12/A13 等
从站使用自己的 RTU Profile，不能继承上述板载极性。

- “远程反馈”识别为远程控制许可 DI，与软件手/自动模式、上位机通信在线状态分开；有效 false 只禁止
  控制，不是设备故障或总故障来源，不生成远程故障点/复位要求，见 [设备归属契约](device-ownership-contract.md)；
- “手动控制/远程手动”且包含多台设备时，默认形成整组建议：每台设备独立启停，手动和自动请求完全
  分域；一台设备的手动操作不改变其他设备。只让用户一次确认是否采用，不逐设备追问。原文明确手动
  联动或存在已确认共用安全联锁时按特殊要求记录，不能从自动联动静默继承；
- 同一控制器有多台受控设备且涉及自动时，按每台设备建立独立自动选择，不把一项“自动控制”解释为
  全柜唯一模式。自动联动/轮换/加减机只在已选自动且可用的设备中选取；手动运行占用真实容量但不被
  自动启停。形成一张包含候选不足、下游未选自动、逐台模式切换的整组建议卡；`PER_DEVICE_AUTO`
  场景随需求记录，不能只在代码中临时补选项；
- “运行一段时间、停止一段时间/按时轮换”涉及多台设备时，默认每台各有独立可写运行与停止时长，
  同值初值不等于共用参数；不能仅从一句“运行时间开放”生成一对 `SYS_RUN_M/SYS_STP_M`。
  逐台记录单位、初值来源、有效范围、计时起点、在线修改与故障/模式中断，明文共享时长记录例外；
- 多台设备的软件故障复位默认按设备归属生成 `*_RST`，一台命令只清本机软件故障；点表没有复位 DI
  不妨碍北向 one-shot，但不能由“故障反馈”推断硬件故障可软件清除。已有全局复位点位按接口兼容
  记录差异，不能直接扇出清全组；
- “启停控制”先按点位拓扑形成默认建议：单个启停 DO 建议保持型；启动/停止两个 DO 建议脉冲型并以
  `500 ms` 为可调初值；阀门开/关两个 DO 且有开/关到位时，建议行程期间保持、到位撤销。以一张是/否
  决策卡让用户采纳，不重复问开放题；接线、设备手册或既有兼容契约冲突时，以证据为准并标记阻塞；
- “液位差计”优先作为独立仪表，不能擅自改为两路绝对液位相减；
- “备用”计入资源盘点但不分配控制、参数或北向字段，不编造用途；
- “例如 20 cm / 10 cm”是候选设定；“15–30 min”是候选区间，不是一个已确认默认值；
- 明确 `4–20 mA` 的点可预置 `4.0f/20.0f` 电流端点；未知工程量上下限和液位阈值以 `0.0f` 的
  `float` 调试占位并标记必填。占位未解除或范围相等时必须禁止相关自动控制，不能当成现场参数；
- 普通工艺值触发启停泵、加减泵或阀门切换时，默认补充连续 `30000 ms` 到达确认：条件退出或质量
  失效即取消并从 0 重计，到时前保持原需求。保护/故障动作不延时；用户只需在建议卡中采纳或改写时间；
- “开放设定”表示建议提供 parameter；其上下限、单位、何时生效和持久化仍由工程师提出方案；
- “夜间/低流量”未给出时钟/流量依据时不增造输入，建议先采用不分时的定时辅助，标注待采纳；
- 只用于监控的气体/绝对液位不得自动升级为安全联锁，也不能声称已具备人身保护。
- “数据由其他采集器/业务机/上级传入”先识别为外部实时输入候选，读取
  [外部实时输入契约](external-input-contract.md)；不占用物理 DI/AI，不自动当作 parameter，也不因软件
  可写就冒充现场反馈。点表补充数据生产者、写入 owner、协议字段、类型/单位/范围和更新周期证据。

## 固定产出与证据层级

第一次有效输入后就交付需求草案。未决项不妨碍完成归一化点表、推荐控制流程、状态转移、参数建议、
北向候选白名单和验收矩阵；`DRAFT` 可交付，只有生成可运行代码才要求 `FROZEN`。
已有目标项目时存入其 README；独立使用技能时写用户指定文档或当前工作区 `works/`，不要求固件工程。
技能评审样例也可存入 `works/`，不自动登记为新工艺项目。

按项目需求模板输出，补充以下内容：

1. 当前输入版本、原文出处、归一化点表、已用/备用点数与资源预算；
2. 工艺结果和明确非目标；主场景与组合关系；
3. “原文事实 / 当前项目已确认事实 / 工程建议 / 缺失证据”四种来源，并附原要求保留表和边界差异表；
4. 少量稳定编号的决策卡：推荐选项 A、可用替代 B、影响、采纳状态；用户可回复“采用建议，D03 改 B”；
5. 唯一输出 owner、正常/异常状态转移表、故障影响范围、再启动条件；
6. 参数表：单位、默认候选、范围依据、成组关系、失效结果、生效时机、持久化；
7. 关键 HMI 字段、质量/有效性、报警与复位、兼容规则；
8. Given/When/Then：对应规则/决策 ID、输入序列、扫描时间、必须出现和禁止出现的输出；
9. 现场事实待补清单、采纳记录和机器可读契约。

同一项目已有确认可以复用，但必须引用当前有效章节和版本。历史实现、旧冻结块与当前 DRAFT 冲突时，
按当前需求优先，记录差异；不能把历史数值转写成“本次用户给定”。确认问题只聚焦差异，不重复问已答项。
“按推荐做”仅确认已经展示的决策卡范围；沉默不是采纳，不能伪造确认项或填入安全证据。
`CONFIRM_RECOMMENDATION` 未采纳仍阻止冻结；`EVIDENCE_BLOCKER` 缺失也阻止冻结，但两者均不阻止草案交付。

## 组合控制：液位差优先 + 定时辅助 + 下游延停

推荐拆成四层：每机液位差滞回需求、每机定时辅助需求、组级联动/owner 仲裁、每机反馈监督与最终输出。
两台设备需求独立；压榨机是共享下游，不能把三台设备整体套入互斥主备模板。

建议给用户一次展示三组卡（可继续引用已有确认）：

| 卡 | 推荐 A | 替代 B 与影响 |
| --- | --- | --- |
| D01 自动需求合成（仅原文明确组合时；互斥要求改用枚举选择） | 液位差滞回需求 OR 定时需求；定时阶段独立推进；高差期间定时到停点不能停格栅；差值回低限后若定时仍请求则继续运行 | 高差接管时复位定时，解除后重启完整停机周期；需另定低限后的行为，与 OR 方案测试不同 |
| D02 启动/清料 | 保留原文“同步启动”作为请求层候选；同拍请求下游，持续监督反馈；最后一台格栅真实反馈 GOOD+停止后才开始清料延时 | 下游反馈先确认再启格栅更保守，但改变“同步启动”，需明确采纳；无反馈时无法声称物理清料完成 |
| D03 故障和再启动 | 自动时下游不可用/停止/超时则禁止或停止上游，取消旧延停；复位清故障并恢复本机可用，默认重新使能才运行；手动默认逐设备独立且不继承自动联动 | 只有 PLC 明确要求手动联动或共用安全联锁时，才列跨设备动作及堵料/检修影响供确认 |

这些是供确认的设计选项，不是本表已确认行为。手/自动模式粒度和就地移交策略另记录：失去远程许可可
撤销远程输出，但不能声称软件已让就地运行的设备停机。允许上游物理就地运行时，下游清料还要明确其
是否有远程 owner，绝不越权接管。

避免联动循环依赖：先算上游工艺请求，再算下游目标，再用下游许可/反馈门控上游最终输出；不得让
“下游启动依赖上游最终输出”同时与“上游输出依赖下游运行反馈”互相等待。

延停判断使用真实反馈而非只看请求：上游请求已关但反馈仍运行或坏质量时不宣告“全部停止”，进入有界
的停止监督/故障策略。不能以“安全”为由无限运行压榨机；反馈超时后如何处置下游必须写入故障矩阵。
延停中重新来料可取消延停；模式切换、急停、下游故障要明确是否清除延停来源，禁止旧请求复活。
本机故障复位不改共享延停来源或其计时基准；平台复位/过程重新开始与该命令分开定义。

## 运行时职责：不能继承工具默认行为

普通 PLC 工具提供语言、扫描、诊断和配置能力，具体联锁、停机顺序、重启和质量策略仍是应用设计。
KZ3 已提供输入快照、one-shot 消费、安全目标初始化、提交校验、功能块和运行累计；项目仍负责请求
仲裁、每机监督、坏质量策略、组级联动和 `Logic_Stop` 中业务状态清理。
控制器 `controller_reset` 由平台处理；项目逐设备故障复位通常仅在运行扫描被消费，不能代替平台
FAULT_SAFE 恢复。每个场景必须使用当前 API 与真实生命周期测试，不能把厂商 FB 名称当作完全相同语义。

同拍参数快照不表示多笔 HMI 写入事务原子化。高低限/量程成组修改可能经过非法中间组合，需选定：拒绝
单笔非法关系、保持最后合法组、或安全禁止相关自动控制并提示配置错误。只有当前平台实际支持时才实现
暂存+提交接口，不能虚构事务 API。保护停机不受最小运行时间或普通清料延时阻挡。

## 必须补齐的边界域

每域记录 `specified / pending / not_applicable`、依据和验收场景；不适用要说明理由。

| 域 | 需要明确 | 对应主机负向场景 |
| --- | --- | --- |
| io_semantics | 模块归属、按点位拓扑建议持续/脉冲、许可/反馈/输出区分 | POINT_MAPPING |
| ownership | 手自动、就地远程、移交和 STOP 优先；多设备手动独立、请求域隔离 | MODE_TRANSFER / MANUAL_INDEPENDENCE / MODE_ISOLATION |
| startup_recovery | 首拍、重上电、故障恢复、复位+启动同拍 | RECOVERY_NO_START |
| process_arbitration | 高低限与定时交叉、共享下游、多请求 | DEMAND_PRIORITY |
| feedback_interlocks | 启停超时、运行丢失、粘连/坏反馈、不允许动作窗口 | FEEDBACK_FAILURE |
| measurement_quality | INIT/STALE/OFFLINE/BAD、NaN/Inf、断线、量程和恢复 | BAD_QUALITY |
| timing_parameters | 等号、扫描抖动、回绕、溢出、参数在线修改 | PARAMETER_UPDATE |
| fault_reset | 客观故障、锁存、报警确认、清除和再启动分别定义 | RESET_FAULTS |
| communication | 北向/南向分别定义，掉线信号来源与旧命令恢复 | COMMUNICATION_LOSS |
| retention | state 易失、parameter 可选保持、runtime 框架累计 | RUNTIME_PERSISTENCE |
| hmi_contract | 操作权限、关键点、质量有效性、名称地址及单位兼容 | HMI_CONTRACT |

通信中断行为只有存在可用心跳/租约/连接诊断来源时才能生成；HMI 不轮询不等于设备离线。若平台没有
可供项目消费的诊断点，明确不能实现该断线停机要求，提出“补通信许可”或“确认本地自治”的选择。
external input 自带按本地接收时间计算的质量与中断计数，可作为该字段的数据时效证据，但不能推导整个
上级设备在线，也不能证明外部物理设备状态；涉及 external input 时另加 `EXTERNAL_INPUT_LIFECYCLE`。
